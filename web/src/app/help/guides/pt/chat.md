# Chat

O Chat é o espaço de trabalho da plataforma: onde faz perguntas sobre os seus dados, os analisa com o assistente, cria relatórios e revê os resultados. Este guia explica o ecrã e os seus controlos, como obter respostas fiáveis, a que pode aceder o assistente e o que lhe perguntará antes de agir, e como levar o trabalho que quer repetir de uma conversa para a biblioteca de prompts e para um agendamento.

## 1. O que é o Chat

### Chat de terminal

No servidor, `fleet chat` abre o chat de terminal. Inicia sessão com a sua própria chave de API, criada por um administrador com `fleet sched apikey create <name> --type user --user you@example.com`; guarde-a em `~/.config/fleet/api-key`. As novas conversas usam por predefinição o modelo do espaço de trabalho; `--model` ou `/model` seleciona outro modelo. `--message "..."` e `--no-tui` permitem usar scripts e entradas por canalização. No modo de execução única, stdout é armazenado até o turno terminar para conter a resposta final em vez de rascunhos substituídos; os avisos de progresso e aprovação vão para stderr. O modo de execução única escreve o ID da conversa em stderr; `--conversation <id>` retoma o contexto do modelo e carrega as aprovações pendentes em modo interativo. Aceitar uma sugestão de modelo só altera essa conversa. `/new` regressa ao modelo predefinido do espaço de trabalho, salvo se tiver escolhido explicitamente outro com `--model` ou `/model`; ao retomar outra conversa, mantém-se o modelo guardado, salvo se essa escolha explícita estiver ativa. Após aceitar uma sugestão, as mensagens usam o modelo guardado dessa conversa, incluindo alterações posteriores feitas por outro cliente; `/model` define uma nova escolha explícita. As sugestões de modelo mostram o modelo de destino fixado quando o cartão foi criado. Deve descartar os cartões antigos sem um destino fixado antes de pedir outra sugestão. Uma nova conversa de terminal (incluindo `/new`) começa com os mesmos conectores opcionais de um novo chat Web: os que tem ativos por predefinição em Definições → Ligações. `--connector NAME` (pode ser repetido) substitui esse conjunto para a nova conversa, por exemplo `--connector email --connector lens`; um nome desconhecido ou indisponível é recusado antes de enviar qualquer coisa. `--connector` não altera uma conversa existente: use o seletor Ferramentas da Web (ou peça ao assistente no chat para ativar um conector MCP opcional do pacote para essa conversa).

As atualizações, os reinícios e as paragens habituais do servidor (`fleet update`, `fleet restart`, `fleet stop`) são recusados por predefinição se houver um turno de chat, uma ação aprovada ou uma tarefa agendada em curso. Com `--wait`, deixam de aceitar novo trabalho enquanto aguardam a conclusão do atual (`--wait-timeout` define o limite, de 90 minutos por predefinição; `--force` ignora a verificação). Se o servidor reiniciar durante uma ação aprovada, o resultado é apresentado como desconhecido; verifique o resultado externo antes de tentar outra ação.

O terminal mostra as ações preparadas e o número de pendentes. `/approvals` mostra os argumentos de execução completos e fixados, resumos de uma linha e prazos; `/approve` e `/deny` decidem sobre o cartão mais antigo ou aceitam um ID de aprovação completo. `/edit {"name":"...","prompt":"...","cron":"..."}` altera localmente o cartão de tarefa agendada mais antigo antes da aprovação. Os campos omitidos não mudam. `cron` só pode ser alterado num cartão recorrente; não pode ser adicionado a uma tarefa de execução única nem apagado, porque isso faria a tarefa executar-se de imediato. O servidor valida as alterações quando aprova. Após editar, o resumo de uma linha do cartão é novamente gerado a partir dos valores alterados. Assim, o nome, o prompt e o cron apresentados são os que serão submetidos, incluindo a indicação aproximada de execuções por mês, recalculada para o cron editado em vez de continuar a descrever o horário anterior. Um agendamento que se ativa mais de cerca de mil vezes por mês mostra um mínimo (`≥1000 runs/month`), porque a contagem para nesse ponto. Se o terminal não conseguir interpretar o cron editado, não apresenta qualquer estimativa. Cada ferramenta preparada mostra automaticamente os seus argumentos de execução completos e fixados como JSON com carateres escapados; o resumo de uma linha não é o registo a rever. Se o servidor não fornecer uma captura completa (ou os argumentos ultrapassarem o limite de revisão de 1 MiB), o terminal recusa a aprovação. Os carateres de controlo em revisões, resultados e erros são escapados para que não possam controlar o terminal. Quando stdout de um resultado de aprovação é redirecionado para uma canalização ou ficheiro, preserva o resultado original para automações; a saída direta para o terminal mantém os carateres escapados.

Adicione `session` a uma decisão para a aplicar a futuras chamadas dessa ferramenta na mesma conversa, ou `pattern arg=glob` para limitar a regra aos argumentos que correspondam. Os padrões usam os nomes originais dos argumentos de texto, como `name`, `cron` ou `to_email` (não a etiqueta `to` do resumo). Nas ferramentas de navegador integradas, um padrão `action=` também corresponde ao nome habitual da ação, e outro nome da mesma ação num padrão representa-a (em `playwright_browser`, `action=start_session` também abrange `live`). São permitidos espaços nos padrões glob, e uma recusa correspondente tem prioridade sobre as aprovações. `/approvals` mostra os argumentos de padrão disponíveis para as ações tratadas pelo servidor; é necessário que o servidor os forneça. As regras de ferramentas executáveis são repostas ao reiniciar o servidor. As regras dos cartões de tarefas agendadas e de outras ações tratadas pelo servidor duram esta sessão de terminal e continuam a resolver cada cartão através do endpoint de aprovação do servidor. `/resume <id>` muda de conversa e carrega os respetivos cartões; `/approvals reload` atualiza os cartões. Os cartões expirados são removidos; se um pedido de rede falhar, o cartão é mantido para tentar novamente. As chamadas de execução única usam `--conversation <id> --approve <approval-id>` ou `--deny`. Uma ação recusada ou falhada devolve um código de saída diferente de zero, sem indicar sucesso.

O Chat é a conversa com o assistente: faz perguntas, ele trabalha, lê o resultado e orienta-o. A maior parte do que é executado na sua instalação tomou forma aqui, numa conversa que alguém pôde observar e corrigir antes de a deixar executar-se sozinha.

O trabalho recorrente costuma seguir um ciclo. Uma conversa produz algo que vale a pena guardar. Essa conversa torna-se um prompt guardado na biblioteca de prompts. O prompt torna-se uma tarefa agendada. A tarefa executa-se por si só e envia o resultado por email a quem o deve ver. Este guia explica em detalhe os dois primeiros passos; o **Guia de tarefas em segundo plano** explica os restantes.

> conversa → prompt guardado → tarefa agendada → a sua caixa de entrada *(este guia cobre os dois primeiros)*

As duas interfaces dividem o trabalho de forma simples. O Chat funciona **com a sua participação**: participa na conversa, pergunta, lê e orienta o trabalho; é aí que o relatório ganha forma até chegar ao resultado correto. As tarefas em segundo plano funcionam **em autonomia**: quando essa conversa está correta, é executada de acordo com um horário e entrega os resultados; só tem de intervir quando algo precisa de si. As competências são as mesmas nos dois locais; só muda o seu papel.

Os cartões de início rápido de um novo chat podem recolher alguns dados antes de começar o trabalho. Os campos de texto preservam os espaços ao escrever; as caixas de texto maiores aceitam várias linhas. A pré-visualização do prompt preserva essas quebras de linha para verificar o que será enviado antes de premir o botão de execução do cartão.

### Painel de lançamento de patrulhas: a sua primeira patrulha em cinco passos

A forma mais rápida de pôr o assistente a patrulhar é **Patrulhas** (o ícone de brilhos) na barra lateral esquerda, entre **Chat** e **Tarefas em segundo plano**, em qualquer interface. Se a barra estiver recolhida, procure esse ícone; num telefone, abra a barra lateral. Até o abrir pela primeira vez, mostra um pequeno ponto intermitente. As patrulhas ficam no Chat: cada uma é um chat que se ativa de acordo com o seu horário. Por isso, **Patrulhas** é o seu índice e ponto de entrada: se ainda não tiver patrulhas, abre o **Painel de lançamento de patrulhas**; quando já tem alguma, lista-as (nome, chat, frequência e **Em pausa** se estiver pausada). Clique numa para abrir o chat; no fim aparece **Nova patrulha** para abrir o painel de lançamento. O painel de lançamento é um assistente passo a passo que o leva do início até uma patrulha em funcionamento. Começa com **Porquê usar patrulhas?**, uma ilustração de quatro níveis que vai do chat aos relatórios agendados, às patrulhas que analisam e decidem e, por fim, ao assistente a agir em seu nome. Também explica como ganhar confiança: comece com **Sugerir e perguntar** e ative **⚡ Aprovação automática** na barra de Patrulha quando confiar nas suas decisões. **Mostrar o plano** lista os cinco passos antes de começar:

1. **Ligue as suas ferramentas.** São apresentados todos os conectores que pode usar; os ativos por predefinição em novos chats aparecem selecionados, e pode selecionar ou desmarcar os restantes para esta patrulha. Um conector que ainda precisa de credenciais mostra **Configurar**, e **Ligar outra ferramenta** abre **Definições → Ligações**; ambos abrem num novo separador e a lista atualiza-se quando regressar.
2. **Defina as suas regras fundamentais.** Escolha **Quem está de vigia** (o perfil predefinido do espaço de trabalho, salvo se escolher outro, incluindo os seus próprios perfis) e guarde as suas **condições inegociáveis**: toque numa sugestão ou escreva a sua e prima **Guardar**. Cada um é guardado de imediato como uma memória fixada, para que o assistente o leia em todos os chats, incluindo as patrulhas; pode editá-lo ou eliminá-lo mais tarde em **Definições → Memórias**.
3. **Escolha o que monitorizar.** Escolha entre **Detetar negócios mal configurados**, **Alertar quando a despesa cair**, **Garantir a entrega de relatórios**, **Fazer a triagem da minha caixa de entrada**, **Sugerir otimizações**, **Preparar-me para o dia** e **Detetar anomalias nos meus dados**, e acrescente o que quiser pelas suas próprias palavras. Cada cartão mostra quais das ferramentas selecionadas servem para ele (**Usa…**) ou de que tipo de conector precisaria. Depois escolha a autonomia: **Apenas informar** (nunca altera nada), **Sugerir e perguntar** (prepara cartões de aprovação; a predefinição) ou **Agir por mim** (ativa **⚡ Aprovação automática** no chat e lista tudo o que fez). Uma nota sob a opção sugere começar com **Sugerir e perguntar** e ativar **⚡ Aprovação automática** mais tarde.
4. **Escolha uma frequência.** **Manhãs dos dias úteis** (8:00, de segunda a sexta-feira; predefinição), **Duas vezes por dia útil**, **De 2 em 2 horas**, **A cada hora**, **Todas as manhãs** ou **Arranque de segunda-feira**, ou **Horário personalizado** para usar o editor completo de horários e o fuso horário (o do navegador por predefinição).
5. **Lance a patrulha.** Reveja o plano, o nome da patrulha e **O que faz em cada execução**: as instruções que o assistente recebe sempre que a patrulha se ativa, redigidas a partir das suas respostas. **Redigir com IA** pede ao assistente para as escrever por si; se não conseguir, mantém-se o seu rascunho. Edite o que quiser e prima **Lançar patrulha**.

Ao lançá-la, é criado um novo chat com o perfil e as ferramentas que escolheu, a patrulha é adicionada e a primeira verificação é executada de imediato; **Ver como trabalha** abre esse chat. Salvo se tiver escolhido **Agir por mim**, o ecrã de confirmação também sugere ativar **⚡ Aprovação automática** quando as decisões forem consistentemente acertadas. A partir daí, é uma patrulha normal dentro do chat (explicada abaixo): pode pausá-la ou pará-la na barra de Patrulha, ou pedir no chat para a alterar. Nada é criado até premir **Lançar patrulha**, exceto as condições inegociáveis guardadas, que se tornam memórias assim que premir **Guardar**. Pode fechar o painel de lançamento com **Talvez mais tarde** ou `Esc` a qualquer momento, exceto enquanto **Redigir com IA** está a escrever (até cerca de 45 segundos) ou durante os poucos segundos do lançamento; as respostas são mantidas durante o resto da sessão do navegador. Uma conta só de leitura vê a página **Porquê usar patrulhas?** com uma nota a explicar que não pode guardar memórias nem iniciar uma patrulha, e um botão **Entendido** em vez do restante assistente.

### Patrulhas e temporizadores no chat

Também pode executar uma **patrulha** recorrente ou um **temporizador** de execução única diretamente numa conversa de chat, sem sair da conversa nem a converter numa tarefa em segundo plano separada. Sempre que uma patrulha ou um temporizador se ativa, o assistente reativa-se na mesma conversa, mantendo todo o histórico de mensagens, os ficheiros do espaço de trabalho e os conectores ativos.

Há duas formas de iniciar uma patrulha ou um temporizador:

- **Peça no chat:** diga ao assistente o que deve monitorizar e com que frequência (por exemplo, *«monitorize os meus negócios de 2 em 2 horas e atualize o painel se o ritmo de despesa cair»* ou *«volte dentro de 30 minutos e verifique o carregamento dos dados históricos»*). O assistente usa a ferramenta `chat_patrol` (`create`, `list`, `update`, `pause`, `resume`, `cancel`) para adicionar ou ajustar o agendamento da conversa atual.
- **Use Patrulha no editor de mensagens:** abra **Mais opções** (`•••`) na barra do editor de mensagens e clique em **Patrulha e agendamento** (ou na etiqueta ativa **Patrulha** da barra). Escolha uma predefinição (**A cada hora**, **A cada 2 h**, **A cada 4 h**, **A cada 6 h**, **De segunda a sexta às 9:00**, **Todos os dias às 9:00**, **Daqui a 30 min (uma vez)**, **Daqui a 2 h (uma vez)**, ou **Personalizado** para criar um agendamento recorrente por horas, minutos, todos os dias, dias úteis ou dias específicos da semana e fuso horário, com uma opção **Cron avançado**, ou um temporizador único personalizado em minutos ou horas). Introduza as instruções da patrulha e prima **Iniciar patrulha** (ou **Iniciar temporizador**).

Quando uma conversa tem uma patrulha ou um temporizador ativos ou pausados, a **Barra de Patrulha** aparece acima da conversa com o estado do agendamento (**Patrulha ativa**, **Temporizador ativado** ou **Em pausa**), a frequência, o número de execuções e a contagem decrescente até à próxima, junto dos botões **Executar agora**, **Pausar / Retomar** e **Parar**. Ativar **⚡ Aprovação automática** (na janela de Patrulha, na respetiva barra ou em **Mais opções** no editor de mensagens) permite que as chamadas de ferramentas que admitem aprovação por sessão sejam executadas sem intervenção enquanto está ausente. Se um turno de patrulha preparar um cartão de aprovação, este permanece aberto durante 24 horas e o turno é retomado automaticamente assim que o aprovar. As conversas com uma patrulha ativa ou pausada ficam excluídas da limpeza por retenção até a patrulha ser parada.

Uma patrulha usa o perfil do chat, pelo que um perfil seu, como um gémeo digital, pode monitorizar por si: prima **Iniciar patrulha** numa das patrulhas sugeridas em **Definições → Perfis** (consulte [Os seus próprios perfis e gémeo digital](#your-own-personas-and-digital-twin)).

### Clientes ACP (Zed, Neovim, Emacs, JetBrains, Buzz)

`fleet acp` permite que um cliente Agent Client Protocol comunique com o Fleet. O cliente inicia-o e cada mensagem torna-se um turno normal do chat do Fleet, com o utilizador indicado por `--email` ou `FLEET_USER_EMAIL`. A conversa aparece no chat Web como qualquer outra. As respostas, o raciocínio e os passos das ferramentas são transmitidos ao cliente em direto. Se um passo precisar de aprovação, a resposta termina com uma ligação ou um comando `fleet chat --approve`, porque as aprovações são resolvidas no Fleet, não no cliente. Não são aceites imagens nem áudio. O JetBrains envia as capturas de ecrã que arrasta para o chat apenas como um nome de ficheiro, pelo que o assistente nunca vê a imagem e não é apresentado qualquer aviso.

Os ficheiros que anexa no editor chegam ao Fleet tal como são enviados pelo editor. Quando envia apenas uma ligação para um ficheiro, como faz o JetBrains com um ficheiro anexado ou aberto no editor, `fleet acp` pede o texto ao editor se este permitir aos agentes ler ficheiros (o JetBrains e o agent-shell do Emacs permitem), e envia-o com a mensagem. São enviados até 100 KB de um ficheiro e até 300 KB do conjunto de ficheiros ligados numa mensagem: os ficheiros maiores são reduzidos e os com mais de 1 MB não são enviados; em ambos os casos, o assistente é informado. No JetBrains, isto significa que o ficheiro aberto no editor é enviado ao Fleet com cada mensagem, acrescentando o texto à conversa de cada vez; feche os ficheiros com segredos antes de conversar.

Se o seu operador tiver adicionado o Fleet ao espaço de trabalho do Buzz, pode mencioná-lo aí com @. Por predefinição, apenas a pessoa que o configurou e os seus próprios agentes lhe podem dar instruções; o seu operador também pode autorizar outras pessoas. A resposta chega quando o turno termina, na conversa da sua mensagem, e menciona-o com @; não aparece nada enquanto trabalha e as respostas não são transmitidas em direto nem editadas. Se enviar outra mensagem ao Fleet enquanto trabalha, responderá às duas numa única resposta. O Fleet não pode ler os ficheiros anexados no Buzz, e as instruções de agente e as memórias do Buzz não chegam ao Fleet. A conversa também fica no chat Web do Fleet, sob o utilizador com que o agente é executado.

O Fleet não usa os servidores MCP enviados pelo editor: os que configurou e, salvo se estiver desativado, o integrado no JetBrains. As ferramentas e os conectores do Fleet são os que o seu operador configurou e são executados no servidor do Fleet. A primeira resposta de uma sessão indica-o e nomeia os servidores enviados pelo editor.

Quando o cliente abre uma sessão, `fleet acp` verifica primeiro o seu utilizador e token junto do servidor do Fleet. Um token incorreto, um email que não corresponde a um utilizador do Fleet, um leitor com acesso só de leitura ou um endereço não admitido pelo servidor impedem a abertura da sessão, com um erro que explica o motivo e como o resolver. Um servidor inacessível não a impede: a sessão abre-se e a primeira mensagem informa do problema.

A resposta termina no cliente assim que está completa. O Fleet pode precisar de mais alguns segundos para fechar o turno (por predefinição, dá um nome a uma nova conversa após a primeira resposta); uma mensagem enviada nesse período espera até 90 segundos em vez de ser colocada na fila.

Uma mensagem enviada pelo cliente enquanto outra está em execução não a para. Espera, e as mensagens da mesma sessão são executadas uma de cada vez, pela ordem em que o cliente as enviou. Um cancelamento do cliente para a resposta em curso e as mensagens anteriores ao cancelamento que ainda estejam à espera; uma mensagem enviada logo após o cancelamento é executada. `fleet acp` espera até 2 segundos por uma mensagem que demore a chegar, para manter essa ordem, e depois continua sem ela; nesse caso raro, um cancelamento pode não abranger a mensagem enviada imediatamente antes. Podem estar até 20 mensagens à espera atrás da que está em execução. Uma mensagem número 21 é recusada de imediato com um erro que indica que a sessão já tem um prompt em execução e 20 em espera. Não é enviada ao Fleet; volte a enviá-la quando as anteriores tiverem resposta ou cancele-as no cliente.

Se fechar o editor ou parar o agente enquanto uma resposta está em execução, e o editor permitir que o agente encerre de forma normal (o CodeCompanion.nvim do Neovim permite), esse turno também para no Fleet. As mensagens do cliente que ainda estavam à espera são descartadas: nunca chegam ao Fleet. Uma mensagem que o Fleet já tinha colocado na fila (por exemplo, atrás de um turno iniciado no chat Web) é executada. Um editor que força o encerramento do agente deixa o turno em execução: pare-o no chat Web. O Zed faz isso ao encerrar; no Emacs, fechar o Emacs para o turno, mas fechar o buffer agent-shell não.

### O que acontece quando faz uma pergunta

O assistente faz o trabalho em vez de se limitar a descrevê-lo. Tem um espaço de trabalho privado para cada conversa, com shell, um ambiente de execução de Python e ferramentas de ficheiros, para abrir os dados a que lhe deu acesso (anexados, ligados ou partilhados), analisá-los e entregar o resultado no formato que pedir. Cada passo que realiza aparece na transcrição como um registo que pode expandir. As ações com consequências fora da conversa, como enviar um email ou agendar uma tarefa, param e perguntam-lhe primeiro.

Esse espaço de trabalho é um **ambiente isolado** obrigatório: cada comando, cada linha de Python e cada ficheiro que o assistente lê ou escreve são processados dentro dele, isolados da máquina onde a plataforma é executada. As credenciais dos sistemas ligados nunca entram nele.

## 2. Como ler o ecrã

Há três zonas: a barra esquerda contém as conversas, a transcrição central contém o trabalho e o editor inferior é onde escreve os pedidos.

### A barra lateral

No topo da barra estão as três formas de trabalhar, cada uma com um subtítulo: **Chat** (*Converse sobre o assunto*), **Patrulhas** (*Chats que se ativam de acordo com um horário*: os chats de patrulha e o [Painel de lançamento de patrulhas](#patrol-launchpad-your-first-patrol-in-five-steps)) e **Tarefas em segundo plano** (*Executa-se sem um chat*; anteriormente chamado Centro de operações). **Novo chat** inicia uma conversa nova. O campo de pesquisa, também acessível com `⌘K` ou `Ctrl K`, pesquisa títulos de conversas e também pode pesquisar **Nas mensagens**. Abaixo, as conversas são agrupadas:

| Grupo | O que contém |
| --- | --- |
| **Projetos** | Espaços de trabalho com instruções permanentes, aprendizagens partilhadas e as suas próprias conversas. Um projeto partilhado com a sua equipa tem um ícone de equipa. Consulte [Memórias e projetos](#7-memory-and-projects). |
| **Chats de equipa** | Conversas que os colegas partilham consigo ou abrem em **Modo colaborativo**, com o nome curto do proprietário e uma etiqueta **Em direto** quando o chat colaborativo está ativo. |
| **Fixados** | Conversas que escolheu manter. As conversas fixadas nunca expiram. Se houver duas ou mais, **Reordenar** no cabeçalho permite ordená-las como quiser (consulte [Ordenar os seus chats](#ordering-your-chats)). |
| **Etiquetas** | As suas etiquetas, cada uma como filtro. Clique numa para mostrar apenas as conversas que a têm; clique em várias para restringir mais. |
| **Temporários** | Tudo o resto, com a atividade mais recente primeiro; o menu junto ao cabeçalho permite ordenar por **Mais recentes primeiro** ou **Título A–Z**. Estes chats são eliminados após um período de inatividade (14 dias numa instalação predefinida); o ícone ⓘ junto ao cabeçalho indica-o. Fixe um chat ou mova-o para um projeto para o manter. **Eliminar chats temporários**, a vermelho no fim da barra lateral, elimina-os todos de uma vez após confirmar. |
| **Arquivados** | Recolhido por predefinição. Conversas que pôs de lado sem eliminar; abra o grupo para recuperar uma. |

Uma linha de chat pode ter duas pequenas etiquetas que indicam o público ao passar o cursor: uma significa que é partilhada por ligação e a outra, com a sua equipa. Clique no nome de um projeto para abrir a página e expandi-lo; a seta apenas o recolhe. Ao passar o cursor por um projeto, aparece o menu: **Abrir projeto**, **Novo chat**, **Reordenar chats** (se contiver dois ou mais chats seus) e, para o proprietário, **Partilhar…** e **Definições do projeto…**. Consulte [Manter, organizar e partilhar conversas](#8-keeping-shaping-and-sharing-conversations).

O menu da conta, no fundo da barra, muda a aparência entre **Claro**, **Escuro** e **Sistema**, e abre **Definições** e **Guias** (estes guias de utilização). A opção **Terminar sessão** pede confirmação porque também termina a sessão em todas as aplicações que partilham esse início de sessão.

**Definições → Geral → Idioma** permite escolher **English**, **Español** ou **Português** para a interface e estes guias. A sua escolha é guardada neste navegador. Antes de escolher, a plataforma usa o idioma do seu navegador se estiver disponível; caso contrário, usa inglês. Ao mudar de idioma, a página atual é recarregada e o caminho e a secção são preservados; o parâmetro `lang` do URL também mantém a escolha se o armazenamento do navegador estiver indisponível. As conversas, os ficheiros, os prompts guardados e os restantes conteúdos que escreveu mantêm-se no idioma original.

**Definições → Geral → Notificações do navegador** ativa os alertas no navegador que está a usar, mesmo quando o separador está em segundo plano. Por predefinição, recebe um alerta quando uma tarefa sua termina, espera pela sua resposta ou envia uma nota de progresso durante a execução (**Nota de progresso**: a tarefa continua e o conteúdo da nota não é mostrado); quando uma ação num chat precisa da sua aprovação; e, se a conta tiver um orçamento de utilização, quando tenta criar uma tarefa tendo ultrapassado o limite de aviso (**⚠ Alerta de orçamento**: a verificação é feita nesse momento, não quando o limite é ultrapassado). [Cartões que pedem uma decisão](#6-cards-that-ask-for-a-decision) explica os restantes. O navegador pede permissão na primeira vez. Um alerta mostra apenas um título breve (o início do prompt da tarefa e como correu, a ação pendente ou o orçamento e o período), nunca a conversa nem um resultado. O interruptor aplica-se por navegador e conta; ative-o em cada navegador onde quiser receber alertas. Uma conta **Leitor** não as pode ativar: o interruptor está desativado e a explicação aparece por baixo. Se já estavam ativas antes de a conta passar a leitor, ainda as pode desativar. Funcionam em Chrome, Edge, Firefox e Safari, e em navegadores que usam os mesmos serviços push. Se um navegador usar outro serviço push, o interruptor mostra um erro; ative-as num desses navegadores. Se o interruptor estiver desativado por outro motivo, a linha inferior explica porquê: o navegador não as suporta, estão bloqueadas para este site no navegador (permita-as aí e recarregue) ou a instalação não as configurou. Se a instalação alterar as chaves de notificação, o navegador não recebe alertas até voltar a abrir Fleet, que as renova automaticamente; se o interruptor indicar que não foi possível renová-las, recarregue a página.

Os administradores gerem o acesso das contas em **Definições → Administração → Utilizadores**. O Chat usa **Colaborador** por predefinição; **Leitor** é só de leitura. **Administrador do Fleet** concede todas as permissões de Chat e Tarefas em segundo plano e destaca as opções de Colaborador incluídas. Selecionar novamente Administrador do Fleet desativa-o e define, de forma segura, Colaborador no Chat e nenhum acesso a Tarefas em segundo plano. Cada pessoa tem uma conta do Fleet: o Chat e as Tarefas em segundo plano partilham o email, a palavra-passe e o papel de Administrador do Fleet; o acesso a Tarefas em segundo plano faz parte dessa mesma conta. As contas criadas com acesso ao Fleet no Auth central são adicionadas aqui automaticamente com os papéis aí selecionados. Se a instalação usar o Auth central para iniciar sessão, este gere todas as pessoas por predefinição: a página de acesso só oferece início de sessão único, e esta página lista pessoas e utilização sem controlos (sem **Adicionar utilizador**, editor de linha nem **Mudar o nome da equipa**). Inclui uma ligação para o Auth central, onde se adicionam ou removem pessoas e se alteram os papéis, equipas e palavras-passe. **Definições → Equipa** mostra então a sua equipa, mas não permite alterá-la. Mover alguém de equipa no Auth central também o move aqui, com o mesmo efeito que fazê-lo diretamente: o que partilhava com a equipa anterior deixa de ser partilhado. Mudar o nome de uma equipa no Auth central também o muda aqui e mantém tudo o que era partilhado com essa equipa. Nos restantes casos, mudar aqui o nome de uma equipa mantém tudo o que era partilhado; uma nova equipa que depois use o nome anterior começa sem nada partilhado.

### O cabeçalho

Acima da transcrição, à direita, há dois controlos rápidos para computador: **Painel** muda a conversa para [vista de painel](#dashboard-view), e **Atalhos de teclado** mostra a mesma lista que a [última secção](#13-keyboard-shortcuts) deste guia. Em ecrãs móveis estreitos (`< 40rem`), os botões **Painel** e **Atalhos de teclado** são ocultados do cabeçalho para manter a barra superior compacta (mude para a vista de painel através de **Mais opções → Vista de painel**). **Memórias** e **Mostrar detalhes** (que mostra ou oculta o raciocínio, as notas de trabalho, as chamadas de ferramentas e os custos por turno de toda a conversa) ficam em **Mais opções** (`•••`) no editor de mensagens, com etiquetas claras e acessíveis tanto no chat normal como na vista de painel. Se o seu operador configurar um contacto de suporte no pacote da instalação (`branding.support`), a barra superior também mostra esse botão no Chat, Tarefas em segundo plano, Definições e Guias (em dispositivos móveis, reduz-se a uma etiqueta **Ajuda** ou `branding.support.mobile_label`). Ao premir, abre-se uma janela com a mensagem do operador, um botão **Copiar e-mail** e uma ação **Enviar e-mail** (`mailto:`), omitida por predefinição se não estiver configurada. O cabeçalho de cada conversa também indica quem a pode ver: **Apenas para si**, **Partilhado com a sua equipa**, **Chat colaborativo** ou **Ligação pública**. O editor inclui **Partilhar este chat** dentro de **Mais opções** (`•••`), além de um indicador na barra quando o chat é partilhado. Ambos abrem a janela de partilha.

### A transcrição

As suas mensagens aparecem tal como as escreveu; as muito longas (mais de 4 000 carateres) são recolhidas por predefinição numa pré-visualização com um controlo **Mostrar mensagem completa** / **Mostrar menos** por baixo. Quando a plataforma adiciona a uma mensagem algo que não escreveu, como um anexo ou uma nota da biblioteca de ficheiros partilhados, aparece como uma nota recolhida junto da mensagem, separando claramente o que escreveu do que foi acrescentado.

Cada resposta do assistente segue uma ordem fixa, de cima para baixo, para ver primeiro a resposta e depois o que precisar da sua atenção:

| Parte | O que é |
| --- | --- |
| Registo de execução | Uma linha de etiquetas, uma por cada ferramenta usada: um ficheiro lido, um conector chamado ou código executado. Clique numa etiqueta para ver exatamente o que foi enviado e recebido. Assim pode verificar o trabalho. Uma etiqueta com a cor de perigo indica uma chamada falhada; uma ação enviada para um cartão de aprovação não é considerada falhada: é marcada como **enviado para aprovação**, e o cartão indica se foi executada. Só aparece se **Mostrar detalhes** estiver ativo. Nos turnos executados com a conta de outra pessoa num chat partilhado ou colaborativo, aparece **Detalhes ocultos nos turnos de outros utilizadores** em vez das chamadas privadas de ferramentas, do raciocínio e dos custos por turno. |
| Raciocínio | O raciocínio do assistente explicado por palavras. Também só aparece quando **Mostrar detalhes** está ativo. |
| Notas de trabalho | Enquanto a resposta é gerada, as notas breves que o assistente escreve entre passos («Primeiro vou consultar o negócio»). Só aparecem com **Mostrar detalhes** ativo e até recarregar a página: a conversa guardada mantém a resposta, não as notas. Com os detalhes ocultos, são substituídas por uma linha de estado: **A pensar** ou o passo em curso, como **A executar shell** ou o item do plano em que está a trabalhar. |
| A resposta | Texto, tabelas, gráficos e imagens. O código e os dados aparecem em blocos que podem ser copiados. Quando o assistente cria um relatório HTML, é apresentado como **Pré-visualização de HTML** com um controlo **Mostrar código-fonte**. |
| Cartões interativos | Um formulário, seletor, lista de verificação, comparação, gráfico ou pequena calculadora que o assistente criou para esta resposta. Preencha-o e prima o botão; as suas respostas são enviadas como a mensagem seguinte. Consulte [Cartões interativos](#interactive-cards). |
| Estado | Avisos de situações invulgares do turno: nova tentativa, cancelado ou falhado. Consulte [Quando um turno falha](#11-when-a-turn-goes-wrong). |
| Cartões | Qualquer elemento que peça uma decisão: uma aprovação, uma memória proposta ou uma sugestão de mudança de modelo. Consulte [Cartões que pedem uma decisão](#6-cards-that-ask-for-a-decision). |
| Rodapé | As ações de uma resposta concluída: **Copiar**, **Gerar novamente** e **Tentar novamente com** o modelo mais potente (estas duas últimas só aparecem sob a última resposta; **Tentar novamente com** quando o chat ainda não usa esse modelo e não há um cartão de mudança pendente, porque o cartão oferece o mesmo), **Criar ramificação**, **Guardar como fluxo de trabalho** e **Guardar** (a resposta como memória). Cada uma é explicada mais à frente na respetiva secção do guia. |

As conversas longas ocultam os turnos mais antigos em **Mostrar N turnos anteriores**; um minimapa na margem permite saltar entre mensagens.

### O editor de mensagens

A barra sob a caixa de mensagem mantém à mão os controlos habituais e agrupa as opções secundárias em **Mais opções** (`•••`). Da esquerda para a direita:

| Controlo | O que faz |
| --- | --- |
| Seletor de modelos | Mostra o modelo da conversa e uma faixa de custo de `$` a `$$$$` se o preço for conhecido. Clique para o alterar. Consulte [Escolher o modelo](#picking-the-model). |
| Anexar ficheiros | Adicione ficheiros à mensagem seguinte. Arrastar um ficheiro para qualquer parte da conversa faz o mesmo. |
| Ferramentas | O ícone de chave inglesa. A etiqueta conta os conectores ativos nesta conversa, incluindo os **Sempre ativo**; ao passar o cursor, mostra «Ferramentas, N ativas». Consulte [Conectores numa conversa](#5-connectors-in-a-conversation). |
| Mais opções (`•••`) | Abre um menu com etiquetas organizado em três grupos: **Biblioteca de instruções**, **Perfil** (ativo em qualquer chat novo ou vazio antes de enviar a primeira mensagem, e desativado com *«Só é possível mudar de perfil num novo chat»* quando a conversa já começou) e **Memórias**; **Partilhar este chat**, **Patrulha e agendamento**, **Aprovar ferramentas automaticamente** e **Resumir mensagens anteriores** (quando a conversa tem mensagens, mostra quanto espaço do chat está ocupado); e **Mostrar detalhes**, **Vista de painel** e **Enviar com Enter**. Quando está ativo um perfil diferente do predefinido, um agendamento de patrulha, a partilha (**Chat colaborativo**, com a equipa ou por ligação pública) ou **Aprovação automática**, **Mais opções** mostra um ponto colorido e, nos ecrãs de computador, surge também um indicador de estado diretamente na barra para o ver ou alterar com um clique. |
| Enviar | Na extremidade direita. Enquanto o assistente trabalha, transforma-se em **Parar**. |

### Vista de painel

A vista de painel transforma uma conversa num quadro em direto: os gráficos, números e tabelas do assistente permanecem visíveis como painéis e o chat fica numa coluna estreita ao lado. Use-a para acompanhar algo enquanto continua a conversar: uma carteira de oportunidades, uma campanha, uma lista de lançamento ou uma comparação que está a aperfeiçoar. Ative-a com **Painel** no topo do chat (no computador), **Vista de painel** dentro de **Mais opções**, ou `D`; saia com **Sair**, ou com `Esc` se não estiver a escrever na caixa de mensagem.

- **Peça o que quiser acompanhar.** «Transforme isto num painel», «adicione um painel de negócios em aberto», «atualize o painel de receitas». O assistente cria painéis com os mesmos [cartões interativos](#interactive-cards) que usa no chat e atualiza-os no lugar quando o pede; cada painel mantém a posição e mostra um pequeno número de versão (**v2**, **v3**) e um breve destaque. As mensagens enviadas nesta vista indicam ao assistente que está a olhar para o quadro e quais os painéis que contém, por ordem. Assim, «atualize este gráfico», «atualize o segundo painel» ou «adicione a semana passada ao painel de receitas» chegam ao painel certo, mesmo que tenha fixado o cartão por si próprio. Também lhe pedem para atualizar os painéis em vez de repetir os números no chat. Um quadro vazio oferece alguns pedidos para começar; ao escolher um, é colocado na caixa de mensagem para o editar e enviar.
- **O que aparece no quadro.** Os cartões que apenas mostram informação (gráficos, números, tabelas, listas de verificação) vão para o quadro, tal como os que o assistente tenha marcado como painel. Os formulários que lhe fazem perguntas ficam no chat; **Fixar no quadro** sob um formulário adiciona-o como painel. Um cartão do quadro aparece no chat como uma referência de uma linha; clique nela para saltar para o painel.
- **Organize-o.** Arraste um painel pela pega à esquerda do título, ou foque a pega e use as setas do teclado. Os botões do painel permitem alargá-lo ou estreitá-lo, usar **Focar** para preencher o quadro (`Esc` ou o botão de fecho permitem voltar) e usar **•••** para o mover ou remover; nesse caso, o cartão regressa ao chat. A disposição e a preferência de abrir uma conversa na vista de painel só são guardadas neste navegador; um colega que abra o mesmo chat vê os painéis com a sua própria disposição.
- **As capacidades do assistente não mudam.** Pode escrever, anexar ficheiros e responder a cartões de aprovação na coluna do chat como antes; os emails e as restantes ações continuam a esperar pela sua aprovação. O indicador superior mostra **Em espera**, o nome do passo em curso enquanto o assistente trabalha ou quantas aprovações estão pendentes; clique nele para ir para a primeira.
- **Num telefone**, a barra superior tem botões **Quadro** e **Chat** para alternar entre ambos.
- **A lista de conversas fica oculta**, pelo que os seus atalhos (`J`/`K`, `P`, `A`, `R`, `#`) não têm efeito na vista de painel, e `⌘ K` sai dessa vista para abrir a pesquisa.
- **Pode voltar quando quiser.** Ao sair da vista de painel, regressa ao chat normal, com todos os cartões no lugar e o que tiver escrito na caixa de mensagem ou num cartão intacto. Ao voltar, o quadro é reposto tal como o deixou.

Os painéis são cartões, pelo que se aplicam os limites de [Cartões interativos](#interactive-cards): um painel anterior a uma compactação é marcado como **arquivado** e não aceita respostas, e o quadro só aparece na aplicação Web.

## 3. Como obter boas respostas

Se um fornecedor falhar após um passo de ferramenta concluído, o assistente pode continuar com os resultados através de uma recuperação limitada. Uma ferramenta iniciada durante o passo falhado impede a recuperação, para evitar repetir uma ação com resultado incerto. Verifique o registo de execução antes de repetir manualmente um pedido que tenha terminado com erro.

Dê instruções ao assistente como a um colega competente: explique o que quer, o que deve usar e comente o resultado. A qualidade da resposta depende do pedido; alguns hábitos melhoram-na sempre.

| Hábito | Porque funciona |
| --- | --- |
| **Nomeie a fonte** | Indique qual o relatório, remetente ou conector. «O relatório diário de entregas mais recente da caixa de correio» funciona; «o último ficheiro» obriga o assistente a adivinhar, e uma suposição errada pode parecer correta. |
| **Especifique os identificadores** | Os nomes de negócios, códigos de campanhas e identificadores são os elementos mais fáceis de interpretar mal, mesmo que todos os números à volta estejam corretos. Especifique exatamente os identificadores que pretende e peça para serem apresentados tal como aparecem na fonte. |
| **Use os dados como referência** | Os relatórios costumam ter um dia ou mais de atraso; peça «a data mais recente do ficheiro» em vez de «ontem». Cada fonte tem a sua própria data mais recente; deixe o assistente encontrá-la nos dados sem a presumir. |
| **Peça para mostrar o trabalho** | «Mostre-me as linhas que justificam esse número» é a verificação mais rápida. O registo de execução mostra o que fez; isto mostra as provas. |
| **Assinalar, não adivinhar** | Indique claramente: «Se não conseguir abrir algo ou faltar algum dado, diga-o e continue com o restante». Um relatório fiável explica o que não conseguiu fazer. |
| **Pedidos pequenos, um de cada vez** | Construa por passos. Primeiro obtenha os dados certos; depois, a comparação e, por fim, o formato. Comente cada resultado: «demasiado detalhe», «mostre isso numa tabela», «ponha as datas no topo». A conversa de correção é o que dá ao relatório a sua forma final. |

### Escolher o modelo

Cada conversa usa um modelo que pode alterar a qualquer momento, mesmo a meio da conversa. Clique no seletor de modelos, escreva para pesquisar e escolha o que melhor se adapta ao trabalho. Os modelos que a instalação marca como **recomendado** aparecem no início da lista. O primeiro é o **modelo predefinido**, o nosso modelo de ponta mais inteligente, com que começa cada nova conversa para oferecer o melhor raciocínio e uso de ferramentas. O segundo é o **modelo alternativo**, outro modelo de ponta inteligente de uma família de fornecedores diferente, a que as tarefas e patrulhas recorrem automaticamente em caso de falha e que o assistente propõe quando um turno tem dificuldades. Por predefinição, são **Gemini 4 Argon** (o das novas conversas) e **Claude Opus 5.5** (o modelo de ponta alternativo); o administrador pode alterar qualquer um dos dois. Para otimizar a despesa em consultas, verificações ou formatos de rotina, pode escolher um modelo mais económico ou gratuito. O administrador também pode fixar modelos abaixo dos dois recomendados, por vezes com um nome próprio e uma etiqueta como **alfa**, que indica que ainda estão em teste. Um modelo fixado também pode mostrar **Grátis** em vez da faixa de custo. Os restantes modelos têm um estado (**testado**, **novo** ou **experimental**) e, se a instalação conhecer o preço, mostram a faixa de custo para saber o que vai gastar. Se não houver faixa, o preço é desconhecido, não zero; convém perguntar antes de iniciar um trabalho longo.

O seletor usa os fornecedores de modelos ativos do espaço de trabalho, incluindo os configurados pela instalação. Os modelos de **Espaço de trabalho** são executados diretamente através do fornecedor indicado. Quando a informação dos fornecedores é carregada, são ocultadas as opções recomendadas ou do catálogo público a que o espaço de trabalho não pode aceder. Uma conversa guardada ou uma predefinição que já não está disponível mantém-se visível com uma explicação: use **Escolher um modelo**, escolha um modelo disponível e tente novamente. O Fleet não muda silenciosamente uma conversa existente para outro fornecedor, exceto num caso: uma conversa em **modo restrito** só pode usar os modelos permitidos pelo administrador (por predefinição, o predefinido e o alternativo do espaço de trabalho). Se essa lista mudar, o turno seguinte usa o modelo predefinido do modo restrito e a conversa mantém-no a partir daí. O seletor de modelos mostra a mudança ao começar o turno. Essa mudança precisa de um modelo concreto: se o administrador tiver definido a lista do modo restrito apenas com padrões e sem nomes de modelos, não há um destino possível e a conversa continuará a recusar pedidos. Inicie um novo chat restrito e avise o administrador de que a lista precisa primeiro de um modelo com nome. Os administradores podem corrigir a configuração dos fornecedores em **Definições → Administração → Fornecedores de modelos** e definir o modelo predefinido e o alternativo em **Definições → Administração → Funcionalidades → Níveis de modelos**. Além de OpenRouter, Anthropic, OpenAI e Ollama, essa página permite adicionar qualquer servidor **compatível com OpenAI** (requer o seu URL base; a chave é opcional), **Vercel AI Gateway** (requer uma chave), um recurso **Azure OpenAI** (requer uma chave e o endpoint do recurso como URL base; os modelos são os nomes das implementações do recurso), **Google Gemini** (requer uma chave de API do Gemini de Google AI Studio) e **Amazon Bedrock** (apenas modelos Claude; requer uma chave de API do Bedrock e a região AWS onde a chave foi criada, us-east-1 por predefinição, e os modelos são identificadores de perfis de inferência do Bedrock, como `us.anthropic.claude-sonnet-4-5-20250929-v1:0`). No Azure, uma implementação de GPT-5 ou da série o deve incluir o modelo no nome, como `gpt-5-prod`; caso contrário, os turnos falham. Um modelo de raciocínio mais recente, como o GPT-6, pode falhar independentemente do nome da implementação. Um modelo do Vercel adicionado aí passa a usar o Vercel em vez do OpenRouter. Um fornecedor adicionado aí, exceto OpenRouter, precisa da sua **Janela de contexto** (em tokens, o menor limite dos modelos que oferece) antes de poder ser ativado. Se não a tiver, é marcado como **Sem janela de contexto**, e um turno costuma parar antes de responder com «O modelo selecionado não conseguiu concluir este turno». Se acontecer sempre com um modelo, peça ao administrador para a configurar. Uma tarefa agendada a partir do chat não mantém o respetivo modelo: salvo se pedir um concreto, usa o modelo de tarefas do espaço de trabalho, que por predefinição é o mais potente. Se um fornecedor direto tiver prioridade sobre OpenRouter, as opções disponíveis do OpenRouter têm o nome do fornecedor configurado e usam uma rota explícita com o respetivo prefixo.

Por vezes, o próprio assistente sugere mudar: um cartão com **Mudar e tentar novamente** se a pergunta exceder o que o modelo atual resolve bem, ou um aviso de uma linha se anexar uma folha de cálculo grande ao modelo rápido. O Fleet pode mostrar esse mesmo cartão após uma resposta com dificuldades claras (várias falhas de ferramentas seguidas, um passo repetido ou um turno muito longo) e, salvo se o administrador o tiver desativado, quando a mensagem expressa desacordo com uma resposta incorreta. Tudo isto são sugestões. Nada muda se não aceitar. Se uma resposta estiver errada e não quiser esperar por uma sugestão, **Tentar novamente com** sob a última resposta repete o pedido de imediato com o modelo mais potente.

### Perfis e competências

Um **perfil** é uma forma de trabalhar guardada que a instalação pode incluir e que se escolhe no editor de mensagens. Uma **competência** é uma capacidade empacotada que o assistente pode usar por si só quando se adequa à tarefa, ou que pode invocar escrevendo `/` no início da mensagem e escolhendo-a na lista. A plataforma inclui um pequeno conjunto de competências de uso geral e a instalação pode acrescentar as suas. Em **Definições → Competências**, também pode criar competências pessoais, publicar uma competência em **Competências da área de trabalho** (**Partilhar com o seu espaço de trabalho**), clicar em **Adicionar às minhas competências** numa competência partilhada por um colega em Competências do espaço de trabalho para a ativar nos seus chats e tarefas, ou clicar em **Clonar e editar** em qualquer competência do espaço de trabalho para carregar as instruções no editor e personalizá-la. Também pode pedir ao assistente no chat para propor uma competência ou editar uma existente e depois clicar em **Aprovar** ou **Aprovar e partilhar** em **Definições → Competências**. As suas competências pessoais ativas aparecem junto às do espaço de trabalho no menu de preenchimento automático `/` do editor de mensagens. Se personalizar uma competência do espaço de trabalho com o mesmo nome, a sua versão substitui a descrição e as instruções predefinidas nas suas execuções.

### Os seus próprios perfis e gémeo digital

Em **Definições → Perfis**, pode escrever os seus próprios perfis. São privados: apenas os chats que inicia os podem usar, e aparecem em **Os seus** no menu de perfis do editor de mensagens (dentro de **Mais opções** `•••`).

- **Crie o seu gémeo digital.** Descreva-se (a sua função, o que monitoriza, como decide e como prefere que as coisas sejam escritas), escolha se o gémeo pode ler o que escreveu em chats recentes e selecione **Sugerir ações** ou **Agir em meu nome**. **Criar com o assistente** abre um novo chat com esse pedido no editor; nada é enviado até premir Enviar. O assistente só pode ler as mensagens que escreveu, não as suas próprias respostas nem os chats em modo restrito, arquivados ou eliminados; faz algumas perguntas e prepara um perfil **rascunho** com patrulhas sugeridas. **Escrever eu** abre o editor com um modelo de gémeo digital.
- **Os rascunhos esperam por si.** Um perfil proposto pelo assistente mostra **Proposto — reveja-o** (ou **Alteração proposta a…** se alterar um que já tem) e não faz nada até premir **Aprovar**; **Descartar** elimina-o. Também pode pedir ao assistente em qualquer chat para criar ou melhorar um perfil; usa a ferramenta `persona_studio` e o resultado aparece aqui da mesma forma.
- **Novo perfil** abre o editor, com a opção de começar a partir de um modelo (**Gémeo digital**, **Analista de patrulha**, **Assistente de escrita**). Defina um nome de apresentação (o nome curto deriva dele e não pode mudar depois, porque os chats o usam como referência), uma linha que explique para que serve, **Gémeo digital** ou **Assistente especialista**, **Sugerir ações** ou **Agir em meu nome**, o perfil do espaço de trabalho em que **Baseia-se em** (herda a sua experiência e acesso a ferramentas; o seu perfil acrescenta instruções, mas não pode desbloquear ferramentas que esse perfil não tenha), as instruções e até 8 patrulhas sugeridas (um título, predefinições rápidas de frequência ou o editor de horários por horas, minutos, todos os dias, dias úteis ou dias específicos da semana, um seletor de fuso horário e o que fazer de cada vez; com pelo menos 5 minutos entre execuções e uma opção **Cron avançado** quando necessária). Pode guardar até 50 perfis.
- **Iniciar chat** abre um novo chat com esse perfil. **Iniciar patrulha** numa patrulha sugerida abre um novo chat com esse perfil, adiciona-lhe a patrulha e executa a primeira verificação de imediato. Um perfil configurado como **Agir em meu nome** ativa **⚡ Aprovação automática** nesse chat; um configurado como **Sugerir ações** mantém os cartões de aprovação. Nos dois casos, a autonomia é uma instrução ao assistente mais essa predefinição; a definição de aprovação do chat continua a determinar quais as chamadas de ferramentas que exigem a sua intervenção.
- **Editar** altera todos os chats que usam esse perfil a partir do próximo turno. **Eliminar** mantém esses chats; continuam com o perfil predefinido do espaço de trabalho.
- **Perfis do espaço de trabalho** lista os perfis da sua instalação: use **Iniciar chat** num deles, ou **Personalizar** para criar o seu próprio perfil a partir dele.

Para apresentações Bento, a instalação pode oferecer um modelo inicial com a sua marca. Pode pedir outro tema ou uma apresentação vazia; a disposição e o estilo do modelo inicial são editáveis. Descarregue o ficheiro `.bento.html` e abra-o num navegador para o ver e editar sem ligação.

## 4. Como fornecer dados

Há quatro formas de fornecer dados a uma conversa. Na maioria dos dias, usará as duas primeiras.

| Via | Como funciona |
| --- | --- |
| **Anexar um ficheiro** | Clique em **Anexar ficheiros** ou arraste um ficheiro para a conversa e faça perguntas sobre ele nessa mesma mensagem. São aceites folhas de cálculo, CSV, PDF, documentos e imagens. Os ficheiros demasiado grandes são recusados ao escolhê-los, indicando o limite, em vez de falharem depois. Um anexo pertence à conversa onde foi enviado; uma nota junto da mensagem regista o que foi acrescentado. |
| **Fontes ligadas** | Caixas de correio, APIs de relatórios e outros sistemas ligados à instalação. O assistente consulta-os quando o pede, usando apenas os conectores ativos nessa conversa. Nomeie a fonte no pedido; consulte [a secção seguinte](#5-connectors-in-a-conversation) para saber como ativar os conectores. |
| **Biblioteca de ficheiros partilhados** | Ficheiros de referência que um administrador publica uma vez para todas as conversas: dados históricos, listas de preços ou tabelas de consulta. Ficam em **Definições → Ficheiros partilhados** e o assistente vê-os em todos os chats sem ser necessário voltar a anexá-los. |
| **Ficheiros criados pelo assistente** | Tudo o que produz numa conversa (uma folha de cálculo, um gráfico, um relatório HTML ou uma imagem gerada com o conector opcional **Geração de imagens** (`image_generation`) ativo, por predefinição **Google Nano Banana 2.1**, `google/gemini-nano-banana-2.1`) permanece no espaço de trabalho dessa conversa. Descarregue-o a partir da transcrição, pré-visualize HTML aí mesmo e faça perguntas sobre ele em turnos posteriores usando o nome. |

> **Referências em linha, se estiverem ativas.** Algumas instalações permitem escrever referências numa mensagem: `@url:` seguido de um endereço Web incorpora essa página no turno, e `@file:` seguido de um nome de ficheiro incorpora um ficheiro criado antes pelo assistente nessa conversa. Ambas as funções estão desativadas salvo se um operador as ativar; se uma referência não fizer nada, a função está desativada e pode anexar como sempre.

Nos conectores que aceitam entradas de ficheiros binários, Fleet pode enviar diretamente um fragmento de ficheiro do espaço de trabalho com o hash verificado. Isto evita copiar cadeias base64 grandes para a conversa e funciona sem acesso HTTP do ambiente isolado. O ficheiro completo pode ocupar até 64 MiB e é enviado em fragmentos de um máximo de 8 MiB; o conector pode impor limites inferiores. Continuam a aplicar-se as permissões e as verificações de publicação do conector; um carregamento preparado não significa, por si só, que uma página ou um documento tenha sido publicado.

O assistente guarda os ficheiros obtidos por ligação (uma ligação para um relatório num email, um URL de descarga assinado devolvido por um conector ou um CSV público) no espaço de trabalho da conversa através da ferramenta de descarga. Um ficheiro pode ocupar até 512 MB (se for maior, não é guardado) e uma descarga pode demorar até 5 minutos por predefinição, com um máximo de 30. Se uma ligação mostrar primeiro uma página de «a descarga vai começar» ou uma página cuja única ligação é o ficheiro, o assistente segue-a até lá, até um máximo de três páginas. Se uma ligação que identifica uma folha de cálculo ou um relatório devolver uma página Web (normalmente um início de sessão ou uma ligação expirada), o assistente é informado para não a tratar como o ficheiro. As ligações para endereços privados ou internos são recusadas. Voltar a descarregar a mesma ligação reutiliza o ficheiro anterior se nada tiver mudado; uma descarga é recusada se deixar o servidor com pouco espaço livre.

## 5. Conectores numa conversa

Um conector é uma ligação ativa a um sistema: uma caixa de correio, uma API de relatórios ou um repositório de documentos. Ativá-lo tem dois níveis no Chat e um terceiro no Centro de operações.

| Nível | Onde | O que determina |
| --- | --- | --- |
| Disponibilidade | **Definições → Ligações** | Quais os conectores disponíveis, se cada um está ativo por predefinição em novos chats e qual a conta usada se tiver várias. Configura-se uma vez e mantém-se. |
| Seleção | O menu **Ferramentas** (a chave inglesa) do editor de mensagens, a respetiva biblioteca ou um cartão **Ativar o conector MCP?** no chat | Quais dos seus conectores disponíveis estão ativos em *esta* conversa. Limite a seleção se o chat só precisar de uma fonte; se uma tarefa precisar de um conector MCP opcional do pacote que está ligado mas inativo nessa conversa, o assistente pode propor ativá-lo para aprovação (ou ativá-lo por si só se **Aprovação automática** estiver ativo). |
| Associação | O formulário de tarefas da página Tarefas em segundo plano | Quais os conectores que uma tarefa agendada pode usar, fixados quando é criada. Uma alteração posterior às suas preferências nunca modifica uma tarefa existente. |

**Definições → Ligações** mostra inicialmente quatro ligações em **Incluído na sua área de trabalho** e as que adicionou em **Adicionadas por si**. Uma ligação que precisa que inicie sessão tem um contorno âmbar e mostra **Iniciar sessão** (**Iniciar sessão novamente** enquanto está ligada, para renovar a sessão). **Mostrar tudo** abre uma janela com todos os conectores do espaço de trabalho e os mesmos controlos de disponibilidade, ativação em novos chats e conta predefinida. Uma ligação para um conector fora da pré-visualização abre essa janela automaticamente. **Contas de credenciais** lista as contas com nome que os conectores podem usar (por exemplo, uma por cliente), inicialmente quatro; **Mostrar tudo** expande a lista e **Mostrar menos** recolhe-a. A lista é só de leitura: o seu administrador adiciona e remove estas contas no servidor do Fleet (`fleet mcp account set`), e os seus segredos nunca são apresentados no navegador.

**Encontrar mais ligações** começa com oito opções selecionadas de **Popular**: Microsoft 365 (Outlook), GitHub, Slack, Gmail, Google Drive, Notion, Linear e Salesforce. Um espaço de trabalho com outro catálogo pode mostrar opções diferentes. Sob a pesquisa, as etiquetas de categorias (**Popular**, **Todos** e filtros com contagens) e os cartões **Explorar por categoria** permitem explorar conectores por categoria ou ver todo o diretório agrupado por categoria, com paginação **Mostrar mais** / **Mostrar tudo**. Pesquise por nome ou palavra-chave em todo o diretório ou na categoria escolhida; limpar a pesquisa recupera a vista selecionada (**Popular**, **Todos** ou a categoria ativa), e clicar em **Voltar a Populares** regressa às opções populares. Se faltar o conector pretendido, use **Contactar Elcano** sob a pesquisa para o solicitar.

O menu Ferramentas abre com a pesquisa pronta: escreva para filtrar por nome, descrição, categoria ou nome de uma ferramenta do conector; uma correspondência interna aparece por baixo, como em `↳ ix_clone_deal`. Os conectores ativos aparecem primeiro em **Ativado**; os restantes, sob as respetivas categorias, como **SSP** ou **Gestão de negócios**, e **Outras ferramentas** no fim. A lista **Ativado** mantém a ordem enquanto o menu está aberto, para que uma linha não mude de lugar ao ativá-la ou desativá-la. `↑` e `↓` percorrem a lista; `Space` ou `Enter` altera o estado do conector destacado; `Esc` limpa a pesquisa e depois fecha o menu. Um conector que precisa de configuração ou está indisponível fica oculto até uma pesquisa o encontrar; aparece esbatido, sem interruptor, e selecioná-lo abre-o na biblioteca. **Ativar todas** e **Desativar todas** alteram todos os conectores visíveis no menu; com uma pesquisa, só afetam as correspondências («Os 3 ativos»). O número ao lado indica quantos estão ativos. O ícone de expansão junto à pesquisa, ou **Abrir biblioteca** no fundo do menu, abre a biblioteca **Ferramentas e ligações**: todos os conectores que pode usar no Chat, com filtros de categoria e estado à esquerda, a lista ao centro e o conector selecionado à direita, com o interruptor, estado, **Mostrar N ferramentas** para ver as ferramentas e **Gerir nas Definições** para escolher se começa ativo em novos chats. Num telefone ou numa janela estreita, os filtros deslocam-se horizontalmente como etiquetas, e tocar num conector abre os detalhes noutro ecrã; o botão de voltar no topo (ou `Esc`) regressa à lista. Uma instalação pode reservar ferramentas de conectores para tarefas agendadas, normalmente operações de escrita direta a que o Chat acede através de um processo revisto. O Chat exclui essas ferramentas do menu, da pesquisa, da lista **Mostrar N ferramentas** da biblioteca e de todas as contagens; também não mostra um conector **Incluído** se todas as ferramentas estiverem reservadas. Um conector de terceiros em que tenha iniciado sessão por si próprio aparece, porque as suas ferramentas só são conhecidas quando uma conversa o abre. O assistente não pode chamar uma ferramenta reservada numa conversa, independentemente do que ativar. Uma tarefa agendada pode; por isso, o formulário pode mostrar ferramentas e conectores ausentes do Chat. Se um conector tiver várias contas, o menu **Conta** da linha e da biblioteca escolhe a desta conversa; a predefinida mostra o nome da instalação ou a conta escolhida em **Definições → Ligações**. Um conector que **Requer configuração** tem credenciais adicionadas ao servidor pelo administrador; a ligação **Configurar nas Definições** do administrador abre aí o respetivo cartão. O Fleet carrega no máximo oito ligações de terceiros num turno, contando tanto as que ligou como as partilhadas consigo (as incluídas não contam). Se ativar mais, o turno informa o assistente das excluídas: os primeiros dez nomes e uma contagem das restantes, para que possa avisar se pedir alguma. Mantenha em cada conversa apenas os conectores de que precisa. Alguns conectores estão marcados como **Sempre ativo**: fazem parte da instalação, não podem ser desativados por conversa e os dois botões não os alteram. Cada conector também indica se é **Incluído**, incluído e gerido com a instalação, ou um serviço de terceiros em que iniciou sessão, para saber sempre a que sistema acede. Se um conector de terceiros precisar de um prefixo antes da chave de API, o formulário indica-o (por exemplo, `Authorization: Token token=<key>`); cole apenas a chave. Um conector disponível em vários servidores, como a região europeia de um fornecedor, mostra uma opção **Endpoint** no cartão e no formulário **Adicionar outra conta** de uma ligação; escolha a sua antes de o adicionar. Uma etiqueta **Beta** indica que funciona, mas ainda precisa de melhorias. Uma etiqueta **O diretório mudou** numa ligação de terceiros em **Definições → Ligações** indica que a entrada do diretório com esse nome usa agora outro endereço, método de acesso ou localização de chave; a linha explica o que muda. A ligação mantém os dados com que foi adicionada; elimine-a e adicione-a novamente a partir do diretório para adotar a alteração. Não é possível manter o início de sessão anterior. Uma ligação configurada manualmente com um nome do diretório também mostra a etiqueta e pode manter-se como está.

A maioria das entradas do diretório é adicionada com um clique e depois pede para iniciar sessão no fornecedor. Alguns fornecedores (como Slack, GitHub ou Google Workspace) não permitem que a plataforma se registe automaticamente. Se o administrador já tiver configurado no servidor a aplicação OAuth do espaço de trabalho, essas entradas também exigem apenas um clique: clique em **Adicionar** e inicie sessão com a sua conta. Se o servidor ainda não tiver uma aplicação partilhada configurada, a entrada abre um formulário breve: mostra o **URL de retorno de autorização** que deve fornecer ao fornecedor e pede um **ID de cliente OAuth** e, se o fornecedor o exigir, um **Segredo de cliente OAuth**; o formulário indica quando o segredo é obrigatório. O cliente vem de uma aplicação registada no fornecedor para esse URL de retorno. Siga as instruções de configuração do cartão; por exemplo, em Slack, dentro de `api.slack.com/apps`, crie uma aplicação interna do espaço de trabalho, adicione o **URL de retorno de autorização** em **OAuth & Permissions → Redirect URLs** junto dos **User Token Scopes** pretendidos e ative **Model Context Protocol** em **Features → Agents & AI Apps**. Um administrador também pode configurar uma vez o ID de cliente e o segredo dessa aplicação no servidor, para que as restantes pessoas se liguem com um clique. Após o formulário, inicia sessão no fornecedor como habitualmente.

Se o serviço de que precisa não estiver no diretório, ou só oferecer uma API HTTP ou um portal Web, clique em **Criar uma ligação na conversa** em **Definições → Ligações** (ou escreva `/connector-builder` no Chat) para abrir um chat guiado do Connector Studio. O assistente procura primeiro um servidor MCP oficial; se não existir, usa um conector API HTTP personalizado (etiqueta **API personalizado**) ou um de automação Chromium sem interface (etiqueta **Automatização do navegador**, com uma vista de navegador Co-Pilot opcional em direto para completar por si próprio SSO, 2FA ou um CAPTCHA). Recolhe chaves de API ou palavras-passe num campo oculto, para que o segredo permaneça no anfitrião, e guarda a ligação para si ou para todo o espaço de trabalho. Uma vista de navegador em direto termina quando clica em **End Session**, quando o assistente a fecha, após 10 minutos sem atividade, quando o Fleet reinicia ou quando o Fleet precisa do lugar para uma sessão mais recente; a respetiva ligação abre então uma página a indicar que a sessão já não está disponível e o assistente pode abrir uma nova.

Quando a vista de navegador em direto não consegue fazer algo que pediu, uma nota breve no topo indica-o e, para um endereço que não abre (por exemplo, um que não seja uma página Web), explica porquê.

Cada chamada a um conector aparece como uma etiqueta no registo de execução. Se um número parecer incorreto, abra a etiqueta e leia o que o conector devolveu antes de questionar o cálculo.

> **As credenciais nunca saem da plataforma.** O assistente usa uma ligação, mas nunca vê as credenciais que estão por trás. As chaves e os tokens permanecem no anfitrião, são incorporados numa chamada apenas no momento de a realizar e nunca entram no ambiente isolado, na conversa nem no contexto do modelo.

## 6. Cartões que pedem uma decisão

Quando o assistente quer fazer algo com consequências fora da conversa, para e prepara um cartão. Nada acontece até responder; se ninguém responder, considera-se um não.

É assim que os cartões funcionam por predefinição. Uma instalação também pode colocar uma ferramenta em modo **notificação**, em que a chamada é executada primeiro e o cartão regista o que foi feito em vez de pedir permissão. Leia os botões, não apenas a presença de um cartão: se oferece uma decisão, está a reter a ação; se só permite descartá-lo, está a informar. As regras seguintes referem-se ao primeiro tipo.

| Cartão | Quando aparece | As suas opções |
| --- | --- | --- |
| Enviar este email? | O assistente redigiu uma mensagem e quer enviá-la. O cartão mostra remetente, assunto e destinatários Para, Cc e Bcc em linhas separadas, lista pelo nome todos os ficheiros enviados, incluindo imagens inseridas (visíveis mesmo com o corpo recolhido), e mostra o corpo. Nos emails HTML que excedem a altura da pré-visualização, ou em telefones onde a vista recolhida permite deslocar a página, prima **Expandir email completo** / **Recolher pré-visualização do email** para ver a mensagem completa e interagir com ela. | **Enviar** · **Cancelar** |
| Pré-visualização do email | O assistente quer mostrar-lhe um rascunho sem o enviar, com o mesmo seletor de caixa de entrada **Claro** / **Escuro**, seletor de tamanho **Telemóvel** / **Computador** em ecrãs largos, **Mostrar código-fonte** e controlos **Expandir email completo** / **Recolher pré-visualização do email**. | **Descartar**: apenas para visualizar |
| Executar este comando de shell? | Um comando que a plataforma considera arriscado. | **Aprovar e executar** · **Cancelar** |
| Agendar uma tarefa | O assistente propõe uma tarefa agendada, normalmente porque escolheu **Criar tarefa recorrente…**. Consulte [Do chat para uma tarefa](#10-from-chat-to-a-task). | **Aprovar e agendar** · **Editar** · **Cancelar** |
| Alterar uma tarefa | O assistente quer parar ou atualizar uma tarefa agendada existente. | **Aprovar e parar** ou **Aprovar e atualizar** · **Cancelar** |
| Ativar o conector MCP? | O assistente precisa de um ou mais conectores MCP opcionais do pacote, já ligados mas ainda inativos nesta conversa. Aprová-los ativa-os nesta conversa e retoma a resposta com as ferramentas disponíveis. Se tiver sido atingido o limite horário de retomas automáticas ou o da fila de entrada, aparece um aviso e as ferramentas aplicam-se à mensagem seguinte. Com **Aprovação automática** ativo, o assistente ativa os conectores opcionais do pacote já ligados sem parar num cartão e continua automaticamente dentro desses limites. | **Aprovar e continuar** · **Recusar** |
| Executar uma ação | Qualquer outra ação de um conector que altere algo, como atualizar um registo num sistema externo. O cartão indica a ação, o sistema onde é executada e os argumentos com que foi chamada. Uma instalação pode apresentá-lo em linguagem simples: **APROVAÇÃO NECESSÁRIA** com a contagem decrescente, um título, o registo com o identificador e uma ligação (**Abrir em…**), cada alteração como antes → depois e avisos como «O negócio está ativo» em etiquetas, com os argumentos originais em **Detalhes**. As listas longas mostram os primeiros 10 itens com **Mostrar mais N**, e uma pesquisa se houver mais de 25. | **Aprovar e executar** (**Aprovar** num cartão em linguagem simples) · **Cancelar** |

Três regras para todos os cartões. **Leia o que vai acontecer**, não apenas o botão: o cartão existe para o explicar. **Cancelar não custa nada**: o assistente continua sem realizar a ação e pode pedir-lhe outra forma de o fazer. **Os cartões expiram**: um cartão sem resposta expira como recusado, e a transcrição regista-o. Por predefinição, um cartão de ação espera um dia (24 horas), e uma conversa ou um espaço de trabalho pode alargar esse prazo até 7 dias.

Após aprovar, o cartão mostra o que aconteceu: foi executado, falhou, continua em execução ou, se for um cartão antigo cuja execução terminou antes de os resultados serem guardados, o resultado não foi registado. Um cartão em linguagem simples resume-o numa linha (**Aplicado**, **Não aplicado**, **Recusado**, **Tempo esgotado: não aplicado**), com o resultado próprio da ação por baixo e os registos em **Detalhes**. Uma instalação também pode fazer com que certas ações comuniquem o seu próprio resultado. O cartão concluído explica então numa linha o que aconteceu («Criado 1 negócio de Index Exchange · verificado»), com uma linha por registo: o nome, os identificadores, um estado (**Concluído**, **Não aplicado**, **A verificação não corresponde**, **Requer verificação**, **Resultado incerto**, **Já realizado**, **Não executado**) e uma ligação. O resultado original passa para **Detalhes**. **Requer verificação** significa que o registo foi aplicado, mas um passo posterior falhou (por exemplo, o negócio existe, mas a lista de exclusões não foi adicionada); a nota explica qual, e não é proposta uma nova tentativa porque o registo já existe. Se alguns registos falharam, **Repetir falhados (N)** pede ao assistente para tentar novamente apenas esses, e a nova tentativa regressa como um novo cartão para aprovação: o clique não executa nada. Nunca é proposta uma nova tentativa para um registo que possa já existir. Uma ação executada sem perguntar pode explicar o que fez da mesma forma («Campanha ID ELC07375 atribuída»). Um cartão ainda em execução não é uma nova decisão: não mostra Cancelar, Editar nem a contagem decrescente de expiração, e **Verificar resultado** consulta o resultado sem executar a ação duas vezes. No chat de terminal aplicam-se os mesmos indicadores: `/approve <id>` num cartão em execução obtém o resultado; um resultado histórico desconhecido é tratado como erro, não como sucesso.

Por predefinição, uma ação aprovada de um conector (um cartão **Executar uma ação** ou um envio de email) tem um minuto para terminar. A instalação pode dar mais tempo a conectores lentos, por exemplo para criar ou atualizar registos externos. Se uma ação dessas continuar em execução após cerca de 50 segundos, é apresentada de imediato como em curso em vez de bloquear a página; use **Verificar resultado** um pouco depois para consultar o resultado. Os comandos de shell e os cartões de tarefas mantêm os seus próprios limites.

Uma instalação também pode fazer com que determinadas ações **comuniquem o progresso** durante a execução, por exemplo ao criar muitos registos externos. O cartão em execução mostra então uma barra e uma linha como **12 de 24 · a criar o negócio 12**, atualizadas a cada poucos segundos enquanto o separador está aberto e mantidas ao recarregar; ao terminar, muda sozinho para o resultado, sem usar **Verificar resultado**. Se ativou as notificações do navegador (**Definições → Geral → Notificações do navegador**), também recebe uma quando uma ação deste tipo termina (**✓ Concluído** ou **✗ Não aplicado**, com o título do cartão) e quando o assistente não conseguiu continuar por si só após aprovar, recusar ou esgotar o tempo de um cartão. Clicar nela abre a conversa no separador de Chat se estiver aberto (é recarregado e perde-se qualquer mensagem por enviar), ou num novo. O Safari no Mac não abre novos separadores a partir de notificações; após um momento, abre o último separador de Fleet usado e também o recarrega. Se não houver nenhum separador de Fleet aberto, o clique não abre nada.

As notificações do navegador pertencem à conta que as ativou nele. Terminar sessão pelo menu da conta desativa-as aí, para que a pessoa seguinte não receba as suas. Fechar o separador ou deixar expirar a sessão não as desativa; termine sessão num computador partilhado. O interruptor indica se este navegador recebe notificações de **sua**; se outra pessoa as ativou ou já não estiverem registadas para si, aparece desativado e pode voltar a ativá-lo.

Uma instalação também pode **agrupar** certas ações, por exemplo reservar o mesmo plano em vários sistemas externos. Se o assistente pedir duas ou mais numa resposta, chegam num cartão intitulado **N ações para aprovar**, com uma linha por ação, a respetiva caixa de seleção, o cartão em linguagem simples ou os argumentos, e a conta com que é executada. **Aprovar todas (k)** executa as k ações selecionadas e recusa as restantes numa só decisão; **Cancelar todas** recusa-as todas; **Uma de cada vez** mostra os cartões individuais habituais. A contagem decrescente mostra o prazo mais próximo; se se esgotar, o aviso oferece **Rever uma de cada vez** para voltar aos cartões individuais, repetir os expirados e decidir sobre os pendentes. Após decidir, cada ação mostra o seu próprio resultado (em execução, aplicada ou recusada), como se tivesse decidido no cartão individual.

Uma instalação também pode permitir **parar** algumas ações em curso, como um plano que processa muitos negócios. O cartão em execução tem então um botão **Parar**, que pede ao conector para parar após o registo atual; o cartão mostra **Paragem pedida** até a ação terminar. Depende do conector parar nesse ponto; o resultado final indica o que foi executado. Um cartão concluído sem resumo próprio do resultado tem o título **Paragem pedida**, nunca **Aplicado**. Se o conector resumir o resultado, o cartão concluído indica até onde chegou (por exemplo, «Parado após 12 de 24») e oferece **Executar os N restantes**, que pede ao assistente para executar os registos que não chegou a processar; essa ação regressa como um novo cartão para aprovação. Se o conector não permitir parar, a ação continua até ao fim e o cartão indica-o no resultado.

A instalação também pode permitir **excluir registos** de uma ação que abranja vários, como um plano que atualiza muitos negócios. O cartão em linguagem simples mostra então uma caixa em cada registo, todas selecionadas, e uma contagem como **3 de 3 selecionados**. Desmarque um registo para o excluir: fica esbatido e mostra **Excluída**; o botão passa a **Aprovar 2 de 3**, que executa a ação apenas para os registos selecionados com um clique. Nada mais muda na ação, e nunca pode adicionar um registo que não tenha visto. Desmarcar todos os registos transforma o botão em **Recusar**. Num cartão agrupado, os registos de cada ação têm as suas próprias caixas; se nenhuma estiver selecionada, essa ação é recusada. Após aprovar, o cartão indica **Aprovados 2 de 3 · 1 excluído** e assinala o registo excluído; o assistente recebe a lista dos que excluiu. No chat de terminal, `/approve` aprova a ação completa.

A instalação também pode fazer com que o assistente **continue por si só** quando decidir um cartão de certas ações, como atualizar um registo externo, para verificar o resultado e continuar sem ter de escrever «feito». Se uma ação aprovada falhar e não tiver premido **Parar**, o assistente inicia automaticamente um turno de recuperação para diagnosticar o erro e o corrigir ou tentar novamente. Um par de segundos depois de aprovar, recusar ou expirar um cartão (ou de receber o resultado se ainda estava em execução), começa um novo turno por si só. Começa com uma linha esbatida **Continuação automática após uma aprovação — não foi escrito por si**; **Mostrar** revela a nota exata que o assistente recebeu. Se aprovar ou recusar com o chat aberto, é transmitido como qualquer resposta; um turno iniciado por expiração aparece ao voltar ao separador ou recarregar. Se houver vários cartões deste tipo pendentes, espera que decida todos e continua uma única vez. Se já houver um turno em execução, espera atrás como um item **continuação automática** na fila sob o editor, que pode remover. Nunca aprova nada em seu nome: qualquer ação posterior que precise de aprovação mostra um novo cartão. Por predefinição, um chat continua sozinho no máximo 10 vezes por hora; se ultrapassar esse limite ou o Fleet reiniciar antes de continuar, uma nota breve indica-o e deve enviar uma mensagem para prosseguir.

Alguns cartões incluem uma caixa que estende a decisão a todas as chamadas posteriores do mesmo tipo nesta conversa; o botão passa a **Aprovar e permitir tudo**. Deixe-a desmarcada salvo se souber exatamente o que fará o resto da conversa. A instalação pode desativar essa caixa em ações que precisem sempre da sua decisão; os cartões não a mostram e cada chamada tem o seu próprio cartão. Também pode ativar **Aprovação automática** na conversa atual através de **Mais opções** (`•••`) na barra do editor, mesmo durante uma resposta. Enquanto está ativo, um ícone de raio permite desativá-lo com um clique. As ações executáveis de conectores e os comandos de shell são executados sem cartão, mas o envio de emails, os cartões de tarefas agendadas e as ações que exigem sempre uma decisão continuam a perguntar. Os cartões não servem para explorar o que uma ação alteraria; peça primeiro ao assistente para descrever a alteração e aprove o cartão quando concordar.

A instalação, não o assistente, determina quais as ferramentas que exigem aprovação e quais apenas informam; convém conhecer a diferença antes de atuar sobre um sistema externo. O administrador pode explicar-lhe.

### Dois cartões de sugestões

**Memórias propostas.** Quando o assistente aprende algo sobre si ou o seu trabalho que vale a pena manter, propõe uma memória em vez de a guardar: **Guardar** ou **Não guardar**. O cartão mostra o destino, **Guardar em: As minhas memórias** ou **Aprendizagens da equipa**; num projeto partilhado com a equipa, Aprendizagens da equipa está pré-selecionado e pode alterá-lo. Consulte [Memórias e projetos](#7-memory-and-projects).

**Sugestões de modelo.** Se uma pergunta exceder o que o modelo atual resolve bem, ou uma resposta tiver dificuldades claras, um cartão oferece **Mudar e tentar novamente**, **Apenas mudar** ou **Descartar**, salvo se já houver um cartão de aprovação de ação pendente. Recusar não custa nada; depois de descartar uma sugestão, não verá outra durante várias mensagens. Se mudar de modelo e depois voltar ao rápido, pode aparecer outra sugestão.

### Cartões interativos

Quando uma resposta visual funciona melhor do que o texto, o assistente pode criar um cartão no momento: um formulário com vários dados, uma lista onde adicionar, duplicar ou remover itens, opções obtidas de um sistema ligado, uma lista de verificações corretas ou pendentes, uma tabela para selecionar linhas, um gráfico ou uma calculadora cujos totais mudam ao escrever. O assistente decide quando um cartão ajuda; também pode pedi-lo diretamente («dê-me um formulário para isto»).

- **Preencha-o e prima o botão.** Os campos com asterisco vermelho são obrigatórios; o cartão indica quantos precisam de correção e leva-o ao primeiro. Uma ligação **Corrigir** junto a uma linha da lista de verificação leva ao campo correspondente. As calculadoras, listas de verificação e cartões de simulação independentes atualizam totais, gráficos e barras de progresso enquanto altera as entradas, sem enviar mensagens. Podem oferecer **Copiado** para copiar um resumo formatado ou **Repor** para repor as predefinições. Ao alterar uma entrada de um cartão editável, também aparece **Repor** no cabeçalho se não houver um botão de reposição utilizável no rodapé; repõe os valores iniciais e apaga o rascunho guardado.
- **As suas respostas tornam-se a mensagem seguinte.** Premir um botão envia o que introduziu como uma mensagem normal, com um resumo do nome do cartão, do botão premido e das respostas; **Mostrar o que foi enviado** revela o texto exato. Se não foi possível enviar, o resumo indica **Não enviado** e o cartão mantém-se aberto para tentar novamente. O cartão em si nunca age: o assistente lê as suas respostas e continua, e qualquer ação posterior que precise de aprovação continua a mostrar o cartão de aprovação habitual.
- **Alguns botões perguntam primeiro.** Um botão que pede confirmação antes de enviar mostra **Sim** e **Voltar** no seu lugar; **Voltar** (ou `Escape`) permite voltar sem enviar.
- **Um cartão enviado fica bloqueado.** Mantém as suas respostas no ecrã. **Editar e reenviar** desbloqueia-o para alterar algo e reenviar; **Cancelar edição** repõe o que enviou.
- **Um cartão espera que a resposta chegue.** Se o assistente ainda estiver a responder ou a ligação tiver sido interrompida ao premir, o cartão mostra **Enviado · … — à espera de chegar ao assistente** e mantém botões e campos desativados para evitar o envio duplicado. **Desbloquear** desbloqueia-as se ainda assim quiser voltar a enviá-las. Se a resposta nunca chegar (a ligação volta e a resposta não está lá, ou a remove da fila sob a caixa de mensagem), o cartão desbloqueia-se sozinho e indica **Não enviado. Tente novamente.**
- **Uma escolha única opcional pode ser anulada.** Uma lista de opções redondas mostra **Limpar escolha** após escolher uma, e uma tabela de seleção de uma única linha mostra **Limpar seleção**, se a pergunta for opcional.
- **Os cartões atualizados substituem os anteriores.** Se o assistente rever as respostas e voltar com uma versão corrigida, o cartão anterior é recolhido numa nota de uma linha (**Mostrar** abre-o), e os problemas são assinalados nos campos do novo.
- **As respostas por enviar são mantidas neste navegador** enquanto desloca a página ou recarrega, até as enviar, durante um máximo de 7 dias e para os 20 cartões editados mais recentemente. Enviar a partir de um cartão não altera o que está a escrever na caixa de mensagem.
- **Não são enviadas respostas demasiado grandes.** Se as respostas, normalmente uma lista longa colada, forem demasiado grandes para uma mensagem, o cartão indica-o e não envia nada. Encurte a lista e volte a premir o botão.
- **Os cartões anteriores a uma compactação são só de leitura.** Após compactar uma conversa (consulte [Conversas longas](#long-conversations)), não pode responder a um cartão da parte resumida, porque o assistente já não tem os detalhes. Peça para voltar a mostrar o cartão.

Os cartões interativos só aparecem no Chat na aplicação Web. As tarefas agendadas nunca os mostram. O chat de terminal nomeia o cartão e encaminha para o chat Web; os clientes de editor ligados por ACP só mostram a chamada original à ferramenta, pelo que deve abrir a conversa na Web para usar o cartão. Uma vista partilhada ou só de leitura mostra as respostas que enviou, mas não o cartão.

## 7. Memórias e projetos

Duas formas de dar ao assistente um contexto que mantém. As memórias são suas e acompanham-no em todas as conversas. Um projeto é partilhado com a sua equipa e orienta todas as conversas que contém.

### Memórias

Uma memória é um facto breve que o assistente recebe no início de cada conversa: uma preferência, uma regra permanente ou algum contexto sobre o seu trabalho. As suas memórias são pessoais; os chats de outras pessoas não as veem. Um projeto acrescenta um segundo tipo, partilhado, explicado abaixo.

Há quatro formas de adicionar memórias. Pode escrever uma no gestor. Pode pedir ao assistente para se lembrar de algo numa conversa, e ele proporá a memória como um cartão para escolher **Guardar** ou **Não guardar**. Pode premir **Guardar** no rodapé de qualquer resposta para manter o que o assistente acabou de dizer, sem escrever um turno de «lembre-se disto». A plataforma também pode propor memórias detetadas após um turno; aparecem como **Proposto** no gestor até as aceitar. Nada é guardado como memória sem a sua autorização, exceto o que escrever por si próprio.

Abra **Memórias** a partir de **Mais opções** (`•••`) no editor de mensagens ou de **Definições → Memórias**. Num chat de projeto, o gestor tem dois separadores: **As minhas memórias** e **Aprendizagens da equipa**. Cada memória indica de onde veio (**Manual**, **Guardado a partir do chat** ou **Extraído automaticamente da conversa**) e oferece estas ações:

| Ação | O que faz |
| --- | --- |
| **Fixar** | É sempre fornecida primeiro ao assistente e fica protegida contra a substituição por uma memória mais recente. Use-o para as regras que nunca devem deixar de se aplicar. |
| **Retirar** | Mantê-la no registo, mas deixar de a fornecer ao assistente. Retirar não significa afirmar que o facto deixou de ser verdadeiro; significa deixar de o citar. É o adequado para qualquer informação desatualizada. |
| **Restaurar** | Voltar a usar uma memória retirada. |
| **Mover para as aprendizagens da equipa** | Move uma memória pessoal para as aprendizagens da equipa de um projeto, para que os chats de todos os membros nesse projeto a recebam. É movida em vez de copiada: a memória deixa de se aplicar às suas conversas fora do projeto e não é fornecida duas vezes ao assistente dentro dele. Se uma regra o deve acompanhar em todo o lado e também servir a equipa, mantenha a memória pessoal e adicione uma aprendizagem da equipa em separado. Se pertencer a vários projetos, escolhe qual. |
| **Eliminar** | Eliminá-la por completo. |

> **As boas memórias são regras, não dados.** «Os nomes dos negócios podem conter erros de escrita intencionais; nunca os corrija» é uma memória. O valor da despesa de hoje não é. As memórias definem como quer que o trabalho seja feito; os dados pertencem às fontes.

### Projetos

Um projeto é um espaço para um conjunto de trabalho relacionado: uma conta, uma campanha ou uma família de relatórios. Contém **instruções** que todas as conversas do projeto seguem e **aprendizagens da equipa**, uma memória partilhada que todos os membros podem ler e ampliar. Todas as conversas do projeto, iniciadas aí ou movidas depois, recebem ambos; assim, a equipa não tem de voltar a explicar-se em cada chat. As conversas de um projeto ficam excluídas da regra de expiração.

Cada conversa de um projeto recebe três camadas de contexto, por esta ordem: as instruções do projeto, as aprendizagens da equipa e as suas próprias memórias. Só o proprietário define as instruções; qualquer membro pode escrever aprendizagens da equipa.

### Criar um

**Novo projeto** (o **+** junto de **Projetos** na barra) pede um nome, instruções opcionais e **Quem pode ver**: **Apenas para si** (projeto privado) ou a sua equipa. Ao partilhá-lo com a equipa, todos veem as instruções, as aprendizagens e os chats partilhados consigo; mas cada chat continua a ser **Apenas para si** até o proprietário o partilhar. Tem de pertencer a uma equipa para essa opção aparecer. As equipas são configuradas em **Definições → Equipa** e um administrador adiciona os membros; se a instalação usar o Auth central para iniciar sessão, o administrador faz ambas as coisas aí. Ao criar um projeto, abre-se a respetiva página principal. As mesmas opções ficam disponíveis depois em **Definições do projeto** (a engrenagem da página do projeto ou o menu na barra), que só o proprietário pode abrir.

O proprietário pode transferir o projeto para outro membro com **Transferir…**, para que continue a existir quando deixar de participar; a transferência fica disponível depois de partilhar o projeto. Continua a usar o projeto como membro da equipa; se tiver saído dessa equipa, a transferência também termina o acesso e os seus chats voltam a ser temporários. O painel de transferência indica qual o caso aplicável. Eliminar um projeto pede confirmação e enumera o que é eliminado com ele: as aprendizagens da equipa e quantos chats de outras pessoas saem do projeto e voltam a ser temporários; oferece **Exportar primeiro**. Mudar um projeto partilhado para **Apenas para si** mostra, antes de guardar, quantos chats passam a Apenas para si e quantos chats de colegas regressam às suas conversas sem projeto. Nenhuma das duas ações elimina conversas; os chats ficam sempre com o proprietário.

### A página do projeto

A barra mostra todos os projetos visíveis: primeiro os fixados e depois os restantes segundo a última criação ou edição (nome, definições ou partilha); conversar num projeto não o move para cima. Se a lista exceder o espaço disponível, a secção **Projetos** desloca-se de forma independente, tal como **Chats** abaixo.

Abra um projeto na barra para aceder à página principal. Junto ao título, uma etiqueta indica quem o pode ver: **Apenas para si** ou **Partilhado com** a sua equipa; se estiver partilhado, explica o que a equipa vê. Até partilhar um chat do projeto, um breve **cartão de primeiros passos** explica os passos seguintes (partilhar o projeto, adicionar instruções, partilhar um chat), cada um com um botão para o fazer. **×** oculta-o por agora; num projeto pessoal, **Manter privado** oculta-o definitivamente. Depois, de cima para baixo:

| Área | O que contém |
| --- | --- |
| **Os seus chats** | As suas conversas deste projeto, com o número das partilhadas com a equipa e uma pesquisa limitada ao projeto. Cada linha tem uma etiqueta, **Apenas para si** ou o nome da equipa, e uma marca **Em direto** se o modo **Chat colaborativo** estiver ativo. Altere-a para partilhar ou deixar de partilhar o chat e os ficheiros; **Mais opções de partilha…** abre a janela de partilha. Num projeto partilhado, **Novo chat** pergunta se o novo chat começa como **Apenas para si** ou partilhado com a equipa. |
| **Partilhado pela sua equipa** | Conversas que os colegas partilharam neste projeto, com o proprietário e a data. Abra um chat partilhado só de leitura para o ler ou ramificar, ou um marcado **Em direto · Colaborativo** para participar diretamente na conversa em direto; consulte [Partilhar com a sua equipa](#sharing-with-your-team). Uma linha que já tenha ramificado indica **Criou uma ramificação deste chat** e continua a abrir o chat atual do proprietário. |
| **Instruções** | As instruções permanentes. O proprietário pode editá-las. |
| **Aprendizagens da equipa** | Uma linha por aprendizagem, com quem a escreveu e quando. **Nova aprendizagem da equipa** adiciona uma. O menu da linha contém **Fixar**, **Editar**, **Retirar** ou **Restaurar**, e **Eliminar**. A mesma lista é o separador Aprendizagens da equipa do gestor de memórias, para que a possa manter sem sair de uma conversa. |
| **Fontes** | Ficheiros agrupados por chat. Num projeto partilhado aparece primeiro **Da sua equipa**, com os ficheiros que os colegas partilharam e que podem ser descarregados; depois, **Os seus chats**. Cada grupo seu indica quantos ficheiros contém e, se o chat estiver partilhado com a equipa, quantos são partilhados; o interruptor de um ficheiro altera a partilha e a seta descarrega-o. Os ficheiros que carregou e as suas competências pessoais nunca aparecem aqui, nem os ficheiros ocultos ou internos (cujo nome começa por um ponto), salvo se o assistente lhe tiver apresentado algum numa resposta. As cópias provenientes de uma ramificação têm a etiqueta **A sua cópia**. Cada secção lista os 50 chats com ficheiros cuja atividade é mais recente; se houver mais, o painel indica que só mostra os ficheiros mais recentes. |

As permissões numa frase: **os membros gerem as suas próprias aprendizagens; o proprietário gere-as todas.** Retirar é a opção habitual quando uma aprendizagem deixa de ser verdadeira. Deixa de ser fornecida ao assistente, mas mantém-se o registo do que foi aprendido e de quem o escreveu.

> **O que deve ser guardado como aprendizagem da equipa.** O mesmo critério das memórias pessoais, aplicado à equipa: regras e contexto, não dados. «O cliente quer que os nomes dos negócios sejam apresentados exatamente como aparecem no relatório de origem» é uma aprendizagem. Os números desta semana não são. Se todos repetirem uma aprendizagem nos chats do projeto, convém deixá-la por escrito.

Pode mover qualquer conversa para um projeto com **Mover para um projeto** e retirá-la com **Remover do projeto**, que confirma que voltará a ser temporária e oferece **Fixar e remover** para evitar uma expiração acidental. Se um projeto trouxer mais estrutura do que precisa, as **etiquetas** são uma opção mais simples: etiquete conversas no respetivo menu e filtre a barra por etiqueta. As etiquetas organizam; não contêm instruções nem aprendizagens.

## 8. Manter, organizar e partilhar conversas

Cada conversa da barra tem um menu no botão `⋮` que aparece ao passar o cursor. Estas são todas as opções.

| Opção | O que faz |
| --- | --- |
| **Fixar** | Mantê-la indefinidamente e apresentá-la em **Fixados**. Fixe qualquer conversa que não queira perder. |
| **Mudar nome** | As conversas recebem um título a partir da primeira troca de mensagens. Mude o nome das que mantiver para que a barra seja uma lista de trabalhos, não de primeiras frases. |
| **Mover para um projeto** | Guardá-la num projeto. A conversa recebe o contexto desse projeto a partir do turno seguinte. |
| **Etiquetas** | Adicionar ou remover etiquetas. As etiquetas também servem de filtros na barra. |
| **Descarregar chat** | Exporte a conversa num de três formatos: **Página web**, que abre em qualquer navegador, tem o aspeto do chat e permite imprimir para PDF; **Documento de texto**, para colar em email, Word ou Docs; ou **Dados em bruto**, o registo completo para programadores. **Incluir o trabalho do agente** acrescenta chamadas de ferramentas, resultados e raciocínio; está desativado por predefinição para que um chat longo seja descarregado como conversa, sem todos os detalhes de execução. |
| **Criar tarefa recorrente…** | Peça ao assistente para transformar esta conversa numa tarefa agendada. Consulte [Do chat para uma tarefa](#10-from-chat-to-a-task). |
| **Guardar como fluxo de trabalho** | Transforme toda a conversa num modelo reutilizável de fluxo de trabalho na biblioteca de prompts ou numa **Competência do agente (`/skill-name`)** pessoal. Consulte [Do chat para uma tarefa](#10-from-chat-to-a-task). |
| **Partilhar…** | Abre a janela de partilha: primeiro com a equipa e depois **Partilhar fora da sua equipa** (uma ligação pública). Consulte [Partilhar com a sua equipa](#sharing-with-your-team). |
| **Selecionar** | Entre no modo de seleção para fixar, etiquetar ou eliminar várias conversas de uma vez. Se a seleção incluir chats partilhados com a equipa, a confirmação de eliminação indica quantos são e que a equipa perderá esses chats e os ficheiros partilhados; quem os ramificou mantém as cópias. |
| **Arquivar** | Pô-la de lado sem a eliminar. As conversas arquivadas nunca expiram e podem ser recuperadas a partir do grupo **Arquivados**. Arquivar um chat partilhado com a equipa deixa de o partilhar; primeiro pede confirmação e indica quantos ficheiros são partilhados. Ao desarquivá-lo, regressa como **Apenas para si**. Um chat arquivado não pode ser partilhado com a equipa; primeiro tem de o desarquivar. |
| **Eliminar** | Eliminar a conversa e tudo o que produziu. É pedida confirmação e não pode ser anulado. Se o chat estiver partilhado com a equipa, a confirmação explica o que perderá; os colegas que o ramificaram mantêm as cópias. |

> **O que expira e quando.** Uma conversa não fixada, fora de um projeto, não arquivada e não partilhada é eliminada após um período de inatividade: 14 dias, salvo se o operador tiver definido outro prazo. Também existe um limite por pessoa de conversas não fixadas; numa conta muito ativa, as mais antigas podem desaparecer antes de terminar o prazo. Fixar, arquivar, mover para um projeto ou partilhar uma conversa exclui-a dos dois limites.

### Ordenar os seus chats

Os chats fixados e os de um projeto começam ordenados do mais recente para o mais antigo. Para lhes dar a sua própria ordem:

- **Chats fixados:** prima **Reordenar** no cabeçalho **Fixados**.
- **Chats de um projeto:** abra o menu `⋮` do projeto e escolha **Reordenar chats**.

Cada chat mostra então um par de setas. Arraste um chat para onde quiser ou prima as setas para subir e descer, que também funcionam com o teclado e em telefones. Cada movimento é guardado imediatamente na conta, pelo que a ordem é a mesma em todos os dispositivos onde inicia sessão. Prima **Concluído** (ou `Esc`) para voltar às linhas normais.

Um chat que fixa ou adiciona ao projeto pela primeira vez aparece no topo, acima dos ordenados, até o mover; se o desafixar ou retirar e depois o devolver, recupera o lugar anterior. **Reordenar** está disponível para um máximo de 500 chats de cada vez e não para contas só de leitura, que não podem guardar uma ordem. Num projeto, ordena os seus próprios chats; cada colega ordena os seus.

Os chats **Temporários** usam uma ordenação automática no menu do cabeçalho: **Atividade recente** (predefinição), **Mais recentes primeiro** (por data de início) ou **Título A–Z**. A escolha é guardada neste dispositivo. Os chats temporários expiram se não forem usados, pelo que são ordenados automaticamente; para dar a um deles um lugar próprio, fixe-o ou mova-o para um projeto.

### Na transcrição

**Editar mensagem** numa das suas mensagens permite alterá-la e reenviar a partir desse ponto. No rodapé de qualquer resposta aparecem **copiar** e **ramificar**; sob a última também aparecem **regenerar** (voltar a perguntar, opcionalmente com outro modelo) e **Tentar novamente com** o modelo mais potente (perguntar com ele e mantê-lo no resto do chat). **Criar ramificação** inicia uma conversa nova e independente com tudo o que ocorreu até essa resposta, para explorar uma alternativa sem alterar a original. Ramifique se quiser manter os dois caminhos; edite se a versão anterior estava simplesmente errada. As duas ações de guardar do rodapé, **Guardar como fluxo de trabalho** e **Guardar**, são explicadas em [Do chat para uma tarefa](#10-from-chat-to-a-task) e [Memórias e projetos](#7-memory-and-projects).

### Partilhar com a sua equipa

Partilhar uma conversa com a equipa permite divulgar um bom trabalho. Um chat só é partilhado com uma equipa quando está num projeto partilhado com essa equipa **e** o proprietário o partilha; partilhar o projeto nunca partilha os seus chats por si só.

**A janela de partilha** (**Partilhar este chat** dentro de **Mais opções** `•••` no editor, a etiqueta de visibilidade no cabeçalho ou **Partilhar…** no menu do chat) mostra sempre primeiro a equipa e oferece um botão que trata de tudo conforme a situação:

| Situação | O botão |
| --- | --- |
| O chat não pertence a nenhum projeto | **Mover e partilhar** para um projeto já partilhado com a equipa, ou **Criar projeto partilhado** se ainda não existir nenhum; o chat é movido para aí e partilhado. |
| O chat pertence a um projeto pessoal | **Partilhar primeiro o projeto** abre a página do projeto com a confirmação visível; depois, o cartão de primeiros passos permite partilhar o chat com um clique. |
| O chat pertence a um projeto partilhado com a equipa | **Partilhar com a sua equipa**. **Inclui N ficheiros · Escolher…** permite desmarcar ficheiros antes de os partilhar. |
| O chat está partilhado | **Copiar ligação para a sua equipa**, além de **Deixar de partilhar**, que pede confirmação e indica quantos ficheiros deixarão de ser partilhados quando os consegue contar. |
| Não pertence a uma equipa | Ainda não há com quem partilhar; a janela explica como aderir a uma equipa. |

**O que é partilhado.** As suas mensagens, as respostas do assistente e os **ficheiros que o assistente apresentou nas respostas** (as ligações para ficheiros do chat), incluindo os que apresentar depois, porque um chat partilhado se mantém atualizado. Os ficheiros que desmarcar continuam sem ser partilhados, mesmo que desative e reative a partilha ou arquive e desarquive o chat. Os ficheiros que carregou nunca são partilhados; também não são partilhados os ficheiros que o assistente escreveu sem os apresentar. São excluídas as chamadas de ferramentas, os respetivos resultados e o raciocínio. No seu próprio chat partilhado, cada ligação de ficheiro indica **Partilhado** ou **Não partilhado**; clique nela para gerir os ficheiros em **Fontes** do projeto.

É partilhada **em modo só de leitura**: cada conversa tem um único proprietário e o que um colega fizer não altera a sua. Os colegas veem as novas mensagens enquanto continua a trabalhar.

**A ligação para a equipa** só abre para membros da equipa com sessão iniciada, na vista só de leitura. Qualquer outra pessoa só vê que o chat está partilhado com a equipa; um colega sem sessão iniciada passa pelo início de sessão e chega diretamente ao chat. Quando um chat deixa de ser partilhado, a ligação indica-o.

**Quando termina a partilha.** Uma conversa partilhada com a equipa tem sempre um lugar: o projeto onde está. Movê-la para outro projeto partilhado com a mesma equipa mantém a partilha. Movê-la para qualquer outro local, retirá-la do projeto, arquivá-la ou eliminá-la termina a partilha; cada ação pede confirmação e indica quantos ficheiros partilhados serão afetados. Tornar o projeto pessoal, eliminá-lo ou sair da equipa também termina a partilha. Mover um chat para um projeto partilhado nunca o partilha por si só; a confirmação propõe **Partilhar com** a sua equipa.

**Partilhar fora da sua equipa** é a ligação pública independente: qualquer pessoa com o URL pode ler a transcrição, mas nunca os ficheiros.

**Ler o chat de um colega.** Abra-o em **Partilhado pela sua equipa** na página do projeto ou através de uma ligação que lhe tenham enviado. Vê a transcrição com o nome do proprietário; os ficheiros partilhados são descarregados na versão atual e os que não partilhou aparecem como nomes bloqueados. No lugar do editor aparece uma única ação: **Criar ramificação para continuar no seu próprio chat**. Cria uma conversa privada sua no mesmo projeto, com todo o conteúdo da transcrição, e **os ficheiros partilhados são incluídos como cópias suas**; o assistente da sua ramificação pode usá-los. As suas cópias nunca mudam depois, mesmo que o original deixe de ser partilhado ou seja eliminado. Ao abrir um chat que já ramificou, um aviso liga à sua cópia e indica se o proprietário acrescentou mensagens depois; **Criar outra ramificação** inicia uma nova ramificação da versão atual.

**Modo de chat colaborativo.** Para as equipas que querem trabalhar juntas na mesma conversa em direto, a janela de partilha inclui uma secção **Modo colaborativo** (**Ativar** / **Desativar**). Os novos chats começam como **Apenas para si** por predefinição, salvo se um administrador tiver ativado **Chat colaborativo de equipa por predefinição** em **Definições → Administração → Funcionalidades** (`FLEET_TEAM_CHATS_SHARED_BY_DEFAULT`). Nesse caso, os novos chats sem projeto ou em projetos de equipa, fora do modo restrito e criados por membros da equipa, começam automaticamente em **Modo colaborativo**. Os chats criados num projeto pessoal mantêm-se privados até se ativar o modo Chat colaborativo na janela Partilhar. Quando o modo de chat colaborativo está ativo:

- Os colegas e as restantes pessoas adicionadas ao chat veem-no em **Chats de equipa** na barra com uma etiqueta **Em direto**, podem abri-lo diretamente na vista de chat e enviar mensagens para a conversa partilhada.
- Cada mensagem mostra o email do remetente acima do balão, e cada turno é executado com **a própria conta do remetente**: usa o email, as memórias pessoais, as competências, as contas de conectores e os cartões de aprovação do remetente. Como as chamadas de ferramentas, o raciocínio e o resumo de tokens e custo pertencem à pessoa cujas credenciais executaram o turno, ativar **Mostrar detalhes** mostra **Detalhes ocultos nos turnos de outros utilizadores** nos turnos iniciados por outra pessoa.
- Por predefinição, toda a equipa ou espaço de trabalho do proprietário pode participar. Em **Pessoas que podem participar** da janela de partilha, o proprietário pode remover pessoas com `×`, restaurá-las com `+` ou convidar alguém com **Adicionar pessoa por email**.

### Enquanto um turno está em execução

**Parar** para o turno atual; a resposta parcial fica na transcrição, marcada como **Turno interrompido.** e com **Tentar novamente** no último turno, mesmo depois de recarregar. Os turnos que a plataforma termina antecipadamente são marcados da mesma forma: por atingir o limite por turno (4 horas por predefinição), o limite de custo ou tokens, ou por um reinício do servidor, que também inclui uma nota explicativa. Escrever e enviar durante um turno não o interrompe: a mensagem espera numa fila sob o editor, com **Enviar agora** para a adiantar e um controlo para a remover. As mensagens na fila são executadas por ordem quando o turno atual termina, cada uma como o seu próprio turno visível; a fila é mantida ao recarregar ou mudar de chat.

### Conversas longas

À medida que a conversa cresce, **Resumir mensagens anteriores** em **Mais opções** (`•••`) mostra quanto espaço do chat está ocupado como percentagem da janela de contexto do modelo. Com **Mostrar detalhes** ativo, uma linha de totais sobre o editor mostra a mesma percentagem junto ao custo acumulado da conversa. Quando a conversa fica cheia, um aviso indica-o e o assistente começa a demorar e a custar mais por turno. **Resumir mensagens anteriores**, em **Mais opções** ou no aviso, substitui os turnos antigos por um resumo breve para a conversa voltar a caber confortavelmente; a transcrição mantém o histórico e só é reduzida a vista de trabalho do assistente. Se a conversa mudar enquanto o resumo é escrito, por exemplo por uma resposta de outro separador ou uma nova tentativa, o resumo não é guardado e o chat indica *«A conversa mudou enquanto era resumida, pelo que o resumo não foi guardado. Volte a resumi-la».* Volte a resumir para incluir o estado atual. Não precisa de vigiar: por predefinição, quando um pedido atinge cerca de 90% do limite do modelo, a plataforma resume por si só a parte mais antiga dessa vista, entre turnos ou a meio de um turno longo que continua a obter dados; uma nota na resposta indica-o. Se um modelo continuar a recusar um pedido por ser demasiado longo, a plataforma resume e tenta novamente por si só em vez de dar o turno como falhado. Se o tema mudar por completo, começar outra conversa é mais barato e claro do que compactar a anterior.

## 9. A biblioteca de prompts

A biblioteca é onde se guarda um prompt concluído. Os prompts são criados nos chats, executados nas tarefas e guardados na biblioteca, o local consultado por ambos.

Existe uma única biblioteca, acessível a partir de três locais: **Biblioteca de instruções** dentro de **Mais opções** (`•••`) no editor de mensagens, **Definições → Prompts** e o campo de prompt do formulário de tarefas na página Tarefas em segundo plano. Todos abrem a mesma lista, pelo que um prompt guardado a partir de uma conversa é, palavra por palavra, o que uma tarefa pode executar. Contém dois tipos de entrada:

| Tipo | O que é |
| --- | --- |
| Instruções da instalação | Incluídos na instalação e atualizados a partir de fora da aplicação. Só de leitura, marcado como **Git** na lista. Use-os tal como estão ou insira um e adapte-o para criar o seu próprio prompt. |
| Prompts do espaço de trabalho | Criados pela sua equipa. Cada um é **Privado**, visível apenas para o autor, ou **Espaço de trabalho**, visível em toda a instalação. Só o autor ou um administrador os pode editar ou eliminar. |

### Usar um prompt

Abra a biblioteca, pesquise ou percorra a lista e selecione uma entrada para a ler por completo. **Usar instrução** insere-o no rascunho; envie-o tal como está ou acrescente conteúdo primeiro. Na página Tarefas em segundo plano, a mesma ação preenche as instruções da tarefa e usa o nome do prompt como título inicial.

Alguns prompts da instalação são **formulários** e aparecem assinalados como **Formulário** na lista. Ao selecionar um, surgem as respetivas perguntas em vez do texto. Preencha os campos assinalados como `*`; alguns formulários agrupam definições adicionais em **Mais opções**. **Usar instrução** só fica disponível quando todos os campos obrigatórios tiverem uma resposta, e a **Pré-visualização das instruções** por baixo do formulário mostra exatamente o que será inserido. Se deixar vazio um campo opcional de texto, número ou data, este é omitido do prompt, para que não tenha de procurar marcadores por preencher depois. O prompt concluído é acrescentado ao rascunho como qualquer outro, pronto para ler, alterar ou anexar ficheiros antes de o enviar. Se preferir preenchê-lo à mão, **Inserir instrução sem processamento** insere o modelo com os respetivos `{placeholders}`.

### Criar e editar

**Nova instrução** abre um formulário com um nome, uma descrição opcional («ajuda os colegas a encontrá-lo») e o texto do prompt. Se já tiver texto no editor, este é copiado para o formulário. **Partilhar com este espaço de trabalho** determina se será privado ou do espaço de trabalho; deixe a opção desmarcada até o prompt ter sido revisto e ser a versão acordada pela equipa. Ao selecionar uma entrada sua, surgem **Editar**, **Duplicar** e **Eliminar**; as entradas da instalação e as partilhadas por colegas oferecem **Clonar e editar** para poder personalizar uma cópia sua.

Uma convenção que convém adotar desde o início. **Uma versão da equipa por relatório**: quando um prompt é partilhado, convém eliminar os rascunhos privados que lhe deram origem; a tarefa que o executa deve ser criada por quem a vai manter, pois a linha só é visível para o criador e os administradores.

### Cópias de segurança

**Criar cópia de segurança de JSON** descarrega a biblioteca tal como a vê, incluindo os prompts da instalação, como um ficheiro simples. Guarde de vez em quando uma cópia na unidade partilhada da equipa; contém todo o seu trabalho com prompts num único ficheiro.

> **Porque é a biblioteca que define o que foi acordado.** Uma tarefa executa o que lhe foi indicado ao ser criada. Se o relatório precisar de uma correção, corrija o prompt da biblioteca e volte a selecioná-lo na tarefa para que esta use a nova versão. Se alterar as instruções dentro de uma tarefa, cria uma variante que ninguém mais pode ver e a cópia da biblioteca deixa de refletir a realidade sem que ninguém se aperceba. As outras definições da tarefa —o horário, os destinatários e os conectores que pode usar— têm campos próprios no formulário, e inserir um prompt não as altera.

## 10. Do chat para uma tarefa

Tem uma conversa que vale a pena guardar. Dois passos transformam-no em algo que se executa por si só: extrair um prompt do chat e levá-lo para uma tarefa. Há várias formas de dar cada passo, e a mais adequada depende do que pretende guardar: o relatório exato ou o método usado para o elaborar.

### Extrair o prompt do chat

**Peça ao assistente para o redigir.** A opção para um relatório que queira reproduzir exatamente da mesma forma em cada execução. O assistente sabe o que acabou de criar, e pode pedir-lhe para corrigir o rascunho na mesma conversa antes de guardar o que quer que seja. Peça algo como:

> Escreva-me um prompt que possa guardar na biblioteca de prompts e que reproduza exatamente este relatório numa única execução. Fixe esta estrutura como modelo: as mesmas secções na mesma ordem, as mesmas tabelas e a mesma formatação, alterando apenas os dados. Tem de funcionar num chat completamente novo, sem qualquer outro contexto.

Leia o rascunho, peça alterações e cole-o em **Nova instrução**.

**Guardar como fluxo de trabalho.** A opção adequada para um método que pretenda reutilizar com outros dados de entrada. A partir do menu `⋮` da conversa ou do rodapé de qualquer resposta, a plataforma lê toda a conversa —incluindo o que o assistente fez e os erros que cometeu pelo caminho— e transforma-a num modelo de fluxo de trabalho: um objetivo, as entradas como marcadores entre parênteses retos, os passos com a ferramenta usada em cada um, o resultado e as notas. Os nomes, as datas e os alvos desta execução são generalizados; o método mantém-se específico. No diálogo para guardar, escolha **Destino**: guarde-o na **Biblioteca de instruções** (privado por predefinição, ou **Partilhar com a área de trabalho**) ou diretamente como uma **Competência do agente (`/skill-name`)** (pessoal por predefinição, ou publicada em **Competências da área de trabalho** para que os colegas possam clicar em **Adicionar às minhas competências**).

Guardar como fluxo de trabalho é adequado para aquela tarde que dedicou a conseguir que o assistente caracterizasse um novo conjunto de dados, calculasse uma referência e redigisse uma nota, porque no próximo trimestre pretende aplicar esse procedimento a outro cliente. Não é a opção adequada para um relatório diário fixo em que pretende responder à mesma pergunta da mesma forma todas as manhãs; para isso, use a primeira opção.

**Escreva-o.** Adequado para pedidos simples. A lista de verificação seguinte continua a aplicar-se.

Seja qual for a opção, reveja o rascunho antes de o guardar. Para um prompt de relatório: nomeie todas as fontes, especifique os identificadores, fixe a disposição e a ordem das secções e inclua a regra de assinalar qualquer elemento indisponível e continuar com o restante. Para um modelo de fluxo de trabalho: os marcadores abrangem tudo o que muda entre execuções, e nenhum passo diz «analise os dados» quando na conversa foi feito algo específico. Se o rascunho mencionar destinatários ou uma hora de execução, continuará a funcionar, mas é melhor definir esses detalhes na própria tarefa, onde podem ser alterados sem mexer no prompt. Depois, **teste-o**: abra um novo chat, insira o prompt guardado a partir da biblioteca e envie-o. Deverá obter o mesmo relatório com os dados atuais. Se for diferente, volte à conversa em que o criou, explique ao assistente o que mudou e atualize o prompt guardado.

### Levar o prompt para uma tarefa

**A partir da biblioteca, na página Tarefas em segundo plano.** A opção recomendada. Na página Tarefas em segundo plano, **Nova tarefa** abre o formulário de tarefas; insira o prompt da biblioteca e defina o horário, o modelo e os destinatários. O prompt tem um único local de referência e a tarefa utiliza-o. O guia de Tarefas em segundo plano explica o formulário campo a campo.

**Criar tarefa recorrente… a partir do chat.** A opção direta. A partir do menu da conversa, o assistente propõe uma tarefa baseada nela e prepara um cartão de agendamento. **Editar** abre o nome, o horário e o prompt completo; **Aprovar e agendar** (ou **Aprovar com alterações**, se tiver editado) cria a tarefa; **Cancelar** não cria nada. O nome que confirmar será o título da tarefa no quadro. O cartão também mostra o modelo que executará a tarefa: o modelo para tarefas do espaço de trabalho (por predefinição, o modelo mais potente), em vez do que estava a ser usado neste chat.

A diferença é clara: o prompt é gerado a partir da conversa em vez de ser retirado da biblioteca, pelo que deve revê-lo em **Editar** com a mesma lista de verificação. Considere guardar esse prompt revisto também na biblioteca, para ter um local onde aplicar futuras correções.

Em ambos os casos, a tarefa surge no seu próprio quadro na página Tarefas em segundo plano. Os colegas recebem os e-mails, mas, a menos que sejam administradores, não veem a linha da tarefa; por isso, a versão de um relatório para a equipa deve ser criada por quem a vai manter.

> **Há uma regra que se aplica a todas as opções.** Uma tarefa mantém o prompt com que foi criada. Uma alteração na biblioteca só chega a uma tarefa quando o prompt é novamente selecionado nessa tarefa. Depois de alterar um prompt da biblioteca, abra as tarefas que o usam, volte a inserir o prompt e prima **Executar agora** uma vez para confirmar.

A partir daqui, continue com o **Guia de tarefas em segundo plano**: estados de execução, registos e o que fazer quando uma execução precisa de atenção.

## 11. Quando um turno falha

A maioria dos problemas manifesta-se na transcrição. Procure na tabela seguinte o que está a ver.

| O que vê | O que fazer |
| --- | --- |
| **A tentar novamente** | Uma ligação ou um serviço falhou momentaneamente e o turno volta a tentar por si só após uma breve contagem decrescente. Aguarde. Normalmente resolve-se por si só. |
| Não aparece nada durante algum tempo | Um modelo que raciocina antes de escrever pode permanecer em silêncio durante um minuto ou mais, e isso não é uma falha. Por predefinição, a plataforma dá ao modelo cerca de um minuto e quinze segundos para começar. Se ainda não tiver começado, verá **A tentar novamente** enquanto a plataforma volta a tentar automaticamente, e depois a sua instalação pode experimentar um modelo de reserva, que normalmente responde sem que tenha de fazer mais nada. Se a última tentativa também não começar, um cartão indica que o modelo não começou a responder. Volte a tentar a partir do cartão ou escolha outro modelo. |
| **Falha no turno** | O turno não foi concluído. O aviso explica o motivo quando possível. No último turno, **Tentar novamente** reenvia a sua última mensagem. Se falhar da mesma forma duas vezes, altere algo: o modelo, o pedido ou o anexo. |
| **Sem créditos** | A chave de API da instalação ficou sem créditos ou atingiu o limite de despesa. Carregue o saldo da chave de API, ou use **Contactar licensing@elcanotek.com** no cartão para adicionar créditos, e prima **Tentar novamente**. |
| A resposta parece parar | Se o telemóvel bloquear ou o portátil entrar em suspensão, o ecrã pode perder a ligação enquanto o assistente continua a trabalhar. Aguarde alguns segundos depois de recuperar a ligação: a página verifica o estado automaticamente e retoma a transmissão em direto ou apresenta a resposta concluída. Se o turno já tiver falhado durante a sua ausência, a página explica o que aconteceu e oferece **Tentar novamente**, ou **Escolher outro modelo** se era disso que o turno precisava. Após uma interrupção prolongada, estas verificações tornam-se menos frequentes; voltar ao separador provoca uma imediatamente. Recarregue apenas se continuar bloqueado depois disso. O trabalho não se perdeu em nenhum dos casos. |
| Um aviso na parte superior: **… foi atualizado** | Foi publicada uma nova versão da aplicação desde que esta página foi carregada. Prima **Recarregar** quando lhe convier ou descarte o aviso com **×**. Nunca recarrega a página por si só. O mesmo aviso surge em todas as páginas da aplicação e também quando esta é adicionada ao ecrã principal de um iPhone ou iPad, onde não há um botão próprio para recarregar. |
| Uma página que diz **Ocorreu um erro** | Ocorreu um erro na página. Prima **Recarregar** ou **Ir para a página inicial**. Uma página que ficou aberta durante uma atualização normalmente recarrega uma vez por si só para usar a nova versão. Se essa mesma página voltar a falhar logo a seguir, aguarda a sua intervenção. |
| Modelo indisponível | O aviso oferece **Escolher outro modelo**. Escolha um e volte a enviar; a conversa mantém o histórico. |
| Ficheiro recusado | Se um anexo ultrapassar o limite de tamanho, é recusado ao selecioná-lo e o limite é apresentado. Divida o ficheiro ou limite-o às colunas e datas de que precisa. |
| Conector indisponível | O seletor mostra **Indisponível** junto a um conector, ou o registo de execução mostra uma chamada que devolveu um erro. Verifique em **Definições → Ligações** se o início de sessão caducou; caso contrário, informe o administrador e junte uma exportação de **Descarregar chat** no formato **Dados em bruto**: inclui sempre o registo completo, pelo que não apresenta opções para assinalar. |
| A conversa está cheia | Um aviso indica a percentagem. **Resumir mensagens anteriores**, ou inicie uma nova se tiver mudado de assunto. |
| A resposta está errada | Abra os indicadores do registo de execução e leia o que cada fonte devolveu realmente. Depois, peça: «mostre-me as linhas de onde vem esse valor». A maioria das respostas erradas deve-se a uma fonte errada ou a um identificador mal interpretado; ambos são visíveis no registo de execução. |

Tudo o que não conseguir resolver a partir da transcrição deve ser comunicado ao administrador. A forma mais rápida de o enviar é **Descarregar chat** no menu `⋮` da conversa e escolher **Dados em bruto**: esse formato inclui sempre o registo completo, incluindo o que cada ferramenta devolveu, pelo que não é preciso voltar a descrever nada nem é possível esquecer uma opção. (**Incluir o trabalho do agente** surge nos dois formatos legíveis, que o excluem por predefinição; Dados em bruto não apresenta a caixa de verificação porque nunca omite nada.)

## 12. Práticas de trabalho

Sete hábitos para que uma instalação partilhada seja compreensível e os seus relatórios fiáveis.

| Hábito | Motivo |
| --- | --- |
| Dê nomes úteis às conversas | Mude o nome de tudo o que guardar para que o título descreva o trabalho realizado. Os títulos servem para pesquisar, partilhar e passar o trabalho a um colega quando é necessária uma segunda opinião. |
| Fixe o que importa | As conversas não fixadas expiram. Fixe, guarde num projeto ou arquive tudo o que não queira perder. |
| Escolha o modelo adequado ao trabalho | Entre os modelos recomendados, use o rápido para obter dados, fazer verificações e formatar; use o mais potente para avaliar e redigir. Mude de modelo durante a conversa quando o pedido mudar. |
| Especifique fontes e identificadores | Indique que relatório, que remetente e que negócio. O registo de execução só pode mostrar o que pediu. |
| Leia o cartão antes de aprovar | Um cartão é a forma de a plataforma explicar o que vai acontecer. Cancelar nunca tem custos. |
| Guarde cada prompt num único local | Crie-o no chat, guarde-o na biblioteca e execute-o a partir de uma tarefa. Corrija-o na biblioteca e volte a selecioná-lo na tarefa. |
| Registe as aprendizagens no projeto | Uma regra que a equipa repete constantemente no chat deve ser guardada nas aprendizagens da equipa do projeto, onde todas as conversas a recebem sem que ninguém tenha de voltar a escrevê-la. |

## 13. Atalhos de teclado

Tudo o que se descreve aqui também pode ser feito com o rato. Prima `?` em qualquer local fora de um campo de texto para ver esta mesma lista na aplicação. `⌘` no Mac equivale a `Ctrl` no Windows e no Linux.

| Atalho | Ação |
| --- | --- |
| `⌘ K` | Abrir a pesquisa |
| `⌘ ⇧ O` | Iniciar uma nova conversa |
| `⇧ Esc` | Colocar o foco no editor |
| `Enter` / `Shift Enter` | Enviar / adicionar uma linha (ou o inverso, se **Enviar com Enter** estiver desativado) |
| `J` / `K` | Mover o foco para baixo / cima na lista de conversas |
| `Enter` | Abrir a conversa focada |
| `P` | Fixar ou desafixar a conversa com o foco |
| `A` | Arquivar a conversa focada |
| `R` | Mudar o nome da conversa focada |
| `#` | Eliminar a conversa em foco (abre a confirmação; nunca elimina sem aviso) |
| `Y` | Copiar a última resposta |
| `E` | Editar a sua última mensagem |
| `D` | Ativar ou desativar [vista de painel](#dashboard-view) (`Esc` permite sair) |
| `?` | Mostrar a ajuda dos atalhos |
| `Esc` | Fechar a pesquisa, a ajuda sobreposta ou a barra lateral |

Os atalhos de uma só letra nunca são ativados enquanto escreve num campo de texto, pelo que não podem interromper uma mensagem.

Três combinações que talvez esperasse são deixadas livres de propósito para que o navegador as mantenha: `⌘F` continua a pesquisar na página (a forma natural de pesquisar na transcrição que está a ver), `⌘N` continua a abrir uma nova janela e `⌘J` continua a abrir as transferências. Por isso, iniciar uma nova conversa e colocar o foco no editor usam as outras duas combinações indicadas acima.
