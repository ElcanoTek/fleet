# Chat

Chat es el espacio de trabajo de la plataforma: donde preguntas sobre tus datos, los analizas con el asistente, creas informes y revisas los resultados. Esta guía explica la pantalla y sus controles, cómo obtener respuestas fiables, a qué puede acceder el asistente y qué te preguntará antes de actuar, y cómo llevar el trabajo que quieres repetir desde una conversación a la biblioteca de prompts y a una programación.

## 1. Qué es Chat

### Chat de terminal

En el servidor, `fleet chat` abre el chat de terminal. Inicia sesión con tu propia clave de API, que un administrador crea con `fleet sched apikey create <name> --type user --user you@example.com`; guárdala en `~/.config/fleet/api-key`. Los nuevos hilos usan de forma predeterminada el modelo del espacio de trabajo; `--model` o `/model` selecciona otro modelo. `--message "..."` y `--no-tui` permiten usar scripts y entradas canalizadas. En el modo de ejecución única, stdout se almacena hasta que termina el turno para que contenga la respuesta final y no borradores sustituidos; los avisos de progreso y aprobación van a stderr. El modo de ejecución única escribe el ID de la conversación en stderr; `--conversation <id>` reanuda su contexto de modelo y carga las aprobaciones pendientes en modo interactivo. Aceptar una sugerencia de modelo solo cambia esa conversación. `/new` vuelve al modelo predeterminado del espacio de trabajo, salvo que hayas elegido explícitamente otro con `--model` o `/model`; al reanudar otro hilo se conserva su modelo guardado, salvo que esté activa esa elección explícita. Tras aceptar una sugerencia, los mensajes usan el modelo guardado de esa conversación, incluidos los cambios posteriores de otro cliente; `/model` establece una nueva elección explícita. Las sugerencias de modelo muestran el modelo de destino fijado al crear la tarjeta. Debes descartar las tarjetas antiguas sin un destino fijado antes de pedir otra sugerencia. Un nuevo hilo de terminal (incluido `/new`) empieza con los mismos conectores opcionales que un nuevo chat web: los que tienes activados de forma predeterminada en Configuración → Conexiones. `--connector NAME` (se puede repetir) sustituye ese conjunto para el nuevo hilo, por ejemplo `--connector email --connector lens`; un nombre desconocido o no disponible se rechaza antes de enviar nada. `--connector` no cambia un hilo existente: usa el selector Herramientas de la web (o pide al asistente en el chat que active un conector MCP opcional del paquete para esa conversación).

Las actualizaciones, los reinicios y las detenciones habituales del servidor (`fleet update`, `fleet restart`, `fleet stop`) se rechazan de forma predeterminada si hay un turno de chat, una acción aprobada o una tarea programada en curso. Con `--wait`, dejan de aceptar trabajo nuevo mientras esperan a que termine el actual (`--wait-timeout` establece el límite, de 90 minutos por defecto; `--force` omite la comprobación). Si el servidor se reinicia durante una acción aprobada, su resultado se muestra como desconocido; comprueba el resultado externo antes de intentar otra acción.

El terminal muestra las acciones preparadas y el número de pendientes. `/approvals` muestra los argumentos de ejecución completos y fijados, resúmenes de una línea y plazos; `/approve` y `/deny` deciden sobre la tarjeta más antigua o aceptan un ID de aprobación completo. `/edit {"name":"...","prompt":"...","cron":"..."}` modifica localmente la tarjeta de tarea programada más antigua antes de aprobarla. Los campos omitidos no cambian. `cron` solo se puede cambiar en una tarjeta recurrente; no se puede añadir a una tarea de ejecución única ni borrar, porque eso haría que la tarea se ejecutase de inmediato. El servidor valida los cambios cuando apruebas. Tras editar, el resumen de una línea de la tarjeta se vuelve a generar a partir de los valores editados. Así, el nombre, el prompt y el cron que ves son los que se enviarán, incluida la indicación aproximada de ejecuciones al mes, que se recalcula para el cron editado en vez de seguir describiendo el horario anterior. Una programación que se activa más de unas mil veces al mes muestra un mínimo (`≥1000 runs/month`), porque el recuento se detiene ahí. Si el terminal no puede interpretar el cron editado, no muestra ninguna estimación. Cada herramienta preparada muestra automáticamente sus argumentos de ejecución completos y fijados como JSON con caracteres escapados; el resumen de una línea no es el registro que debe revisarse. Si el servidor no proporciona una instantánea completa (o los argumentos superan el límite de revisión de 1 MiB), el terminal rechaza la aprobación. Los caracteres de control de revisiones, resultados y errores se escapan para que no puedan controlar el terminal. Cuando stdout de un resultado de aprobación se redirige a una canalización o archivo, conserva el resultado original para automatizaciones; la salida directa al terminal mantiene los caracteres escapados.

Añade `session` a una decisión para aplicarla a futuras llamadas de esa herramienta en la misma conversación, o `pattern arg=glob` para limitar la regla a los argumentos que coincidan. Los patrones usan los nombres originales de los argumentos de texto, como `name`, `cron` o `to_email` (no la etiqueta `to` del resumen). En las herramientas ejecutables, los nombres de los argumentos coinciden sin distinguir mayúsculas de minúsculas, y si una llamada incluye el mismo argumento más de una vez, una denegación se aplica si alguno de sus valores coincide y una aprobación solo si coinciden todos. En una tarjeta de tarea programada u otra acción gestionada por el servidor, un patrón solo coincide con un nombre tal como lo escribe la llamada, y nunca con uno que la llamada incluye más de una vez, así que ese patrón no resuelve la tarjeta y decides tú. Para las herramientas de navegador integradas, un patrón `action=` también coincide con el nombre habitual de la acción, y otro nombre de la misma acción en un patrón la representa (en `playwright_browser`, `action=start_session` también abarca `live`). Se permiten espacios en los patrones glob, y una denegación coincidente tiene prioridad sobre las aprobaciones. En una denegación, `*` y `?` también coinciden con la barra `/`, así que `command=rm *` abarca `rm -rf /tmp/x`; en una aprobación se detienen en la `/`, así que `command=ls *` abarca `ls -la` pero no `ls /tmp`. `/approvals` muestra los argumentos de patrón disponibles para las acciones gestionadas por el servidor; requiere que el servidor los proporcione. Las reglas de herramientas ejecutables se restablecen al reiniciar el servidor. Las reglas de tarjetas de tareas programadas y otras acciones gestionadas por el servidor duran esta sesión de terminal y siguen resolviendo cada tarjeta a través del endpoint de aprobación del servidor. `/resume <id>` cambia de conversación y carga sus tarjetas; `/approvals reload` actualiza las tarjetas. Las tarjetas caducadas se eliminan; si falla una solicitud de red, la tarjeta se conserva para volver a intentarlo. Las llamadas de ejecución única usan `--conversation <id> --approve <approval-id>` o `--deny`. Una acción rechazada o fallida devuelve un código de salida distinto de cero, sin indicar éxito.

Chat es la conversación con el asistente: preguntas, trabaja, lees el resultado y le orientas. La mayor parte de lo que se ejecuta en tu instalación tomó forma aquí, en una conversación que alguien pudo observar y corregir antes de dejarla ejecutarse sola.

El trabajo recurrente suele seguir un ciclo. Una conversación produce algo que merece la pena guardar. Esa conversación se convierte en un prompt guardado en la biblioteca de prompts. El prompt se convierte en una tarea programada. La tarea se ejecuta por sí sola y envía el resultado por correo a quienes deban verlo. Esta guía explica en detalle los dos primeros pasos; la **Guía de tareas en segundo plano** explica el resto.

> conversación → prompt guardado → tarea programada → tu bandeja de entrada *(esta guía cubre los dos primeros)*

Las dos interfaces se reparten el trabajo de forma sencilla. Chat funciona **con tu participación**: participas en la conversación, preguntas, lees y orientas el trabajo; ahí se da forma al informe hasta obtener el resultado correcto. Las tareas en segundo plano funcionan **sin tu intervención**: una vez que esa conversación es correcta, se ejecuta según un horario y entrega sus resultados; solo tienes que intervenir cuando algo te necesita. Las habilidades son las mismas en ambos lugares; solo cambia tu papel.

Las tarjetas de inicio rápido de un nuevo chat pueden recoger algunos datos antes de empezar el trabajo. Los campos de texto conservan los espacios al escribir; los cuadros de texto más grandes aceptan varias líneas. La vista previa del prompt conserva esos saltos de línea para que compruebes lo que se enviará antes de pulsar el botón de ejecución de la tarjeta.

### Panel de inicio de patrullas: tu primera patrulla en cinco pasos

La forma más rápida de poner al asistente a patrullar es **Patrullas** (el icono de destellos) en la barra lateral izquierda, entre **Chat** y **Tareas en segundo plano**, en cualquier interfaz. Si la barra está contraída, busca ese icono; en un teléfono, abre la barra lateral. Hasta que lo abras por primera vez, muestra un pequeño punto que parpadea. Las patrullas están en Chat: cada una es un chat que se activa según su horario. Por eso, **Patrullas** es su índice y su puerta de entrada: si aún no tienes patrullas, abre el **Panel de inicio de patrullas**; cuando ya tienes alguna, las enumera (nombre, chat, frecuencia y **En pausa** si está pausada). Pulsa una para abrir su chat; al final aparece **Nueva patrulla** para abrir el panel de inicio. El panel de inicio es un asistente paso a paso que te lleva desde cero hasta una patrulla en funcionamiento. Empieza con **¿Por qué usar patrullas?**, una ilustración de cuatro niveles que va del chat a los informes programados, las patrullas que analizan y deciden y, por último, el asistente actuando en tu nombre. También explica cómo ir ganando confianza: empieza con **Sugerir y preguntar** y activa **⚡ Aprobación automática** en la barra de Patrulla cuando confíes en sus decisiones. **Mostrar el plan** enumera los cinco pasos antes de empezar:

1. **Conecta tus herramientas.** Se muestran todos los conectores que puedes usar; los activados de forma predeterminada en nuevos chats aparecen marcados, y puedes marcar o desmarcar los demás para esta patrulla. Un conector que aún necesita credenciales muestra **Configurar**, y **Conectar otra herramienta** abre **Configuración → Conexiones**; ambos lo hacen en una pestaña nueva y la lista se actualiza al volver.
2. **Establece tus reglas básicas.** Elige **Quién está de guardia** (el perfil predeterminado del espacio de trabajo, salvo que elijas otro, incluidos tus propios perfiles) y guarda tus **condiciones innegociables**: toca una sugerencia o escribe la tuya y pulsa **Guardar**. Cada uno se guarda de inmediato como un recuerdo fijado, para que el asistente lo lea en todos los chats, incluidas las patrullas; puedes editarlo o eliminarlo después en **Configuración → Recuerdos**.
3. **Elige qué supervisar.** Elige entre **Detectar acuerdos mal configurados**, **Alertar cuando caiga el gasto**, **Asegurar la entrega de informes**, **Clasificar mi bandeja de entrada**, **Sugerir optimizaciones**, **Prepararme para el día** y **Detectar anomalías en mis datos**, y añade cualquier otra cosa con tus propias palabras. Cada tarjeta muestra cuáles de las herramientas que has marcado sirven para ella (**Usa…**) o qué tipo de conector necesitaría. Después elige su autonomía: **Solo informar** (nunca cambia nada), **Sugerir y preguntar** (prepara tarjetas de aprobación; la opción predeterminada) o **Actuar por mí** (activa **⚡ Aprobación automática** en el chat y enumera todo lo que ha hecho). Una nota bajo la opción sugiere empezar con **Sugerir y preguntar** y activar **⚡ Aprobación automática** más adelante.
4. **Elige una frecuencia.** **Mañanas de días laborables** (8:00, de lunes a viernes; predeterminado), **Dos veces por día laborable**, **Cada 2 horas**, **Cada hora**, **Cada mañana** o **Inicio del lunes**, o **Horario personalizado** para usar el editor completo de horarios y la zona horaria (la de tu navegador de forma predeterminada).
5. **Inicia la patrulla.** Revisa el plan, el nombre de la patrulla y **Qué hace en cada ejecución**: las instrucciones que recibe el asistente cada vez que se activa la patrulla, redactadas a partir de tus respuestas. **Redactar con IA** pide al asistente que las escriba por ti; si no puede, se conserva tu borrador. Edita lo que quieras y pulsa **Iniciar patrulla**.

Al iniciarla, se crea un chat nuevo con el perfil y las herramientas que hayas elegido, se añade la patrulla y se ejecuta la primera comprobación de inmediato; **Ver cómo trabaja** abre ese chat. Salvo que hayas elegido **Actuar por mí**, la pantalla de confirmación también sugiere activar **⚡ Aprobación automática** cuando sus decisiones sean acertadas de forma constante. A partir de ahí es una patrulla normal dentro del chat (se explica más abajo): puedes pausarla o detenerla desde la barra de Patrulla, o pedir en el chat que la cambie. No se crea nada hasta que pulses **Iniciar patrulla**, salvo las condiciones innegociables guardadas, que se convierten en recuerdos en cuanto pulsas **Guardar**. Puedes cerrar el panel de inicio con **Quizá más tarde** o `Esc` en cualquier momento, salvo mientras **Redactar con IA** está escribiendo (hasta unos 45 segundos) o durante los pocos segundos del inicio; tus respuestas se conservan durante el resto de la sesión del navegador. Una cuenta de solo lectura ve la página **¿Por qué usar patrullas?** con una nota que explica que no puede guardar recuerdos ni iniciar una patrulla, y un botón **Entendido** en lugar del resto del asistente.

### Patrullas y temporizadores dentro del chat

También puedes ejecutar una **patrulla** recurrente o un **temporizador** de ejecución única directamente dentro de una conversación de chat, sin salir del hilo ni convertirlo en una tarea en segundo plano independiente. Cada vez que se activa una patrulla o un temporizador, el asistente se reactiva en la misma conversación, conservando todo su historial de mensajes, los archivos del espacio de trabajo y los conectores activados.

Hay dos formas de iniciar una patrulla o un temporizador:

- **Pídelo en el chat:** dile al asistente qué debe supervisar y con qué frecuencia (por ejemplo, *«supervisa mis acuerdos cada 2 horas y actualiza el panel si cae el ritmo de gasto»* o *«vuelve dentro de 30 minutos y comprueba la carga de datos históricos»*). El asistente usa la herramienta `chat_patrol` (`create`, `list`, `update`, `pause`, `resume`, `cancel`) para añadir o ajustar la programación de la conversación actual.
- **Usa Patrulla en el editor de mensajes:** abre **Más opciones** (`•••`) en la barra del editor de mensajes y pulsa **Patrulla y programación** (o la etiqueta activa **Patrulla** de la barra). Elige una opción predefinida (**Cada hora**, **Cada 2 h**, **Cada 4 h**, **Cada 6 h**, **De lunes a viernes a las 9:00**, **Cada día a las 9:00**, **En 30 min (una vez)**, **En 2 h (una vez)**, o **Personalizado** para crear una programación recurrente por horas, minutos, cada día, días laborables o días concretos de la semana y zona horaria, con una opción **Cron avanzado**, o un temporizador único personalizado en minutos u horas). Introduce las instrucciones de la patrulla y pulsa **Iniciar patrulla** (o **Iniciar temporizador**).

Cuando una conversación tiene una patrulla o un temporizador activos o pausados, la **Barra de Patrulla** aparece encima del hilo con el estado de la programación (**Patrulla activa**, **Temporizador activado** o **En pausa**), la frecuencia, el número de ejecuciones y la cuenta atrás para la siguiente, junto con los botones **Ejecutar ahora**, **Pausar / Reanudar** y **Detener**. Activar **⚡ Aprobación automática** (en la ventana de Patrulla, su barra o **Más opciones** en el editor de mensajes) permite que las llamadas a herramientas que admiten aprobación por sesión se ejecuten sin intervención mientras estás ausente. Si un turno de patrulla prepara una tarjeta de aprobación, esta permanece abierta 24 horas y el turno se reanuda automáticamente en cuanto la apruebas. Las conversaciones con una patrulla activa o pausada quedan excluidas de la limpieza por retención hasta que se detenga la patrulla.

Una patrulla usa el perfil del chat, por lo que un perfil tuyo, como un gemelo digital, puede supervisar por ti: pulsa **Iniciar patrulla** en una de sus patrullas sugeridas en **Configuración → Perfiles** (consulta [Tus propios perfiles y gemelo digital](#your-own-personas-and-digital-twin)).

### Clientes ACP (Zed, Neovim, Emacs, JetBrains, Buzz)

`fleet acp` permite que un cliente Agent Client Protocol se comunique con Fleet. El cliente lo inicia y cada mensaje se convierte en un turno normal del chat de Fleet, con el usuario indicado por `--email` o `FLEET_USER_EMAIL`. La conversación aparece en el chat web como cualquier otra. Las respuestas, el razonamiento y los pasos de herramientas se transmiten al cliente en directo. Si un paso requiere aprobación, la respuesta termina con un enlace o un comando `fleet chat --approve`, porque las aprobaciones se resuelven en Fleet, no en el cliente. No se aceptan imágenes ni audio. JetBrains envía las capturas de pantalla que arrastras al chat solo como un nombre de archivo, de modo que el asistente nunca ve la imagen y no se muestra ninguna advertencia.

Los archivos que adjuntas en tu editor llegan a Fleet tal como los envía el editor. Cuando solo envía un enlace a un archivo, como hace JetBrains con un archivo adjunto o abierto en el editor, `fleet acp` pide su texto al editor si este permite a los agentes leer archivos (JetBrains y agent-shell de Emacs lo permiten), y lo envía con tu mensaje. Se envían hasta 100 KB de un archivo y hasta 300 KB del conjunto de archivos enlazados en un mensaje: los archivos más largos se recortan y los de más de 1 MB no se envían; en ambos casos se informa al asistente. En JetBrains, esto significa que el archivo abierto en el editor se envía a Fleet con cada mensaje, añadiendo su texto a la conversación cada vez; cierra los archivos con secretos antes de chatear.

Si tu operador ha añadido Fleet a tu espacio de trabajo de Buzz, puedes mencionarlo allí con @. De forma predeterminada, solo la persona que lo configuró y sus propios agentes pueden darle instrucciones; tu operador también puede autorizar a otras personas. La respuesta llega cuando termina su turno, en el hilo de tu mensaje, y te menciona con @; no aparece nada mientras trabaja y las respuestas no se transmiten en directo ni se editan. Si envías otro mensaje a Fleet mientras trabaja, responderá a ambos en una sola respuesta. Fleet no puede leer los archivos adjuntos en Buzz, y las instrucciones de agente y los recuerdos de Buzz no llegan a Fleet. La conversación también está en el chat web de Fleet, bajo el usuario con el que se ejecuta el agente.

Fleet no usa los servidores MCP que envía tu editor: los que configuraste y, salvo que esté desactivado, el integrado en JetBrains. Las herramientas y los conectores de Fleet son los que configuró tu operador y se ejecutan en el servidor de Fleet. La primera respuesta de una sesión lo indica y nombra los servidores que envió tu editor.

Cuando el cliente abre una sesión, `fleet acp` comprueba primero tu usuario y tu token con el servidor de Fleet. Un token incorrecto, un correo que no corresponde a un usuario de Fleet, un lector con acceso de solo lectura o una dirección no admitida por el servidor impiden abrir la sesión, con un error que explica el motivo y cómo resolverlo. Un servidor inaccesible no la impide: la sesión se abre y tu primer mensaje informa del problema.

La respuesta termina en el cliente en cuanto está completa. Fleet puede necesitar unos segundos más para cerrar el turno (por defecto, asigna un nombre a una conversación nueva después de su primera respuesta); un mensaje que envíes durante ese tiempo espera hasta 90 segundos en lugar de ponerse en cola.

Un mensaje enviado desde el cliente mientras otro sigue ejecutándose no lo detiene. Espera, y los mensajes de la misma sesión se ejecutan de uno en uno, en el orden en que el cliente los envió. Una cancelación del cliente detiene la respuesta en curso y los mensajes anteriores a la cancelación que aún estén esperando; un mensaje enviado justo después de cancelar sí se ejecuta. `fleet acp` espera hasta 2 segundos por un mensaje que tarde en llegar, para mantener ese orden, y después continúa sin él; en ese caso poco frecuente, una cancelación puede no alcanzar al mensaje enviado justo antes. Puede haber hasta 20 mensajes esperando detrás del que se está ejecutando. Un mensaje número 21 se rechaza de inmediato con un error que indica que la sesión ya tiene un prompt en ejecución y 20 en espera. No se envía a Fleet; vuelve a enviarlo cuando los anteriores hayan recibido respuesta o cancélalos desde el cliente.

Si cierras el editor o detienes el agente mientras sigue ejecutándose una respuesta, y el editor permite que el agente se cierre de forma ordenada (CodeCompanion.nvim de Neovim lo permite), ese turno también se detiene en Fleet. Los mensajes del cliente que aún esperaban detrás se descartan: nunca llegan a Fleet. Un mensaje que Fleet ya había puesto en cola (por ejemplo, detrás de un turno iniciado desde el chat web) sí se ejecuta. Un editor que fuerza el cierre de su agente deja el turno en ejecución: detenlo desde el chat web. Zed lo hace al cerrarse; en Emacs, cerrar Emacs detiene el turno, pero cerrar el búfer agent-shell no.

### Qué ocurre cuando preguntas

El asistente hace el trabajo en lugar de limitarse a describirlo. Tiene un espacio de trabajo privado para cada conversación, con shell, un entorno de ejecución de Python y herramientas de archivos, para abrir los datos a los que le hayas dado acceso (adjuntos, conectados o compartidos), analizarlos y entregarte el resultado en el formato que pidas. Cada paso que realiza aparece en la transcripción como un registro que puedes desplegar. Las acciones con consecuencias fuera de la conversación, como enviar un correo o programar una tarea, se detienen y te preguntan primero.

Ese espacio de trabajo es un **entorno aislado** obligatorio: cada comando, cada línea de Python y cada archivo que el asistente lee o escribe se procesan dentro de él, aislados de la máquina donde se ejecuta la plataforma. Las credenciales de los sistemas conectados nunca entran en él.

## 2. Cómo leer la pantalla

Hay tres zonas: la barra izquierda contiene tus conversaciones, la transcripción central contiene el trabajo y el editor inferior es donde escribes tus peticiones.

### La barra lateral

En la parte superior de la barra están las tres formas de trabajar, cada una con un subtítulo: **Chat** (*Habla sobre ello*), **Patrullas** (*Chats que se activan según un horario*: tus chats de patrulla y el [Panel de inicio de patrullas](#patrol-launchpad-your-first-patrol-in-five-steps)) y **Tareas en segundo plano** (*Se ejecuta sin un chat*; antes llamado Centro de operaciones). **Nuevo chat** inicia una conversación nueva. El campo de búsqueda, al que también se accede con `⌘K` o `Ctrl K`, busca por títulos de conversación y también puede buscar **En mensajes**. Debajo, las conversaciones se agrupan:

| Grupo | Qué contiene |
| --- | --- |
| **Proyectos** | Espacios de trabajo con instrucciones permanentes, aprendizajes compartidos y sus propias conversaciones. Un proyecto compartido con tu equipo lleva un icono de equipo. Consulta [Recuerdos y proyectos](#7-memory-and-projects). |
| **Chats de equipo** | Conversaciones que tus compañeros comparten contigo o abren en **Modo colaborativo**, con el nombre corto del propietario y una etiqueta **En directo** cuando el chat colaborativo está activo. |
| **Fijados** | Conversaciones que has elegido conservar. Las conversaciones fijadas nunca caducan. Si hay dos o más, **Reordenar** en la cabecera te permite ordenarlas a tu gusto (consulta [Ordenar tus chats](#ordering-your-chats)). |
| **Etiquetas** | Tus etiquetas, cada una como filtro. Pulsa una para mostrar solo las conversaciones que la llevan; pulsa varias para acotar más. |
| **Temporales** | Todo lo demás, con la actividad más reciente primero; el menú junto a la cabecera permite ordenar por **Más recientes primero** o **Título A–Z**. Estos chats se eliminan tras un período de inactividad (14 días en una instalación predeterminada); el icono ⓘ junto a la cabecera lo indica. Fija un chat o muévelo a un proyecto para conservarlo. **Eliminar chats temporales**, en rojo al final de la barra lateral, los elimina todos a la vez después de confirmar. |
| **Archivados** | Contraído de forma predeterminada. Conversaciones que has apartado sin eliminar; abre el grupo para recuperar una. |

Una fila de chat puede llevar dos pequeñas etiquetas que indican su público al pasar el cursor: una significa que se comparte por enlace y la otra, con tu equipo. Pulsa el nombre de un proyecto para abrir su página y expandirlo; la flecha solo lo contrae. Al pasar el cursor por un proyecto aparece su menú: **Abrir proyecto**, **Nuevo chat**, **Reordenar chats** (si contiene dos o más chats tuyos) y, para el propietario, **Compartir…** y **Configuración del proyecto…**. Consulta [Conservar, organizar y compartir conversaciones](#8-keeping-shaping-and-sharing-conversations).

El menú de tu cuenta, al pie de la barra, cambia la apariencia entre **Claro**, **Oscuro** y **Sistema**, y abre **Configuración**, **Guías** (estas guías de usuario) y **Contexto y conexiones**; los administradores también encuentran ahí **Configuración de administración** y **Analítica**. La opción **Cerrar sesión** pide confirmación porque también cierra tu sesión en todas las aplicaciones que comparten ese inicio de sesión.

**Configuración → General → Idioma** permite elegir **English**, **Español** o **Português** para la interfaz y estas guías. Tu elección se guarda en este navegador. Antes de que elijas, la plataforma usa el idioma de tu navegador si está disponible; en caso contrario, usa inglés. Al cambiar el idioma se recarga la página actual y se conservan la ruta y la sección; el parámetro `lang` de la URL también conserva la elección si el almacenamiento del navegador no está disponible. Las conversaciones, los archivos, los prompts guardados y los demás contenidos que hayas escrito se mantienen en su idioma original.

**Configuración → General → Notificaciones del navegador** activa las alertas en el navegador que estás usando, incluso cuando la pestaña está en segundo plano. Por defecto, recibes una alerta cuando una tarea tuya termina, espera tu respuesta o envía una nota de progreso durante la ejecución (**Nota de progreso**: la tarea continúa y no se muestra el contenido de la nota); cuando una acción de un chat necesita tu aprobación; y, si tu cuenta tiene un presupuesto de uso, cuando intentas crear una tarea habiendo superado el límite de aviso (**⚠ Alerta de presupuesto**: se comprueba en ese momento, no cuando se supera el límite). [Tarjetas que piden una decisión](#6-cards-that-ask-for-a-decision) explica las demás. El navegador pide permiso la primera vez. Una alerta solo muestra un título breve (el inicio del prompt de la tarea y su resultado, la acción pendiente o el presupuesto y su período), nunca la conversación ni un resultado. El interruptor se aplica por navegador y cuenta; actívalo en cada navegador donde quieras recibir alertas. Una cuenta **Lector** no puede activarlas: el interruptor está deshabilitado y la explicación aparece debajo. Si ya estaban activadas antes de que la cuenta pasara a ser de lector, aún puede desactivarlas. Funcionan en Chrome, Edge, Firefox y Safari, y en navegadores que usan los mismos servicios push. Si un navegador usa otro servicio push, el interruptor muestra un error; actívalas en uno de esos navegadores. Si el interruptor está deshabilitado por otro motivo, la línea inferior explica por qué: el navegador no las admite, están bloqueadas para este sitio en el navegador (permítelas allí y recarga) o la instalación no las ha configurado. Si la instalación cambia sus claves de notificación, el navegador no recibe alertas hasta que vuelvas a abrir Fleet, que las renueva automáticamente; si el interruptor indica que no ha podido renovarlas, recarga la página.

Los administradores gestionan el acceso de las cuentas en **Configuración → Administración → Usuarios**. Chat usa **Colaborador** de forma predeterminada; **Lector** es de solo lectura. **Administrador de Fleet** concede todos los permisos de Chat y Tareas en segundo plano y resalta las opciones de Colaborador incluidas. Volver a seleccionar Administrador de Fleet lo desactiva y establece de forma segura Colaborador en Chat y ningún acceso a Tareas en segundo plano. Cada persona tiene una cuenta de Fleet: Chat y Tareas en segundo plano comparten su correo, contraseña y rol de Administrador de Fleet; el acceso a Tareas en segundo plano forma parte de esa misma cuenta. Las cuentas creadas con acceso a Fleet en Auth central se añaden aquí automáticamente con los roles allí seleccionados. Si tu instalación usa Auth central para iniciar sesión, este gestiona a todas las personas por defecto: la página de acceso solo ofrece inicio de sesión único, y esta página enumera personas y uso sin controles (sin **Añadir usuario**, editor de fila ni **Cambiar nombre del equipo**). Incluye un enlace a Auth central, donde se añaden o eliminan personas y se cambian sus roles, equipos y contraseñas. **Configuración → Equipo** muestra entonces tu equipo, pero no permite modificarlo. Mover a alguien de equipo en Auth central también lo mueve aquí, con el mismo efecto que hacerlo directamente: lo que compartía con su equipo anterior deja de compartirse. Renombrar un equipo en Auth central también lo renombra aquí y mantiene todo lo compartido con ese equipo. En los demás casos, renombrar aquí un equipo mantiene todo lo compartido; un equipo nuevo que después use el nombre anterior empieza sin nada compartido.

### La cabecera

Encima de la transcripción, a la derecha, hay dos controles rápidos para escritorio: **Panel** cambia la conversación a [vista de panel](#dashboard-view), y **Atajos de teclado** muestra la misma lista que la [última sección](#13-keyboard-shortcuts) de esta guía. En pantallas móviles estrechas (`< 40rem`), los botones **Panel** y **Atajos de teclado** se ocultan de la cabecera para mantener compacta la barra superior (cambia a la vista de panel desde **Más opciones → Vista de panel**). **Recuerdos** y **Mostrar detalles** (que muestra u oculta el razonamiento, las notas de trabajo, las llamadas a herramientas y los costes por turno de toda la conversación) están en **Más opciones** (`•••`) en el editor de mensajes, con etiquetas claras y accesibles tanto desde el chat normal como desde la vista de panel. Si tu operador configura un contacto de soporte en el paquete de la instalación (`branding.support`), la barra superior muestra también ese botón en Chat, Tareas en segundo plano, Configuración y Guías (en móviles se reduce a una etiqueta **Ayuda** o `branding.support.mobile_label`). Al pulsarlo, se abre un diálogo con el mensaje del operador, un botón **Copiar correo** y una acción **Enviar correo** (`mailto:`), que se omite de forma predeterminada si no está configurada. La cabecera de cada conversación también indica quién puede verla: **Solo tú**, **Compartido con tu equipo**, **Chat colaborativo** o **Enlace público**. El editor incluye **Compartir este chat** dentro de **Más opciones** (`•••`), además de un indicador en la barra cuando el chat está compartido. Ambos abren el diálogo para compartir.

### La transcripción

Tus mensajes aparecen tal como los escribiste; los muy largos (más de 4.000 caracteres) se contraen por defecto en una vista previa con un control **Mostrar mensaje completo** / **Mostrar menos** debajo. Cuando la plataforma añade a un mensaje algo que no escribiste, como un archivo adjunto o una nota de la biblioteca de archivos compartidos, aparece como una nota contraída junto al mensaje, separando claramente lo que escribiste de lo que se añadió.

Cada respuesta del asistente sigue un orden fijo, de arriba abajo, para que veas primero la respuesta y después lo que necesite tu atención:

| Parte | Qué es |
| --- | --- |
| Registro de ejecución | Una fila de etiquetas, una por cada herramienta usada: un archivo leído, un conector llamado o código ejecutado. Pulsa una etiqueta para ver exactamente qué se envió y qué se recibió. Así puedes comprobar el trabajo. Una etiqueta con el color de peligro indica una llamada fallida; una acción enviada a una tarjeta de aprobación no se considera fallida: se marca como **enviado para aprobación**, y la tarjeta indica si se ejecutó. Solo aparece si **Mostrar detalles** está activado. En turnos ejecutados con la cuenta de otra persona en un chat compartido o colaborativo, aparece **Detalles ocultos en los turnos de otros usuarios** en lugar de sus llamadas privadas a herramientas, razonamiento y costes por turno. |
| Razonamiento | El razonamiento del asistente explicado con palabras. También aparece solo cuando **Mostrar detalles** está activado. |
| Notas de trabajo | Mientras se genera la respuesta, las notas breves que escribe el asistente entre pasos («Primero voy a consultar el acuerdo»). Solo aparecen con **Mostrar detalles** activado y hasta que recargues la página: la conversación guardada conserva la respuesta, no las notas. Con los detalles ocultos, las sustituye una línea de estado: **Pensando** o el paso en curso, como **Ejecutando shell** o el elemento del plan en el que está trabajando. |
| La respuesta | Texto, tablas, gráficos e imágenes. El código y los datos aparecen en bloques que se pueden copiar. Cuando el asistente crea un informe HTML, se muestra como **Vista previa de HTML** con un control **Mostrar código fuente**. |
| Tarjetas interactivas | Un formulario, selector, lista de comprobación, comparación, gráfico o pequeña calculadora que el asistente ha creado para esta respuesta. Complétalo y pulsa su botón; tus respuestas se envían como tu siguiente mensaje. Consulta [Tarjetas interactivas](#interactive-cards). |
| Estado | Avisos de situaciones inusuales del turno: reintentando, cancelado o fallido. Consulta [Cuando un turno falla](#11-when-a-turn-goes-wrong). |
| Tarjetas | Cualquier elemento que pida una decisión: una aprobación, un recuerdo propuesto o una sugerencia de cambio de modelo. Consulta [Tarjetas que piden una decisión](#6-cards-that-ask-for-a-decision). |
| Pie | Las acciones de una respuesta terminada: **Copiar**, **Regenerar** y **Reintentar con** el modelo más potente (estas dos últimas solo aparecen bajo la última respuesta; **Reintentar con** cuando el chat aún no usa ese modelo y no hay una tarjeta de cambio pendiente, porque la tarjeta ofrece lo mismo), **Crear rama**, **Guardar como flujo de trabajo** y **Guardar** (la respuesta como recuerdo). Cada una se explica más adelante en su sección de la guía. |

Las conversaciones largas ocultan los turnos más antiguos tras **Mostrar N turnos anteriores**; un minimapa en el borde permite saltar entre mensajes.

### El editor de mensajes

La barra bajo el cuadro de mensaje mantiene a mano los controles habituales y agrupa las opciones secundarias en **Más opciones** (`•••`). De izquierda a derecha:

| Control | Qué hace |
| --- | --- |
| Selector de modelos | Muestra el modelo de la conversación y una banda de coste de `$` a `$$$$` si se conoce el precio. Pulsa para cambiarlo. Consulta [Elegir el modelo](#picking-the-model). |
| Adjuntar archivos | Añade archivos a tu siguiente mensaje. Arrastrar un archivo a cualquier parte de la conversación hace lo mismo. |
| Herramientas | El icono de llave inglesa. Su etiqueta cuenta los conectores activos en esta conversación, incluidos los **Siempre activado**; al pasar el cursor, muestra «Herramientas, N activadas». Consulta [Conectores en una conversación](#5-connectors-in-a-conversation). |
| Más opciones (`•••`) | Abre un menú con etiquetas organizado en tres grupos: **Biblioteca de instrucciones**, **Perfil** (activo en cualquier chat nuevo o vacío antes de enviar el primer mensaje, y desactivado con *«Solo se puede cambiar de perfil en un chat nuevo»* cuando la conversación ya ha empezado) y **Recuerdos**; **Compartir este chat**, **Patrulla y programación**, **Aprobar herramientas automáticamente** y **Resumir mensajes anteriores** (cuando la conversación tiene mensajes, muestra cuánto se ha llenado el chat); y **Mostrar detalles**, **Vista de panel** y **Enviar con Intro**. Cuando está activo un perfil distinto del predeterminado, una programación de patrulla, el uso compartido (**Chat colaborativo**, con el equipo o por enlace público) o **Aprobación automática**, **Más opciones** muestra un punto de color y, en pantallas de escritorio, aparece además un indicador de estado directamente en la barra para verlo o cambiarlo con un clic. |
| Enviar | En el extremo derecho. Mientras el asistente trabaja, se convierte en **Detener**. |

### Vista de panel

La vista de panel convierte una conversación en un tablero en directo: los gráficos, cifras y tablas del asistente permanecen visibles como paneles y el chat se estrecha en una columna a su lado. Úsala para seguir algo mientras continúas conversando: una cartera de oportunidades, una campaña, una lista de lanzamiento o una comparación que estás mejorando. Actívala con **Panel** en la parte superior del chat (en escritorio), **Vista de panel** dentro de **Más opciones**, o `D`; sal con **Salir**, o con `Esc` si no estás escribiendo en el cuadro de mensaje.

- **Pide lo que quieras vigilar.** «Convierte esto en un panel», «añade un panel de acuerdos abiertos», «actualiza el panel de ingresos». El asistente crea paneles con las mismas [tarjetas interactivas](#interactive-cards) que usa en el chat y los actualiza en su lugar cuando se lo pides; cada panel conserva su posición y muestra un pequeño número de versión (**v2**, **v3**) y un breve resalte. Los mensajes enviados desde esta vista indican al asistente que estás mirando el tablero y qué paneles contiene, por orden. Así, «actualiza este gráfico», «actualiza el segundo panel» o «añade la semana pasada al panel de ingresos» llegan al panel correcto, incluso si fijaste la tarjeta tú mismo. También le piden que actualice los paneles en lugar de repetir sus cifras en el chat. Un tablero vacío ofrece algunas peticiones para empezar; al elegir una, se coloca en el cuadro de mensaje para que la edites y envíes.
- **Qué aparece en el tablero.** Las tarjetas que solo muestran información (gráficos, cifras, tablas, listas de comprobación) van al tablero, igual que las que el asistente haya marcado como panel. Los formularios que te preguntan algo permanecen en el chat; **Fijar en el tablero** bajo un formulario lo añade como panel. Una tarjeta del tablero aparece en el chat como una referencia de una línea; púlsala para saltar al panel.
- **Organízalo.** Arrastra un panel por el asa a la izquierda de su título, o enfoca el asa y usa las flechas del teclado. Los botones del panel permiten ensancharlo o estrecharlo, usar **Enfocar** para llenar el tablero (`Esc` o el botón de cierre permiten volver) y usar **•••** para moverlo o quitarlo; en ese caso, su tarjeta vuelve al chat. La disposición y la preferencia de abrir una conversación en vista de panel solo se guardan en este navegador; un compañero que abra el mismo chat ve los paneles con su propia disposición.
- **Las capacidades del asistente no cambian.** Puedes escribir, adjuntar archivos y responder a tarjetas de aprobación en la columna del chat como antes; los correos y las demás acciones siguen esperando tu aprobación. El indicador superior muestra **En espera**, el nombre del paso en curso mientras trabaja el asistente o cuántas aprobaciones están pendientes; púlsalo para ir a la primera.
- **En un teléfono**, la barra superior tiene botones **Tablero** y **Chat** para alternar entre ambos.
- **La lista de conversaciones queda oculta**, por lo que sus atajos (`J`/`K`, `P`, `A`, `R`, `#`) no hacen nada en la vista de panel, y `⌘ K` sale de esa vista para abrir la búsqueda.
- **Puedes volver cuando quieras.** Al salir de la vista de panel vuelves al chat normal, con todas las tarjetas en su lugar y lo que hayas escrito en el cuadro de mensaje o en una tarjeta intacto. Al volver, el tablero se restaura tal como lo dejaste.

Los paneles son tarjetas, por lo que se aplican los límites de [Tarjetas interactivas](#interactive-cards): un panel anterior a una compactación se marca como **archivado** y no admite respuestas, y el tablero solo aparece en la aplicación web.

## 3. Cómo obtener buenas respuestas

Si un proveedor falla después de un paso de herramienta completado, el asistente puede continuar con sus resultados mediante una recuperación limitada. Una herramienta iniciada durante el paso fallido impide la recuperación, para evitar repetir una acción de resultado incierto. Comprueba el registro de ejecución antes de repetir manualmente una petición que haya terminado con error.

Da instrucciones al asistente como a un compañero competente: explica qué quieres, qué debe usar y comenta el resultado. La calidad de la respuesta depende de la petición; algunos hábitos la mejoran siempre.

| Hábito | Por qué funciona |
| --- | --- |
| **Nombra la fuente** | Indica qué informe, remitente o conector. «El informe diario de entregas más reciente del buzón» funciona; «el último archivo» obliga al asistente a adivinar, y una suposición incorrecta puede parecer correcta. |
| **Especifica los identificadores** | Los nombres de acuerdos, códigos de campañas e identificadores son los elementos más fáciles de interpretar mal, aunque todas las cifras de alrededor sean correctas. Especifica exactamente los identificadores que quieres y pide que se muestren tal como aparecen en la fuente. |
| **Toma los datos como referencia** | Los informes suelen llevar un día o más de retraso; pide «la fecha más reciente del archivo» en lugar de «ayer». Cada fuente tiene su propia fecha más reciente; deja que el asistente la encuentre en los datos sin darla por supuesta. |
| **Pide que muestre su trabajo** | «Muéstrame las filas que justifican esa cifra» es la comprobación más rápida. El registro de ejecución muestra qué hizo; esto muestra las pruebas. |
| **Señalar, no adivinar** | Indícalo claramente: «Si no puedes abrir algo o falta algún dato, dilo y continúa con el resto». Un informe fiable explica lo que no ha podido hacer. |
| **Peticiones pequeñas, de una en una** | Construye por pasos. Primero consigue los datos correctos; después, la comparación y, por último, el formato. Comenta cada resultado: «demasiado detalle», «muéstralo en una tabla», «pon las fechas arriba». La conversación de corrección es lo que da al informe su forma final. |

### Elegir el modelo

Cada conversación usa un modelo que puedes cambiar en cualquier momento, incluso a mitad de la conversación. Pulsa el selector de modelos, escribe para buscar y elige el que mejor se adapte al trabajo. Los modelos que tu instalación marca como **recomendado** aparecen al principio de la lista. El primero es el **modelo predeterminado**, nuestro modelo de vanguardia más inteligente, con el que empieza cada conversación nueva para ofrecer el mejor razonamiento y uso de herramientas. El segundo es el **modelo alternativo**, otro modelo de vanguardia inteligente de una familia de proveedores distinta, al que recurren automáticamente las tareas y patrullas en caso de fallo y que el asistente ofrece cuando un turno tiene dificultades. Por defecto son **Gemini 4 Hydrogen** (el de las conversaciones nuevas) y **Claude Opus 5.5** (el modelo de vanguardia alternativo); tu administrador puede cambiar cualquiera de los dos y, al actualizar el modelo principal o el alternativo del espacio de trabajo, las conversaciones existentes y las tareas recurrentes pueden pasar automáticamente al nuevo modelo con un breve aviso en los chats activos. Para optimizar el gasto en consultas, comprobaciones o formatos rutinarios, puedes elegir un modelo más económico o gratuito. Tu administrador también puede fijar modelos debajo de los dos recomendados, a veces con un nombre propio y una etiqueta como **alfa**, que indica que aún están en pruebas. Un modelo fijado también puede mostrar **Gratis** en lugar de su banda de coste. Los demás modelos llevan un estado (**probado**, **nuevo** o **experimental**) y, si la instalación conoce el precio, muestran su banda de coste para que sepas lo que vas a gastar. Si no hay banda, el precio es desconocido, no cero; conviene consultarlo antes de iniciar un trabajo largo.

El selector usa los proveedores de modelos activos del espacio de trabajo, incluidos los configurados por la instalación. Los modelos de **Espacio de trabajo** se ejecutan directamente a través del proveedor indicado. Cuando se carga la información de proveedores, se ocultan las opciones recomendadas o del catálogo público a las que el espacio de trabajo no puede acceder. Una conversación guardada o una opción predeterminada que ya no está disponible permanece visible con una explicación: usa **Elegir un modelo**, elige un modelo disponible y vuelve a intentarlo. Fleet no cambia silenciosamente una conversación existente a otro proveedor, salvo en un caso: una conversación en **modo restringido** solo puede usar los modelos permitidos por tu administrador (por defecto, el predeterminado y el alternativo del espacio de trabajo). Si esa lista cambia, el siguiente turno usa el modelo predeterminado del modo restringido y la conversación lo conserva desde entonces. El selector de modelos muestra el cambio al empezar el turno. Ese cambio necesita un modelo concreto: si tu administrador ha definido la lista del modo restringido solo con patrones y sin nombres de modelos, no hay destino posible y la conversación seguirá rechazando las peticiones. Inicia un nuevo chat restringido y avisa al administrador de que la lista necesita primero un modelo con nombre. Los administradores pueden corregir la configuración de proveedores en **Configuración → Administración → Proveedores de modelos** y establecer el modelo predeterminado y el alternativo en **Configuración → Administración → Funciones → Niveles de modelos**. Además de OpenRouter, Anthropic, OpenAI y Ollama, esa página permite añadir cualquier servidor **compatible con OpenAI** (requiere su URL base; la clave es opcional), **Vercel AI Gateway** (requiere una clave), un recurso **Azure OpenAI** (requiere una clave y el endpoint del recurso como URL base; sus modelos son los nombres de los despliegues del recurso), **Google Gemini** (requiere una clave de API de Gemini de Google AI Studio) y **Amazon Bedrock** (solo modelos Claude; requiere una clave de API de Bedrock y la región AWS en la que se creó la clave, us-east-1 de forma predeterminada, y sus modelos son identificadores de perfiles de inferencia de Bedrock, como `us.anthropic.claude-sonnet-4-5-20250929-v1:0`). En Azure, una implementación de GPT-5 o de la serie o debe incluir el modelo en su nombre, como `gpt-5-prod`; si no, sus turnos fallan. Un modelo de razonamiento más reciente, como GPT-6, puede fallar independientemente del nombre de la implementación. Un modelo de Vercel añadido allí pasa a usar Vercel en lugar de OpenRouter. Un proveedor añadido allí, salvo OpenRouter, necesita su **Ventana de contexto** (en tokens, el menor límite de los modelos que ofrece) antes de poder activarse. Si no la tiene, se marca como **Sin ventana de contexto**, y un turno suele detenerse antes de responder con «El modelo seleccionado no ha podido completar este turno». Si ocurre siempre con un modelo, pide al administrador que la configure. Una tarea programada desde el chat no conserva su modelo: salvo que pidas uno concreto, usa el modelo de tareas del espacio de trabajo, que por defecto es el más potente. Si un proveedor directo tiene prioridad sobre OpenRouter, las opciones disponibles de OpenRouter llevan el nombre del proveedor configurado y usan una ruta explícita con su prefijo.

A veces el propio asistente sugiere cambiar: una tarjeta con **Cambiar y reintentar** si la pregunta supera lo que el modelo actual resuelve bien, o un aviso de una línea si adjuntas una hoja de cálculo grande al modelo rápido. Fleet puede mostrar esa misma tarjeta después de una respuesta con dificultades claras (varios fallos de herramientas seguidos, un paso repetido o un turno muy largo) y, salvo que tu administrador lo haya desactivado, cuando tu mensaje expresa desacuerdo con una respuesta incorrecta. Todo esto son sugerencias. Nada cambia si no aceptas. Si una respuesta es incorrecta y no quieres esperar una sugerencia, **Reintentar con** bajo la última respuesta repite la petición de inmediato con el modelo más potente.

### Perfiles y habilidades

Un **perfil** es una forma de trabajar guardada que tu instalación puede incluir y que se elige desde el editor de mensajes. Una **habilidad** es una capacidad empaquetada que el asistente puede usar por sí solo cuando encaja con la tarea, o que puedes invocar escribiendo `/` al principio del mensaje y eligiéndola de la lista. La plataforma incluye un pequeño conjunto de habilidades de uso general y tu instalación puede añadir las suyas. En **Configuración → Habilidades** también puedes crear habilidades personales, publicar una habilidad en **Habilidades del espacio de trabajo** (**Compartir con tu espacio de trabajo**), pulsar **Añadir a mis habilidades** en una habilidad compartida por un compañero en Habilidades del espacio de trabajo para activarla en tus chats y tareas, o pulsar **Clonar y editar** en cualquier habilidad del espacio de trabajo para cargar sus instrucciones en el editor y personalizarla. También puedes pedir al asistente en el chat que proponga una habilidad o edite una existente, y luego pulsar **Aprobar** o **Aprobar y compartir** en **Configuración → Habilidades**. Tus habilidades personales activas aparecen junto a las del espacio de trabajo en el menú de autocompletado `/` del editor de mensajes. Si personalizas una habilidad del espacio de trabajo con el mismo nombre, tu versión sustituye la descripción y las instrucciones predeterminadas en tus ejecuciones.

### Tus propios perfiles y gemelo digital

En **Configuración → Perfiles** puedes escribir tus propios perfiles. Son privados: solo los chats que inicias pueden usarlos, y aparecen en **Tuyos** en el menú de perfiles del editor de mensajes (dentro de **Más opciones** `•••`).

- **Crea tu gemelo digital.** Descríbete (tu función, qué supervisas, cómo decides y cómo prefieres que se escriban las cosas), elige si el gemelo puede leer lo que escribiste en chats recientes y selecciona **Sugerir acciones** o **Actuar en mi nombre**. **Crear con el asistente** abre un nuevo chat con esa petición en el editor; no se envía nada hasta que pulses Enviar. El asistente solo puede leer los mensajes que escribiste, no sus propias respuestas ni los chats en modo restringido, archivados o eliminados; hace unas preguntas y prepara un perfil **borrador** con patrullas sugeridas. **Escribirlo yo** abre el editor con una plantilla de gemelo digital.
- **Los borradores te esperan.** Un perfil propuesto por el asistente muestra **Propuesto: revísalo** (o **Cambio propuesto para…** si modifica uno que ya tienes) y no hace nada hasta que pulses **Aprobar**; **Descartar** lo elimina. También puedes pedir al asistente en cualquier chat que cree o mejore un perfil; usa la herramienta `persona_studio` y el resultado aparece aquí de la misma forma.
- **Nuevo perfil** abre el editor, con la opción de empezar con una plantilla (**Gemelo digital**, **Analista de patrulla**, **Asistente de escritura**). Establece un nombre visible (el nombre corto se deriva de él y no puede cambiar después, porque los chats lo usan como referencia), una línea que explique para qué sirve, **Gemelo digital** o **Asistente especialista**, **Sugerir acciones** o **Actuar en mi nombre**, el perfil del espacio de trabajo del que **Se basa en** (hereda su experiencia y acceso a herramientas; tu perfil añade instrucciones, pero no puede desbloquear herramientas que ese perfil no tenga), las instrucciones y hasta 8 patrullas sugeridas (un título, opciones rápidas de frecuencia o el editor de horarios por horas, minutos, cada día, días laborables o días concretos de la semana, un selector de zona horaria y qué hacer cada vez; con al menos 5 minutos entre ejecuciones y una opción **Cron avanzado** cuando sea necesaria). Puedes guardar hasta 50 perfiles.
- **Iniciar chat** abre un chat nuevo con ese perfil. **Iniciar patrulla** en una patrulla sugerida abre un chat nuevo con ese perfil, le añade la patrulla y ejecuta la primera comprobación de inmediato. Un perfil configurado como **Actuar en mi nombre** activa **⚡ Aprobación automática** en ese chat; uno configurado como **Sugerir acciones** mantiene las tarjetas de aprobación. En ambos casos, la autonomía es una instrucción al asistente más esa opción predeterminada; la configuración de aprobación del chat sigue determinando qué llamadas a herramientas requieren tu intervención.
- **Editar** cambia todos los chats que usan ese perfil a partir de su próximo turno. **Eliminar** mantiene esos chats; continúan con el perfil predeterminado del espacio de trabajo.
- **Perfiles del espacio de trabajo** enumera los perfiles de tu instalación: usa **Iniciar chat** en uno, o **Personalizar** para crear tu propio perfil a partir de él.

Para las presentaciones de Bento, tu instalación puede ofrecer una plantilla inicial con su marca. Puedes pedir otro tema o una presentación vacía; el diseño y el estilo de la plantilla inicial son editables. Descarga el archivo `.bento.html` y ábrelo en un navegador para verlo y editarlo sin conexión.

## 4. Cómo aportar datos

Hay cuatro formas de aportar datos a una conversación. La mayoría de los días usarás las dos primeras.

| Vía | Cómo funciona |
| --- | --- |
| **Adjuntar un archivo** | Pulsa **Adjuntar archivos** o arrastra un archivo a la conversación y pregunta sobre él en ese mismo mensaje. Se admiten hojas de cálculo, CSV, PDF, documentos e imágenes. Los archivos demasiado grandes se rechazan al elegirlos, indicando el límite, en lugar de fallar después. Un adjunto pertenece a la conversación donde se envió; una nota junto al mensaje registra lo que se añadió. |
| **Fuentes conectadas** | Buzones, API de informes y otros sistemas conectados a tu instalación. El asistente los consulta cuando se lo pides, usando solo los conectores activados para esa conversación. Nombra la fuente en tu petición; consulta [la sección siguiente](#5-connectors-in-a-conversation) para saber cómo activar los conectores. |
| **Biblioteca de archivos compartidos** | Archivos de referencia que un administrador publica una vez para todas las conversaciones: datos históricos, listas de precios o tablas de consulta. Están en **Configuración → Archivos compartidos** y el asistente los ve en todos los chats sin necesidad de volver a adjuntarlos. |
| **Archivos creados por el asistente** | Todo lo que produce en una conversación (una hoja de cálculo, un gráfico, un informe HTML o una imagen generada con el conector opcional **Generación de imágenes** (`image_generation`) activado, por defecto **Google Nano Banana 2.1**, `google/gemini-nano-banana-2.1`) permanece en el espacio de trabajo de esa conversación. Descárgalo desde la transcripción, previsualiza HTML allí mismo y pregunta por él en turnos posteriores usando su nombre. |

> **Referencias en línea, si están activadas.** Algunas instalaciones permiten escribir referencias en un mensaje: `@url:` seguido de una dirección web incorpora esa página al turno, y `@file:` seguido de un nombre de archivo incorpora un archivo creado antes por el asistente en esa conversación. Ambas funciones están desactivadas salvo que un operador las active; si una referencia no hace nada, la función está desactivada y puedes adjuntar como siempre.

En conectores que admiten entradas de archivos binarios, Fleet puede enviar directamente un fragmento de archivo del espacio de trabajo con su hash verificado. Esto evita copiar cadenas base64 grandes a la conversación y funciona sin acceso HTTP del entorno aislado. El archivo completo puede ocupar hasta 64 MiB y se envía en fragmentos de un máximo de 8 MiB; el conector puede imponer límites menores. Siguen aplicándose los permisos y las comprobaciones de publicación del conector; una subida preparada no significa por sí sola que se haya publicado una página o un documento.

El asistente guarda los archivos obtenidos por enlace (un enlace a un informe en un correo, una URL de descarga firmada devuelta por un conector o una CSV pública) en el espacio de trabajo de la conversación mediante su herramienta de descarga. Un archivo puede ocupar hasta 512 MB (si es mayor, no se guarda) y una descarga puede tardar hasta 5 minutos por defecto, con un máximo de 30. Si un enlace muestra primero una página de «tu descarga comenzará» o una página cuyo único enlace es el archivo, el asistente la sigue hasta llegar a él, con un máximo de tres páginas. Si un enlace que identifica una hoja de cálculo o un informe devuelve una página web (normalmente un inicio de sesión o un enlace caducado), se informa al asistente para que no la trate como el archivo. Se rechazan los enlaces a direcciones privadas o internas. Volver a descargar el mismo enlace reutiliza el archivo anterior si nada ha cambiado; se rechaza una descarga si deja al servidor con poco espacio libre.

## 5. Conectores en una conversación

Un conector es una conexión activa con un sistema: un buzón, una API de informes o un repositorio de documentos. Activarlo tiene dos niveles en Chat y un tercero en el Centro de operaciones.

| Nivel | Dónde | Qué determina |
| --- | --- | --- |
| Disponibilidad | **Configuración → Conexiones** | Qué conectores tienes disponibles, si cada uno está activado por defecto en chats nuevos y qué cuenta usa si dispone de varias. Se configura una vez y se mantiene. |
| Selección | El menú **Herramientas** (la llave inglesa) del editor de mensajes, su biblioteca o una tarjeta **¿Activar el conector MCP?** en el chat | Cuáles de tus conectores disponibles están activos en *esta* conversación. Limita la selección si el chat solo necesita una fuente; si una tarea necesita un conector MCP opcional del paquete que está conectado pero desactivado en esa conversación, el asistente puede proponer activarlo para que lo apruebes (o activarlo por sí solo si **Aprobación automática** está activo). |
| Asignación | El formulario de tareas de la página Tareas en segundo plano | Qué conectores puede usar una tarea programada, fijados al crearla. Un cambio posterior en tus preferencias nunca modifica una tarea existente. |

**Configuración → Conexiones** muestra inicialmente cuatro conexiones en **Incluido en tu espacio de trabajo** y las que añadiste tú en **Añadidas por ti**. Una conexión que añadiste desde **Buscar más conexiones** lleva el nombre y la descripción de su tarjeta del directorio, aquí y en el menú **Herramientas**; una que añadiste por URL con un nombre propio conserva ese nombre. Si el directorio ahora indica otra dirección para una conexión (aparece marcada con **El directorio ha cambiado**), la conexión conserva su propio nombre hasta que la elimines y la vuelvas a añadir desde el directorio. Una conexión que necesita que inicies sesión tiene un borde ámbar y muestra **Iniciar sesión** (**Volver a iniciar sesión** mientras está conectada, para renovar la sesión). **Mostrar todo** abre una ventana con todos los conectores del espacio de trabajo y los mismos controles de disponibilidad, activación en nuevos chats y cuenta predeterminada. Un enlace a un conector fuera de la vista previa abre esa ventana automáticamente. **Cuentas de credenciales** enumera las cuentas con nombre que pueden usar tus conectores (por ejemplo, una por cliente), inicialmente cuatro; **Mostrar todo** amplía la lista y **Mostrar menos** la contrae. La lista es de solo lectura: tu administrador añade y elimina estas cuentas en el servidor de Fleet (`fleet mcp account set`), y sus secretos nunca se muestran en el navegador.

**Buscar más conexiones** empieza con ocho opciones seleccionadas de **Popular**: Microsoft 365 (Outlook), GitHub, Slack, Gmail, Google Drive, Notion, Linear y Salesforce. Un espacio de trabajo con otro catálogo puede mostrar opciones distintas. Bajo el buscador, las etiquetas de categorías (**Popular**, **Todos** y filtros con recuentos) y las tarjetas **Explorar por categoría** permiten explorar conectores por categoría o ver todo el directorio agrupado por categoría, con paginación **Mostrar más** / **Mostrar todo**. Busca por nombre o palabra clave en todo el directorio o en la categoría elegida; borrar la búsqueda recupera la vista seleccionada (**Popular**, **Todos** o la categoría activa), y pulsar **Volver a Populares** vuelve a las opciones populares. Si falta el conector que quieres, usa **Contactar con Elcano** bajo el buscador para solicitarlo.

El menú Herramientas se abre con el buscador listo: escribe para filtrar por nombre, descripción, categoría o nombre de una herramienta del conector; una coincidencia interna aparece debajo, como en `↳ ix_clone_deal`. Los conectores activos aparecen primero en **Activado**; el resto, bajo sus categorías, como **SSP** o **Gestión de acuerdos**, y **Otras herramientas** al final. La lista **Activado** conserva el orden mientras el menú está abierto, para que una fila no cambie de sitio al activarla o desactivarla. `↑` y `↓` recorren la lista; `Space` o `Enter` cambia el estado del conector resaltado; `Esc` borra la búsqueda y después cierra el menú. Un conector que necesita configuración o no está disponible queda oculto hasta que una búsqueda lo encuentra; aparece atenuado, sin interruptor, y seleccionarlo lo abre en la biblioteca. **Activar todas** y **Desactivar todas** cambian todos los conectores visibles en el menú; con una búsqueda, solo afectan a las coincidencias («Los 3 activados»). El número de al lado indica cuántos están activos. El icono de ampliar junto al buscador, o **Abrir biblioteca** al pie del menú, abre la biblioteca **Herramientas y conexiones**: todos los conectores que puedes usar en Chat, con filtros de categoría y estado a la izquierda, la lista en el centro y el conector seleccionado a la derecha, con su interruptor, estado, **Mostrar N herramientas** para ver sus herramientas y **Gestionar en Configuración** para elegir si empieza activado en nuevos chats. En un teléfono o una ventana estrecha, los filtros se desplazan horizontalmente como etiquetas, y pulsar un conector abre sus detalles en otra pantalla; el botón de volver de arriba (o `Esc`) regresa a la lista. Una instalación puede reservar herramientas de conectores para tareas programadas, normalmente operaciones de escritura directa a las que Chat accede mediante un proceso revisado. Chat excluye esas herramientas del menú, la búsqueda, la lista **Mostrar N herramientas** de la biblioteca y todos los recuentos; tampoco muestra un conector **Incluido** si todas sus herramientas están reservadas. Un conector de terceros en el que hayas iniciado sesión tú mismo sí aparece, porque sus herramientas solo se conocen cuando una conversación lo abre. El asistente no puede llamar a una herramienta reservada desde una conversación, actives lo que actives. Una tarea programada sí puede; por eso, su formulario puede mostrar herramientas y conectores ausentes de Chat. Si un conector tiene varias cuentas, el menú **Cuenta** de su fila y de la biblioteca elige la de esta conversación; la predeterminada muestra el nombre de tu instalación o la cuenta elegida en **Configuración → Conexiones**. Un conector que **Requiere configuración** tiene credenciales que tu administrador añade al servidor; el enlace **Configurar en Configuración** del administrador abre allí su tarjeta. Fleet carga como máximo ocho conexiones de terceros en un turno, contando tanto las que conectaste tú como las compartidas contigo (las incluidas no cuentan). Si activas más, el turno informa al asistente de las excluidas: los diez primeros nombres y un recuento del resto, para que pueda avisarte si pides alguna. Mantén en cada conversación solo los conectores que necesita. Algunos conectores están marcados como **Siempre activado**: forman parte de la instalación, no pueden desactivarse por conversación y los dos botones no los modifican. Cada conector también indica si es **Incluido**, incluido y gestionado con la instalación, o un servicio de terceros en el que iniciaste sesión, para que sepas siempre a qué sistema accedes. Si un conector de terceros necesita un prefijo delante de su clave de API, el formulario lo indica (por ejemplo, `Authorization: Token token=<key>`); pega solo la clave. Un conector disponible desde varios servidores, como la región europea de un proveedor, muestra una opción **Punto de conexión** en su tarjeta y en el formulario **Añadir otra cuenta** de una conexión; elige la tuya antes de añadirlo. Una etiqueta **Beta** indica que funciona, pero aún necesita mejoras. Una etiqueta **El directorio ha cambiado** en una conexión de terceros en **Configuración → Conexiones** indica que la entrada del directorio con ese nombre ahora usa otra dirección, método de acceso o ubicación de clave; la fila explica qué cambia. La conexión conserva los datos con los que se añadió; elimínala y añádela otra vez desde el directorio para adoptar el cambio. No se puede conservar el inicio de sesión anterior. Una conexión configurada manualmente con un nombre del directorio también muestra la etiqueta y puede mantenerse como está.

La mayoría de las entradas del directorio se añaden con un clic y después piden iniciar sesión en el proveedor. Algunos proveedores (como Slack, GitHub o Google Workspace) no permiten que la plataforma se registre automáticamente. Si tu administrador ya configuró en el servidor la aplicación OAuth del espacio de trabajo, esas entradas también requieren solo un clic: pulsa **Añadir** e inicia sesión con tu cuenta. Si el servidor aún no tiene una aplicación compartida configurada, la entrada abre un formulario breve: muestra la **URL de retorno de autorización** que debes dar al proveedor y pide un **ID de cliente OAuth** y, si el proveedor lo exige, un **Secreto de cliente OAuth**; el formulario indica cuándo es obligatorio el secreto. El cliente procede de una aplicación registrada en el proveedor para esa URL de retorno. Sigue las instrucciones de configuración de la tarjeta; por ejemplo, en Slack, dentro de `api.slack.com/apps`, crea una aplicación interna del espacio de trabajo, añade la **URL de retorno de autorización** en **OAuth & Permissions → Redirect URLs** junto con los **User Token Scopes** que quieras y activa **Model Context Protocol** en **Features → Agents & AI Apps**. Un administrador también puede configurar una vez el ID de cliente y el secreto de esa aplicación en el servidor, para que los demás se conecten con un clic. Después del formulario, inicias sesión en el proveedor como de costumbre.

Si el servicio que necesitas no está en el directorio, o solo ofrece una API HTTP o un portal web, pulsa **Crear una conexión en el chat** en **Configuración → Conexiones** (o escribe `/connector-builder` en Chat) para abrir un chat guiado de Connector Studio. El asistente busca primero un servidor MCP oficial; si no lo hay, usa un conector API HTTP personalizado (etiqueta **API personalizado**) o uno de automatización Chromium sin interfaz (etiqueta **Automatización del navegador**, con una vista de navegador Co-Pilot opcional en directo para completar tú mismo SSO, 2FA o un CAPTCHA). Recoge las claves de API o contraseñas en un campo oculto, para que el secreto permanezca en el anfitrión, y guarda la conexión para ti o para todo el espacio de trabajo. Una vista de navegador en directo termina cuando pulsas **End Session**, cuando el asistente la cierra, tras 10 minutos sin actividad, cuando Fleet se reinicia o cuando Fleet necesita su lugar para una sesión más reciente; entonces su enlace abre una página que indica que la sesión ya no está disponible y el asistente puede abrir una nueva.

Cuando la vista de navegador en directo no puede hacer algo que le pides, una nota breve en la parte superior lo indica y, si se trata de una dirección que no abrirá (por ejemplo, una que no sea una página web), explica el motivo.

Las credenciales ocultas enviadas en un formulario del chat permanecen en el almacén temporal de esa conversación como una referencia `$secret:`. Si una llamada de conector o de navegador incluye un marcador `[REDACTED]`, o pasa una referencia `$secret:` a una tarea programada o a un conector personalizado guardado (que usan en su lugar las credenciales guardadas en la propia conexión), Fleet rechaza la llamada en vez de enviar el marcador o el texto de la referencia: vuelve a enviar la credencial en un formulario nuevo o actualiza la conexión guardada en **Configuración → Conexiones**.

Cada llamada a un conector aparece como una etiqueta en el registro de ejecución. Si una cifra parece incorrecta, abre la etiqueta y lee lo que devolvió realmente el conector antes de cuestionar el cálculo.

> **Las credenciales nunca salen de la plataforma.** El asistente usa una conexión, pero nunca ve las credenciales que hay detrás. Las claves y los tokens permanecen en el anfitrión, se incorporan a una llamada solo en el momento de realizarla y nunca entran en el entorno aislado, la conversación ni el contexto del modelo.

## 6. Tarjetas que piden una decisión

Cuando el asistente quiere hacer algo con consecuencias fuera de la conversación, se detiene y prepara una tarjeta. No ocurre nada hasta que respondas; si nadie responde, se considera un no.

Así funcionan las tarjetas de forma predeterminada. Una instalación también puede poner una herramienta en modo **notificación**, donde la llamada se ejecuta primero y la tarjeta registra lo hecho en vez de pedir permiso. Lee los botones, no solo la presencia de una tarjeta: si ofrece una decisión, está reteniendo la acción; si solo permite descartarla, te está informando. Las reglas siguientes se refieren al primer tipo.

| Tarjeta | Cuándo aparece | Tus opciones |
| --- | --- | --- |
| ¿Enviar este correo? | El asistente ha redactado un mensaje y quiere enviarlo. La tarjeta muestra remitente, asunto y destinatarios Para, Cc y Cco en líneas separadas, enumera por nombre todos los archivos enviados, incluidas imágenes insertadas (visibles aunque el cuerpo esté contraído), y muestra el cuerpo. En correos HTML que superan la altura de vista previa, o en teléfonos donde la vista contraída permite desplazar la página, pulsa **Expandir correo completo** / **Contraer vista previa del correo** para ver el mensaje completo e interactuar con él. | **Enviar** · **Cancelar** |
| Vista previa del correo | El asistente quiere mostrarte un borrador sin enviarlo, con el mismo selector de buzón **Claro** / **Oscuro**, selector de tamaño **Móvil** / **Escritorio** en pantallas anchas, **Mostrar código fuente** y controles **Expandir correo completo** / **Contraer vista previa del correo**. | **Descartar**: solo para visualizar |
| ¿Ejecutar este comando de shell? | Un comando que la plataforma considera arriesgado. | **Aprobar y ejecutar** · **Cancelar** |
| ¿Ejecutar «Connector studio»? · ¿Ejecutar «Playwright browser»? | El asistente quiere que su navegador integrado escriba, haga clic, pulse una tecla o elija una opción en una página, normalmente mientras crea una conexión. La tarjeta enumera cada paso con palabras sencillas, indica de dónde procede una contraseña (el campo del formulario que rellenaste) en lugar de mostrarla y, cuando los pasos se ejecutan en una sesión de navegador en directo, muestra el sitio donde empezó la sesión y el sitio donde está ahora su página, con una nota si no coinciden. Los argumentos propios de la llamada, con los mismos valores ocultos, están en **Detalles**. | **Aprobar y ejecutar** · **Cancelar** |
| Programar una tarea | El asistente propone una tarea programada, normalmente porque elegiste **Crear tarea recurrente…**. Consulta [Del chat a una tarea](#10-from-chat-to-a-task). | **Aprobar y programar** · **Editar** · **Cancelar** |
| Cambiar una tarea | El asistente quiere detener o actualizar una tarea programada existente. Un cambio en el prompt muestra cada edición como el texto que reemplaza y el texto nuevo, o el texto que se añade al final; el resto del prompt se conserva. Una reescritura completa muestra el prompt nuevo (uno muy largo se acorta en la tarjeta, y lo indica) bajo un aviso de que lo reemplaza todo. (El asistente puede leer el prompt actual de una tarea sin una tarjeta). | **Aprobar y detener** o **Aprobar y actualizar** · **Cancelar** |
| ¿Activar el conector MCP? | El asistente necesita uno o más conectores MCP opcionales del paquete, ya conectados pero aún desactivados en esta conversación. Aprobarlos los activa para esta conversación y reanuda la respuesta con sus herramientas disponibles. Si se alcanzó el límite horario de reanudaciones automáticas o el de la cola de entrada, aparece un aviso y las herramientas se aplican al siguiente mensaje. Con **Aprobación automática** activo, el asistente activa los conectores opcionales del paquete ya conectados sin detenerse en una tarjeta y continúa automáticamente dentro de esos límites. | **Aprobar y continuar** · **Rechazar** |
| Ejecutar una acción | Cualquier otra acción de un conector que cambie algo, como actualizar un registro en un sistema externo. La tarjeta indica la acción, el sistema donde se ejecuta y los argumentos con los que se llamó. Una instalación puede mostrarlo con lenguaje sencillo: **SE REQUIERE APROBACIÓN** con la cuenta atrás, un título, el registro con su identificador y un enlace (**Abrir en…**), cada cambio como antes → después y advertencias como «El acuerdo está activo» en etiquetas, con los argumentos originales en **Detalles**. Las listas largas muestran los 10 primeros elementos con **Mostrar N más**, y un buscador si hay más de 25. | **Aprobar y ejecutar** (**Aprobar** en una tarjeta con lenguaje sencillo) · **Cancelar** |

Tres reglas para todas las tarjetas. **Lee lo que va a ocurrir**, no solo el botón: la tarjeta existe para explicártelo. **Cancelar no cuesta nada**: el asistente continúa sin realizar la acción y puedes pedirle otra forma de hacerlo. **Las tarjetas caducan**: una tarjeta sin respuesta caduca como rechazada, y la transcripción lo registra. De forma predeterminada, una tarjeta de acción espera un día (24 horas), y una conversación o un espacio de trabajo puede ampliar ese plazo hasta 7 días.

Tras aprobar, la tarjeta muestra lo que ocurrió realmente: se ejecutó, falló, sigue ejecutándose o, si es una tarjeta antigua cuya ejecución terminó antes de guardar resultados, no se registró el resultado. Una tarjeta con lenguaje sencillo lo resume en una línea (**Aplicado**, **No aplicado**, **Rechazado**, **Tiempo agotado: no aplicado**), con el resultado propio de la acción debajo y los registros en **Detalles**. Una instalación también puede hacer que ciertas acciones informen de su propio resultado. La tarjeta terminada explica entonces en una línea lo que ha ocurrido («Creado 1 acuerdo de Index Exchange · verificado»), con una fila por registro: su nombre, sus identificadores, un estado (**Listo**, **No aplicado**, **La comprobación no coincide**, **Requiere comprobación**, **Resultado incierto**, **Ya realizado**, **No ejecutado**) y un enlace. El resultado original pasa a **Detalles**. **Requiere comprobación** significa que el registro se ha aplicado, pero ha fallado un paso posterior (por ejemplo, el acuerdo existe, pero no se añadió su lista de exclusiones); su nota explica cuál, y no se ofrece repetirlo porque el registro ya existe. Si han fallado algunos registros, **Reintentar fallidos (N)** pide al asistente que vuelva a intentar solo esos, y el reintento vuelve como una nueva tarjeta para que la apruebes: el clic no ejecuta nada. Nunca se ofrece volver a intentar un registro que quizá ya exista. Una acción ejecutada sin preguntar puede explicar lo que hizo del mismo modo («Campaña ID ELC07375 asignada»). Una tarjeta que sigue ejecutándose no es una nueva decisión: no muestra Cancelar, Editar ni la cuenta atrás de caducidad, y **Comprobar resultado** consulta el resultado sin ejecutar la acción dos veces. En el chat de terminal se aplican los mismos indicadores: `/approve <id>` en una tarjeta en ejecución obtiene el resultado; un resultado histórico desconocido se trata como error, no como éxito.

Por defecto, una acción aprobada de un conector (una tarjeta **Ejecutar una acción** o un envío de correo) tiene un minuto para terminar. La instalación puede dar más tiempo a conectores lentos, por ejemplo para crear o actualizar registros externos. Si una acción así sigue ejecutándose tras unos 50 segundos, se muestra enseguida como en curso en lugar de bloquear la página; usa **Comprobar resultado** un poco después para consultar el resultado. Los comandos de shell y las tarjetas de tareas mantienen sus propios límites.

Una instalación también puede hacer que determinadas acciones **informen de su progreso** durante su ejecución, por ejemplo al crear muchos registros externos. La tarjeta en ejecución muestra entonces una barra y una línea como **12 de 24 · creando el acuerdo 12**, actualizadas cada pocos segundos mientras la pestaña está abierta y conservadas al recargar; al terminar, cambia sola al resultado, sin usar **Comprobar resultado**. Si activaste las notificaciones del navegador (**Configuración → General → Notificaciones del navegador**), también recibes una cuando termina una acción de este tipo (**✓ Completado** o **✗ No aplicado**, con el título de la tarjeta) y cuando el asistente no pudo continuar por sí solo después de aprobar, rechazar o agotar el tiempo de una tarjeta. Pulsarla abre la conversación en tu pestaña de Chat si la tienes abierta (se recarga y se pierde cualquier mensaje sin enviar), o en una nueva. Safari en Mac no abre nuevas pestañas desde notificaciones; tras un momento, abre la última pestaña de Fleet que usaste y también la recarga. Si no hay ninguna pestaña de Fleet abierta, el clic no abre nada.

Las notificaciones del navegador corresponden a la cuenta que las activó en él. Cerrar sesión desde el menú de cuenta las desactiva allí, para que la siguiente persona no reciba las tuyas. Cerrar la pestaña o dejar caducar la sesión no las desactiva; cierra sesión en un ordenador compartido. El interruptor indica si este navegador recibe notificaciones de **tu**; si otra persona las activó o ya no están registradas para ti, aparece desactivado y puedes volver a activarlo.

Una instalación también puede **agrupar** ciertas acciones, por ejemplo reservar el mismo plan en varios sistemas externos. Si el asistente pide dos o más en una respuesta, llegan en una tarjeta titulada **N acciones para aprobar**, con una fila por acción, su casilla, su tarjeta con lenguaje sencillo o sus argumentos, y la cuenta con la que se ejecuta. **Aprobar todas (k)** ejecuta las k acciones marcadas y rechaza las no marcadas en una sola decisión; **Cancelar todas** las rechaza todas; **De una en una** muestra las tarjetas individuales habituales. La cuenta atrás muestra el plazo más cercano; si se agota, el aviso ofrece **Revisar de una en una** para volver a las tarjetas individuales, reintentar las caducadas y decidir sobre las pendientes. Tras decidir, cada acción muestra su propio resultado (en ejecución, aplicada o rechazada), como si hubieras decidido en su tarjeta individual.

Una instalación también puede permitirte **detener** algunas acciones en curso, como un plan que procesa muchos acuerdos. Su tarjeta en ejecución tiene entonces un botón **Detener**, que pide al conector detenerse tras el registro actual; la tarjeta muestra **Detención solicitada** hasta que termina la acción. Depende del conector que se detenga ahí; el resultado final indica qué se ejecutó. Una tarjeta terminada sin resumen propio de resultado se titula **Detención solicitada**, nunca **Aplicado**. Si el conector resume su resultado, la tarjeta terminada indica hasta dónde ha llegado (por ejemplo, «Detenido tras 12 de 24») y ofrece **Ejecutar los N restantes**, que pide al asistente ejecutar los registros que no llegó a procesar; esa acción vuelve como una tarjeta nueva para que la apruebes. Si el conector no permite detenerse, la acción continúa hasta el final y la tarjeta lo indica en su resultado.

La instalación también puede permitirte **excluir registros** de una acción que abarque varios, como un plan que actualiza muchos acuerdos. La tarjeta con lenguaje sencillo muestra entonces una casilla en cada registro, todas marcadas, y un recuento como **3 de 3 seleccionados**. Desmarca un registro para excluirlo: se atenúa y muestra **Excluida**; el botón pasa a **Aprobar 2 de 3**, que ejecuta la acción solo para los registros marcados con un clic. Nada más cambia en la acción, y nunca puede añadir un registro que no hayas visto. Desmarcar todos los registros convierte el botón en **Rechazar**. En una tarjeta agrupada, los registros de cada acción tienen sus propias casillas; si ninguno está marcado, se rechaza esa acción. Tras aprobar, la tarjeta indica **Aprobados 2 de 3 · 1 excluido** y marca el registro excluido; el asistente recibe la lista de los que excluiste. En el chat de terminal, `/approve` aprueba la acción completa.

La instalación también puede hacer que el asistente **continúe por sí solo** cuando decidas una tarjeta de ciertas acciones, como actualizar un registro externo, para comprobar el resultado y seguir sin que escribas «hecho». Si una acción aprobada falla y no pulsaste **Detener**, el asistente inicia automáticamente un turno de recuperación para diagnosticar el error y corregirlo o reintentarlo. Un par de segundos después de aprobar, rechazar o caducar una tarjeta (o de recibir el resultado si seguía ejecutándose), empieza un nuevo turno por sí solo. Empieza con una línea atenuada **Continuación automática tras una aprobación; no lo has escrito tú**; **Mostrar** revela la nota exacta que recibió el asistente. Si apruebas o rechazas con el chat abierto, se transmite como cualquier respuesta; un turno iniciado por caducidad aparece al volver a la pestaña o recargar. Si hay varias tarjetas de este tipo pendientes, espera a que decidas todas y continúa una sola vez. Si ya hay un turno en ejecución, espera detrás como un elemento **continuación automática** en la cola bajo el editor, que puedes quitar. Nunca aprueba nada en tu nombre: cualquier acción posterior que necesite aprobación muestra una tarjeta nueva. Por defecto, un chat continúa solo como máximo 10 veces por hora; si supera ese límite o Fleet se reinició antes de poder continuar, una nota breve lo indica y debes enviar un mensaje para seguir.

Algunas tarjetas incluyen una casilla que extiende tu decisión a todas las llamadas posteriores del mismo tipo en esta conversación; el botón pasa a **Aprobar y permitir todo**. Déjala sin marcar salvo que sepas exactamente qué hará el resto de la conversación. La instalación puede desactivar esa casilla en acciones que siempre necesiten tu decisión; sus tarjetas no la muestran y cada llamada tiene su propia tarjeta. También puedes activar **Aprobación automática** para la conversación actual desde **Más opciones** (`•••`) en la barra del editor, incluso durante una respuesta. Mientras está activo, un icono de rayo permite desactivarlo con un clic. Las acciones ejecutables de conectores y los comandos de shell se ejecutan sin tarjeta, pero el envío de correos, las tarjetas de tareas programadas y las acciones que siempre requieren una decisión siguen preguntando. Las tarjetas no sirven para explorar qué cambiaría una acción; pide primero al asistente que describa el cambio y aprueba la tarjeta cuando estés de acuerdo.

La instalación, no el asistente, determina qué herramientas requieren aprobación y cuáles solo informan; conviene conocer la diferencia antes de actuar sobre un sistema externo. Tu administrador puede explicártelo.

### Dos tarjetas de sugerencias

**Recuerdos propuestos.** Cuando el asistente aprende algo sobre ti o tu trabajo que merece conservarse, propone un recuerdo en vez de guardarlo: **Guardar** o **No guardar**. La tarjeta muestra su destino, **Guardar en: Mis recuerdos** o **Aprendizajes del equipo**; en un proyecto compartido con el equipo, Aprendizajes del equipo está seleccionado de antemano y puedes cambiarlo. Consulta [Recuerdos y proyectos](#7-memory-and-projects).

**Sugerencias de modelo.** Si una pregunta supera lo que el modelo actual resuelve bien, o una respuesta tuvo dificultades claras, una tarjeta ofrece **Cambiar y reintentar**, **Solo cambiar** o **Descartar**, salvo que ya haya una tarjeta de aprobación de acción pendiente. Rechazar no cuesta nada; después de descartar una sugerencia, no verás otra durante varios mensajes. Si cambias de modelo y luego vuelves al rápido, puede aparecer otra sugerencia.

### Tarjetas interactivas

Cuando una respuesta visual funciona mejor que el texto, el asistente puede crear una tarjeta al momento: un formulario con varios datos, una lista donde añadir, duplicar o quitar elementos, opciones obtenidas de un sistema conectado, una lista de comprobaciones correctas o pendientes, una tabla para seleccionar filas, un gráfico o una calculadora cuyos totales cambian al escribir. El asistente decide cuándo ayuda una tarjeta; también puedes pedirla directamente («dame un formulario para esto»).

- **Complétala y pulsa su botón.** Los campos con asterisco rojo son obligatorios; la tarjeta indica cuántos necesitan corrección y te lleva al primero. Un enlace **Corregir** junto a una línea de la lista de comprobación lleva al campo correspondiente. Las calculadoras, listas de comprobación y tarjetas de simulación independientes actualizan totales, gráficos y barras de progreso mientras cambias las entradas, sin enviar mensajes. Pueden ofrecer **Copiado** para copiar un resumen con formato o **Restablecer** para restaurar los valores predeterminados. Al cambiar una entrada de una tarjeta editable, también aparece **Restablecer** en su cabecera si no hay un botón de restablecer utilizable en el pie; restaura los valores iniciales y borra el borrador guardado.
- **Tus respuestas se convierten en tu siguiente mensaje.** Pulsar un botón envía lo que introdujiste como un mensaje normal, con un resumen del nombre de la tarjeta, el botón pulsado y tus respuestas; **Mostrar lo enviado** revela el texto exacto. Si no pudo enviarse, el resumen indica **Sin enviar** y la tarjeta sigue abierta para reintentarlo. La tarjeta en sí nunca actúa: el asistente lee tus respuestas y continúa, y cualquier acción posterior que necesite aprobación sigue mostrando su tarjeta de aprobación habitual.
- **Algunos botones preguntan primero.** Un botón que pide confirmación antes de enviar muestra **Sí** y **Atrás** en su lugar; **Atrás** (o `Escape`) permite volver sin enviar.
- **Una tarjeta enviada queda bloqueada.** Mantiene tus respuestas en pantalla. **Editar y reenviar** la desbloquea para cambiar algo y reenviar; **Cancelar edición** restaura lo que enviaste.
- **Una tarjeta espera a que llegue su respuesta.** Si el asistente sigue respondiendo o la conexión se interrumpió al pulsar, la tarjeta muestra **Enviado · … — esperando a llegar al asistente** y mantiene desactivados botones y campos para evitar el envío duplicado. **Desbloquear** las desbloquea si aun así quieres volver a enviarlas. Si la respuesta nunca llega (la conexión vuelve y no está, o la quitas de la cola bajo el cuadro de mensaje), la tarjeta se desbloquea sola e indica **No enviado. Vuelve a intentarlo.**
- **Una elección única opcional se puede deshacer.** Una lista de opciones redondas muestra **Borrar elección** después de elegir una, y una tabla de selección de una sola fila muestra **Borrar selección**, si la pregunta es opcional.
- **Las tarjetas actualizadas sustituyen a las anteriores.** Si el asistente revisa tus respuestas y vuelve con una versión corregida, la tarjeta anterior se contrae en una nota de una línea (**Mostrar** la abre), y los problemas se señalan en los campos de la nueva.
- **Las respuestas sin enviar se conservan en este navegador** mientras te desplazas o recargas, hasta que las envíes, durante un máximo de 7 días y para las 20 tarjetas editadas más recientemente. Enviar desde una tarjeta no modifica lo que estás escribiendo en el cuadro de mensaje.
- **No se envían respuestas demasiado grandes.** Si tus respuestas, normalmente una lista larga pegada, son demasiado grandes para un mensaje, la tarjeta lo indica y no envía nada. Acorta la lista y vuelve a pulsar el botón.
- **Las tarjetas anteriores a una compactación son de solo lectura.** Tras compactar una conversación (consulta [Conversaciones largas](#long-conversations)), no puedes responder a una tarjeta de la parte resumida, porque el asistente ya no tiene sus detalles. Pídele que vuelva a mostrar la tarjeta.

Las tarjetas interactivas solo aparecen en Chat en la aplicación web. Las tareas programadas nunca las muestran. El chat de terminal nombra la tarjeta y dirige al chat web; los clientes de editor conectados por ACP solo muestran la llamada original a la herramienta, así que abre la conversación en la web para usar la tarjeta. Una vista compartida o de solo lectura muestra las respuestas que enviaste, pero no la tarjeta.

## 7. Recuerdos y proyectos

Dos formas de dar al asistente un contexto que conserva. Los recuerdos son tuyos y te acompañan en todas las conversaciones. Un proyecto se comparte con tu equipo y orienta todas las conversaciones que contiene.

### Recuerdos

Un recuerdo es un dato breve que recibe el asistente al principio de cada conversación: una preferencia, una regla permanente o algo de contexto sobre tu trabajo. Tus recuerdos son personales; los chats de otras personas no los ven. Un proyecto añade un segundo tipo, compartido, que se explica a continuación.

Hay cuatro formas de añadir recuerdos. Puedes escribir uno en el gestor. Puedes pedir al asistente que recuerde algo en una conversación, y propondrá el recuerdo como una tarjeta para que elijas **Guardar** o **No guardar**. Puedes pulsar **Guardar** al pie de cualquier respuesta para conservar lo que acaba de decir el asistente, sin escribir un turno de «recuerda esto». La plataforma también puede proponer recuerdos detectados tras un turno; aparecen como **Propuesto** en el gestor hasta que los aceptes. Nada se guarda como recuerdo sin tu permiso, salvo lo que escribas tú mismo.

Abre **Recuerdos** desde **Más opciones** (`•••`) en el editor de mensajes o desde **Configuración → Recuerdos**. En un chat de proyecto, el gestor tiene dos pestañas: **Mis recuerdos** y **Aprendizajes del equipo**. Cada recuerdo indica de dónde procede (**Manual**, **Guardado desde el chat** o **Extraído automáticamente del chat**) y ofrece estas acciones:

| Acción | Qué hace |
| --- | --- |
| **Fijar** | Se entrega siempre primero al asistente y queda protegido frente a su sustitución por un recuerdo más reciente. Úsalo para las reglas que nunca deben dejar de aplicarse. |
| **Retirar** | Conservarlo en el registro, pero dejar de entregárselo al asistente. Retirar no significa afirmar que el dato dejó de ser cierto; significa dejar de citarlo. Es lo adecuado para cualquier información desactualizada. |
| **Restaurar** | Volver a usar un recuerdo retirado. |
| **Mover a los aprendizajes del equipo** | Mueve un recuerdo personal a los aprendizajes del equipo de un proyecto para que lo reciban los chats de todos sus miembros en ese proyecto. Se mueve en vez de copiarse: el recuerdo deja de aplicarse a tus conversaciones fuera del proyecto y no se entrega dos veces al asistente dentro de él. Si una regla debe acompañarte a todas partes y también servir al equipo, conserva el recuerdo personal y añade un aprendizaje del equipo por separado. Si perteneces a varios proyectos, eliges a cuál. |
| **Eliminar** | Eliminarlo por completo. |

> **Los buenos recuerdos son reglas, no datos.** «Los nombres de los acuerdos pueden contener errores tipográficos intencionados; nunca los corrijas» es un recuerdo. La cifra de gasto de hoy no lo es. Los recuerdos definen cómo quieres que se haga el trabajo; los datos pertenecen a las fuentes.

### Proyectos

Un proyecto es un espacio para un conjunto de trabajo relacionado: una cuenta, una campaña o una familia de informes. Contiene **instrucciones** que sigue cada conversación del proyecto y **aprendizajes del equipo**, un recuerdo compartido que todos los miembros pueden leer y ampliar. Todas las conversaciones del proyecto, iniciadas allí o trasladadas después, reciben ambos; así, el equipo no tiene que volver a explicarse en cada chat. Las conversaciones de un proyecto quedan excluidas de la regla de caducidad.

Cada conversación de un proyecto recibe tres capas de contexto, por este orden: las instrucciones del proyecto, sus aprendizajes del equipo y tus propios recuerdos. Solo el propietario establece las instrucciones; cualquier miembro puede escribir aprendizajes del equipo.

### Crear uno

**Nuevo proyecto** (el **+** junto a **Proyectos** en la barra) pide un nombre, instrucciones opcionales y **Quién puede verlo**: **Solo tú** (proyecto privado) o tu equipo. Al compartirlo con tu equipo, todos ven las instrucciones, los aprendizajes y los chats compartidos con ellos; pero cada chat sigue siendo **Solo tú** hasta que su propietario lo comparta. Debes pertenecer a un equipo para que aparezca esa opción. Los equipos se configuran en **Configuración → Equipo** y un administrador añade a los miembros; si la instalación usa Auth central para iniciar sesión, el administrador hace ambas cosas allí. Al crear un proyecto, se abre su página principal. Las mismas opciones están disponibles después en **Configuración del proyecto** (el engranaje de la página del proyecto o su menú en la barra), que solo puede abrir el propietario.

El propietario puede transferir el proyecto a otro miembro con **Transferir…**, para que siga existiendo cuando deje de participar; la transferencia está disponible una vez compartido el proyecto. Sigues usando el proyecto como miembro del equipo; si has dejado ese equipo, la transferencia también termina tu acceso y tus chats vuelven a ser temporales. El panel de transferencia indica qué caso se aplica. Eliminar un proyecto pide confirmación y enumera lo que se elimina con él: los aprendizajes del equipo y cuántos chats de otras personas salen del proyecto y vuelven a ser temporales; ofrece **Exportar primero**. Cambiar un proyecto compartido a **Solo tú** muestra, antes de guardar, cuántos chats pasan a Solo tú y cuántos chats de compañeros vuelven a sus conversaciones sin proyecto. Ninguna de las dos acciones elimina conversaciones; los chats siempre permanecen con su propietario.

### La página del proyecto

La barra muestra todos los proyectos visibles: primero los fijados y después el resto según su última creación o edición (nombre, configuración o uso compartido); chatear en un proyecto no lo mueve hacia arriba. Si la lista supera el espacio disponible, la sección **Proyectos** se desplaza de forma independiente, igual que **Chats** debajo.

Abre un proyecto desde la barra para acceder a su página principal. Junto al título, una etiqueta indica quién puede verlo: **Solo tú** o **Compartido con** tu equipo; si está compartido, explica qué ve el equipo. Hasta que compartas un chat del proyecto, una breve **tarjeta de primeros pasos** explica los siguientes pasos (compartir el proyecto, añadir instrucciones, compartir un chat), cada uno con un botón para hacerlo. **×** la oculta por ahora; en un proyecto personal, **Mantener privado** la oculta definitivamente. Después, de arriba abajo:

| Área | Qué contiene |
| --- | --- |
| **Tus chats** | Tus conversaciones de este proyecto, con el número de las compartidas con el equipo y un buscador limitado al proyecto. Cada fila tiene una etiqueta, **Solo tú** o el nombre del equipo, y una marca **En directo** si el modo **Chat colaborativo** está activo. Cámbiala para compartir o dejar de compartir el chat y sus archivos; **Más opciones para compartir…** abre el diálogo de compartir. En un proyecto compartido, **Nuevo chat** pregunta si el nuevo chat empieza como **Solo tú** o compartido con el equipo. |
| **Compartido por tu equipo** | Conversaciones que tus compañeros han compartido en este proyecto, con su propietario y fecha. Abre un chat compartido de solo lectura para leerlo o bifurcarlo, o uno marcado **En directo · Colaborativo** para participar directamente en la conversación en vivo; consulta [Compartir con tu equipo](#sharing-with-your-team). Una fila que ya hayas bifurcado indica **Has creado una rama de este chat** y sigue abriendo el chat actual del propietario. |
| **Instrucciones** | Las instrucciones permanentes. El propietario puede editarlas. |
| **Aprendizajes del equipo** | Una fila por aprendizaje, con quién lo escribió y cuándo. **Nuevo aprendizaje del equipo** añade uno. El menú de la fila contiene **Fijar**, **Editar**, **Retirar** o **Restaurar**, y **Eliminar**. La misma lista es la pestaña Aprendizajes del equipo del gestor de recuerdos, para que puedas mantenerla sin salir de una conversación. |
| **Fuentes** | Archivos agrupados por chat. En un proyecto compartido aparece primero **De tu equipo**, con los archivos que compartieron los compañeros y que se pueden descargar; después, **Tus chats**. Cada grupo tuyo indica cuántos archivos contiene y, si el chat está compartido con el equipo, cuántos están compartidos; el interruptor de un archivo cambia su uso compartido y la flecha lo descarga. Los archivos que subiste y tus habilidades personales nunca aparecen aquí, ni tampoco los archivos ocultos o internos (cuyo nombre empieza por un punto), salvo que el asistente te haya presentado alguno en una respuesta. Las copias procedentes de una bifurcación llevan la etiqueta **Tu copia**. Cada sección enumera los 50 chats con archivos de actividad más reciente; si hay más, el panel indica que solo muestra los archivos más recientes. |

Los permisos en una frase: **los miembros gestionan sus propios aprendizajes; el propietario los gestiona todos.** Retirar es la opción habitual cuando un aprendizaje deja de ser cierto. Deja de entregarse al asistente, pero se conserva el registro de lo aprendido y de quién lo escribió.

> **Qué debe guardarse como aprendizaje del equipo.** El mismo criterio que para los recuerdos personales, aplicado al equipo: reglas y contexto, no datos. «El cliente quiere que los nombres de los acuerdos se muestren exactamente como aparecen en el informe de origen» es un aprendizaje. Las cifras de esta semana no lo son. Si todos repiten un aprendizaje en los chats del proyecto, conviene dejarlo por escrito.

Puedes mover cualquier conversación a un proyecto con **Mover a un proyecto** y sacarla con **Quitar del proyecto**, que confirma que volverá a ser temporal y ofrece **Fijar y quitar** para evitar una caducidad accidental. Si un proyecto supone más estructura de la que necesitas, las **etiquetas** son una opción más ligera: etiqueta conversaciones desde su menú y filtra la barra por etiqueta. Las etiquetas organizan; no contienen instrucciones ni aprendizajes.

## 8. Conservar, organizar y compartir conversaciones

Cada conversación de la barra tiene un menú en el botón `⋮` que aparece al pasar el cursor. Estas son todas sus opciones.

| Opción | Qué hace |
| --- | --- |
| **Fijar** | Conservarla indefinidamente y mostrarla en **Fijados**. Fija cualquier conversación que no quieras perder. |
| **Cambiar nombre** | Las conversaciones reciben un título a partir de su primer intercambio. Renombra las que conserves para que la barra sea una lista de trabajos, no de primeras frases. |
| **Mover a un proyecto** | Guardarla dentro de un proyecto. La conversación recibe el contexto de ese proyecto a partir de su siguiente turno. |
| **Etiquetas** | Añadir o quitar etiquetas. Las etiquetas también sirven de filtros en la barra. |
| **Descargar chat** | Exporta la conversación en uno de tres formatos: **Página web**, que se abre en cualquier navegador, se parece al chat y permite imprimir a PDF; **Documento de texto**, para pegar en correo, Word o Docs; o **Datos sin procesar**, el registro completo para desarrolladores. **Incluir el trabajo del agente** añade llamadas a herramientas, resultados y razonamiento; está desactivado por defecto para que un chat largo se descargue como conversación, sin todos sus detalles de ejecución. |
| **Crear tarea recurrente…** | Pide al asistente que convierta esta conversación en una tarea programada. Consulta [Del chat a una tarea](#10-from-chat-to-a-task). |
| **Guardar como flujo de trabajo** | Convierte toda la conversación en una plantilla reutilizable de flujo de trabajo en la biblioteca de prompts o en una **Habilidad del agente (`/skill-name`)** personal. Consulta [Del chat a una tarea](#10-from-chat-to-a-task). |
| **Compartir…** | Abre el diálogo de compartir: primero con tu equipo y después **Compartir fuera de tu equipo** (un enlace público). Consulta [Compartir con tu equipo](#sharing-with-your-team). |
| **Seleccionar** | Entra en el modo de selección para fijar, etiquetar o eliminar varias conversaciones a la vez. Si la selección incluye chats compartidos con el equipo, la confirmación de eliminación indica cuántos son y que el equipo perderá esos chats y sus archivos compartidos; quienes los bifurcaron conservan sus copias. |
| **Archivar** | Apartarla sin eliminarla. Las conversaciones archivadas nunca caducan y se pueden recuperar desde el grupo **Archivados**. Archivar un chat compartido con el equipo deja de compartirlo; primero pide confirmación e indica cuántos archivos están compartidos. Al desarchivarlo, vuelve como **Solo tú**. Un chat archivado no se puede compartir con el equipo; primero debes desarchivarlo. |
| **Eliminar** | Eliminar la conversación y todo lo que produjo. Se pide confirmación y no se puede deshacer. Si el chat está compartido con el equipo, la confirmación explica qué perderá; los compañeros que lo bifurcaron conservan sus copias. |

> **Qué caduca y cuándo.** Una conversación sin fijar, fuera de un proyecto, sin archivar y sin compartir se elimina tras un período de inactividad: 14 días, salvo que el operador haya establecido otro plazo. También existe un límite por persona de conversaciones sin fijar; en una cuenta muy activa, las más antiguas pueden desaparecer antes de que se cumpla el plazo. Fijar, archivar, mover a un proyecto o compartir una conversación la excluye de ambos límites.

### Ordenar tus chats

Los chats fijados y los de un proyecto empiezan ordenados del más reciente al más antiguo. Para darles tu propio orden:

- **Chats fijados:** pulsa **Reordenar** en la cabecera **Fijados**.
- **Chats de un proyecto:** abre el menú `⋮` del proyecto y elige **Reordenar chats**.

Cada chat muestra entonces un par de flechas. Arrastra un chat donde quieras o pulsa sus flechas de subir y bajar, que también funcionan con el teclado y en teléfonos. Cada movimiento se guarda inmediatamente en tu cuenta, de modo que el orden es el mismo en todos los dispositivos donde inicias sesión. Pulsa **Listo** (o `Esc`) para volver a las filas normales.

Un chat que fijas o añades al proyecto por primera vez aparece arriba, por encima de los ordenados, hasta que lo muevas; si lo desfijas o lo sacas y después lo devuelves, recupera su lugar anterior. **Reordenar** está disponible para un máximo de 500 chats a la vez y no para cuentas de solo lectura, que no pueden guardar un orden. En un proyecto ordenas tus propios chats; cada compañero ordena los suyos.

Los chats **Temporales** usan en cambio un orden automático desde el menú de la cabecera: **Actividad reciente** (predeterminado), **Más recientes primero** (por fecha de inicio) o **Título A–Z**. La elección se recuerda en este dispositivo. Los chats temporales caducan si no se usan, así que se ordenan automáticamente; para darle un lugar propio a uno, fíjalo o muévelo a un proyecto.

### En la transcripción

**Editar mensaje** en uno de tus mensajes permite cambiarlo y reenviar desde ese punto. Al pie de cualquier respuesta aparecen **copiar** y **bifurcar**; bajo la última también aparecen **regenerar** (volver a preguntar, opcionalmente con otro modelo) y **Reintentar con** el modelo más potente (preguntar con él y conservarlo para el resto del chat). **Crear rama** inicia una conversación nueva e independiente con todo lo ocurrido hasta esa respuesta, para explorar una alternativa sin modificar la original. Bifurca si quieres conservar ambos caminos; edita si la versión anterior era simplemente incorrecta. Las dos acciones de guardar del pie, **Guardar como flujo de trabajo** y **Guardar**, se explican en [Del chat a una tarea](#10-from-chat-to-a-task) y [Recuerdos y proyectos](#7-memory-and-projects).

### Compartir con tu equipo

Compartir una conversación con tu equipo permite difundir un buen trabajo. Un chat se comparte con un equipo solo cuando está en un proyecto compartido con ese equipo **y** su propietario lo comparte; compartir el proyecto nunca comparte sus chats por sí solo.

**El diálogo de compartir** (**Compartir este chat** dentro de **Más opciones** `•••` en el editor, la etiqueta de visibilidad de la cabecera o **Compartir…** en el menú del chat) muestra siempre primero tu equipo y ofrece un botón que resuelve todo según tu situación:

| Situación | El botón |
| --- | --- |
| El chat no pertenece a ningún proyecto | **Mover y compartir** a un proyecto ya compartido con tu equipo, o **Crear proyecto compartido** si aún no hay ninguno; el chat se mueve allí y se comparte. |
| El chat pertenece a un proyecto personal | **Compartir primero el proyecto** abre la página del proyecto con la confirmación visible; después, la tarjeta de primeros pasos permite compartir el chat con un clic. |
| El chat pertenece a un proyecto compartido con tu equipo | **Compartir con tu equipo**. **Incluye N archivos · Elegir…** permite desmarcar archivos antes de compartirlos. |
| El chat está compartido | **Copiar enlace para tu equipo**, además de **Dejar de compartir**, que pide confirmación e indica cuántos archivos dejarán de compartirse cuando puede contarlos. |
| No perteneces a un equipo | Aún no hay con quién compartir; el diálogo explica cómo unirte a un equipo. |

**Qué se comparte.** Tus mensajes, las respuestas del asistente y los **archivos que el asistente presentó en sus respuestas** (los enlaces a archivos del chat), incluidos los que presente después, porque un chat compartido se mantiene actualizado. Los archivos que desmarques siguen sin compartirse, aunque desactives y reactives el uso compartido o archives y desarchives el chat. Los archivos que subiste nunca se comparten; tampoco se comparten los archivos que el asistente escribió sin presentarlos. Se excluyen las llamadas a herramientas, sus resultados y el razonamiento. En tu propio chat compartido, cada enlace de archivo indica **Compartido** o **No compartido**; púlsalo para gestionar los archivos en **Fuentes** del proyecto.

Se comparte **en modo de solo lectura**: cada conversación tiene un único propietario y lo que haga un compañero no modifica la tuya. Tus compañeros ven los mensajes nuevos mientras sigues trabajando.

**El enlace para tu equipo** solo abre para miembros del equipo con sesión iniciada, en la vista de solo lectura. Cualquier otra persona solo ve que el chat está compartido con tu equipo; un compañero sin sesión iniciada pasa por el inicio de sesión y llega directamente al chat. Cuando un chat deja de compartirse, su enlace lo indica.

**Cuándo termina el uso compartido.** Una conversación compartida con el equipo siempre tiene un lugar: el proyecto donde está. Moverla a otro proyecto compartido con el mismo equipo mantiene el uso compartido. Moverla a cualquier otro lugar, sacarla del proyecto, archivarla o eliminarla termina el uso compartido; cada acción pide confirmación e indica cuántos archivos compartidos se verán afectados. Hacer personal el proyecto, eliminarlo o dejar el equipo también termina el uso compartido. Mover un chat a un proyecto compartido nunca lo comparte por sí solo; la confirmación ofrece **Compartir con** tu equipo.

**Compartir fuera de tu equipo** es el enlace público independiente: cualquiera que tenga la URL puede leer la transcripción, pero nunca los archivos.

**Leer el chat de un compañero.** Ábrelo desde **Compartido por tu equipo** en la página del proyecto o desde un enlace que te hayan enviado. Ves la transcripción con el nombre del propietario; los archivos compartidos se descargan en su versión actual y los que no compartió aparecen como nombres bloqueados. En el lugar del editor aparece una sola acción: **Crear rama para continuar en tu propio chat**. Crea una conversación privada tuya en el mismo proyecto, con todo el contenido de la transcripción, y **los archivos compartidos se incluyen como copias tuyas**; el asistente de tu bifurcación puede usarlos. Tus copias nunca cambian después, aunque el original deje de compartirse o se elimine. Al abrir un chat que ya bifurcaste, un aviso enlaza a tu copia e indica si el propietario añadió mensajes después; **Crear otra rama** inicia una nueva bifurcación de la versión actual.

**Modo de chat colaborativo.** Para los equipos que quieren trabajar juntos en la misma conversación en directo, el diálogo de compartir incluye una sección **Modo colaborativo** (**Activar** / **Desactivar**). Los chats nuevos empiezan como **Solo tú** de forma predeterminada, salvo que un administrador haya activado **Chat colaborativo de equipo de forma predeterminada** en **Configuración → Administración → Funciones** (`FLEET_TEAM_CHATS_SHARED_BY_DEFAULT`). En ese caso, los nuevos chats sin proyecto o de proyectos de equipo, fuera del modo restringido y creados por miembros del equipo, empiezan automáticamente en **Modo colaborativo**. Los chats creados en un proyecto personal siguen siendo privados hasta que se active el modo Chat colaborativo en el diálogo Compartir. Cuando el modo de chat colaborativo está activo:

- Los compañeros y las demás personas añadidas al chat lo ven en **Chats de equipo** en la barra con una etiqueta **En directo**, pueden abrirlo directamente en la vista de chat y enviar mensajes al hilo compartido.
- Cada mensaje muestra el correo del remitente encima de su burbuja, y cada turno se ejecuta con **la propia cuenta del remitente**: usa el correo, los recuerdos personales, las habilidades, las cuentas de conectores y las tarjetas de aprobación del remitente. Como las llamadas a herramientas, el razonamiento y el resumen de tokens y coste pertenecen a la persona cuyas credenciales ejecutaron el turno, activar **Mostrar detalles** muestra **Detalles ocultos en los turnos de otros usuarios** en los turnos iniciados por otra persona.
- Por defecto, puede participar todo el equipo o espacio de trabajo del propietario. En **Personas que pueden participar** del diálogo de compartir, el propietario puede quitar personas con `×`, restaurarlas con `+` o invitar a alguien con **Añadir persona por correo**.

### Mientras se ejecuta un turno

**Detener** detiene el turno actual; la respuesta parcial queda en la transcripción, marcada como **Turno detenido.** y con **Reintentar** en el último turno, incluso después de recargar. Los turnos que la plataforma termina antes de tiempo se marcan igual: por alcanzar el límite por turno (4 horas por defecto), el límite de coste o tokens, o por un reinicio del servidor, que además incluye una nota explicativa. Escribir y enviar durante un turno no lo interrumpe: el mensaje espera en una cola bajo el editor, con **Enviar ahora** para adelantarlo y un control para quitarlo. Los mensajes en cola se ejecutan por orden cuando termina el turno actual, cada uno como su propio turno visible; la cola se conserva al recargar o cambiar de chat.

### Conversaciones largas

A medida que crece una conversación, **Resumir mensajes anteriores** en **Más opciones** (`•••`) muestra lo lleno que está el chat como porcentaje de la ventana de contexto del modelo. Con **Mostrar detalles** activo, una línea de totales sobre el editor muestra el mismo porcentaje junto al coste acumulado de la conversación. Cuando la conversación se llena, un aviso lo indica y el asistente empieza a tardar más y a costar más por turno. **Resumir mensajes anteriores**, en **Más opciones** o en el aviso, sustituye los turnos antiguos por un resumen breve para que la conversación vuelva a caber cómodamente; la transcripción conserva su historial y solo se reduce la vista de trabajo del asistente. Si la conversación cambia mientras se escribe el resumen, por ejemplo por una respuesta desde otra pestaña o un reintento, no se guarda y el chat indica *«La conversación cambió mientras se resumía, por lo que no se guardó el resumen. Vuelve a resumirla».* Vuelve a resumir para incluir su estado actual. No necesitas vigilarlo: por defecto, cuando una petición alcanza cerca del 90 % del límite del modelo, la plataforma resume por sí sola la parte más antigua de esa vista, entre turnos o en medio de uno largo que sigue obteniendo datos; una nota en la respuesta lo indica. Si un modelo sigue rechazando una petición por ser demasiado larga, la plataforma resume y reintenta sola en lugar de dar el turno por fallido. Si el tema cambia por completo, empezar otra conversación es más barato y claro que compactar la anterior.

## 9. La biblioteca de prompts

La biblioteca es donde se guarda un prompt terminado. Los prompts se crean en los chats, se ejecutan en las tareas y se guardan en la biblioteca, el lugar que ambos consultan.

Hay una única biblioteca, accesible desde tres lugares: **Biblioteca de instrucciones** dentro de **Más opciones** (`•••`) en el editor de mensajes, **Configuración → Prompts** y el campo de prompt del formulario de tareas de la página Tareas en segundo plano. Todos abren la misma lista, de modo que un prompt guardado desde una conversación es, palabra por palabra, el que puede ejecutar una tarea. Contiene dos tipos de entrada:

| Tipo | Qué es |
| --- | --- |
| Instrucciones del despliegue | Incluidos con tu instalación y actualizados desde fuera de la aplicación. De solo lectura, marcado como **Git** en la lista. Úsalos tal cual o inserta uno y adáptalo para crear tu propio prompt. |
| Prompts del espacio de trabajo | Creados por tu equipo. Cada uno es **Privado**, visible solo para su autor, o **Espacio de trabajo**, visible para toda la instalación. Solo el autor o un administrador puede editarlos o eliminarlos. |

### Usar un prompt

Abre la biblioteca, busca o desplázate y selecciona una entrada para leerla completa. **Usar instrucción** lo inserta en tu borrador; envíalo tal cual o amplíalo primero. En la página Tareas en segundo plano, la misma acción rellena las instrucciones de la tarea y toma el nombre del prompt como título inicial.

Algunos prompts de la instalación son **formularios** y aparecen marcados como **Formulario** en la lista. Al seleccionar uno, se muestran sus preguntas en lugar de su texto. Rellena los campos marcados como `*`; algunos formularios agrupan ajustes adicionales en **Más opciones**. **Usar instrucción** no estará disponible hasta que todos los campos obligatorios tengan una respuesta, y la **Vista previa de instrucciones** que aparece debajo del formulario muestra exactamente lo que se insertará. Si dejas vacío un campo opcional de texto, número o fecha, se omite del prompt, por lo que no tendrás que buscar marcadores sin rellenar después. El prompt terminado se añade a tu borrador como cualquier otro, listo para leerlo, modificarlo o adjuntarle archivos antes de enviarlo. Si prefieres rellenarlo a mano, **Insertar instrucción sin procesar** inserta la plantilla con sus `{placeholders}`.

### Crear y editar

**Nueva instrucción** abre un formulario con un nombre, una descripción opcional («ayuda a tus compañeros a encontrarlo») y el texto del prompt. Si ya tienes texto en el editor, se copia al formulario. **Compartir con este espacio de trabajo** determina si será privado o del espacio de trabajo; deja la casilla sin marcar hasta que se haya revisado el prompt y sea la versión acordada por el equipo. Al seleccionar una entrada propia, aparecen **Editar**, **Duplicar** y **Eliminar**; las entradas de la instalación y las compartidas por compañeros ofrecen **Clonar y editar** para que puedas personalizar una copia propia.

Una convención que conviene adoptar desde el principio. **Una versión del equipo por informe**: cuando se comparte un prompt, conviene eliminar los borradores privados que llevaron a él; la tarea que lo ejecuta debe crearla quien vaya a mantenerla, ya que su fila solo es visible para su creador y los administradores.

### Copias de seguridad

**Crear copia de seguridad de JSON** descarga la biblioteca tal como la ves, incluidos los prompts de la instalación, como un archivo sencillo. Guarda de vez en cuando una copia en la unidad compartida del equipo; contiene todo tu trabajo con prompts en un único archivo.

> **Por qué la biblioteca define lo acordado.** Una tarea ejecuta lo que se le indicó al crearla. Si hay que corregir el informe, corrige el prompt de la biblioteca y vuelve a seleccionarlo en la tarea para que esta use la nueva versión. Si modificas las instrucciones dentro de una tarea, creas una variante que nadie más puede ver y la copia de la biblioteca deja de reflejar la realidad sin que nadie lo advierta. Los demás ajustes de la tarea —su horario, sus destinatarios y los conectores que puede usar— tienen sus propios campos en el formulario, y la inserción de un prompt no los modifica.

## 10. Del chat a una tarea

Tienes una conversación que merece la pena conservar. Dos pasos lo convierten en algo que se ejecuta por sí solo: extraer un prompt del chat y llevarlo a una tarea. Hay varias formas de dar cada paso, y la adecuada depende de lo que quieras conservar: el informe exacto o el método con el que lo elaboraste.

### Extraer el prompt del chat

**Pide al asistente que lo redacte.** La opción para un informe que quieras reproducir exactamente de la misma forma cada vez. El asistente sabe lo que acaba de crear, y puedes pedirle que corrija el borrador en la misma conversación antes de guardar nada. Pide algo como:

> Escríbeme un prompt que pueda guardar en la biblioteca de prompts y que reproduzca exactamente este informe en una única ejecución. Fija este diseño como plantilla: las mismas secciones en el mismo orden, las mismas tablas y el mismo formato, cambiando solo los datos. Debe funcionar en un chat completamente nuevo, sin ningún otro contexto.

Lee el borrador, pide cambios y pégalo en **Nueva instrucción**.

**Guardar como flujo de trabajo.** La opción adecuada para un método que quieras reutilizar con otros datos de entrada. Desde el menú `⋮` de la conversación o el pie de cualquier respuesta, la plataforma lee toda la conversación —incluido lo que hizo el asistente y los errores que cometió por el camino— y la convierte en una plantilla de flujo de trabajo: un objetivo, las entradas como marcadores entre corchetes, los pasos con la herramienta usada en cada uno, el resultado y las notas. Los nombres, las fechas y los objetivos de esta ejecución se generalizan; el método sigue siendo específico. En el diálogo de guardado, elige **Destino**: guárdalo en la **Biblioteca de instrucciones** (privado por defecto, o **Compartir con el espacio de trabajo**) o directamente como una **Habilidad del agente (`/skill-name`)** (personal por defecto, o publicada en **Habilidades del espacio de trabajo** para que tus compañeros puedan pulsar **Añadir a mis habilidades**).

Guardar como flujo de trabajo encaja bien con esa tarde que dedicaste a lograr que el asistente analizara un conjunto de datos nuevo, calculara una referencia y redactara una nota, porque el próximo trimestre querrás aplicar ese procedimiento a otro cliente. No es la opción adecuada para un informe diario fijo en el que quieras responder a la misma pregunta de la misma manera cada mañana; para eso, usa la primera opción.

**Escríbelo tú.** Adecuado para peticiones sencillas. La lista de comprobación siguiente sigue siendo válida.

Elijas la opción que elijas, revisa el borrador antes de guardarlo. Para un prompt de informe: nombra todas las fuentes, especifica los identificadores, fija el diseño y el orden de las secciones e incluye la regla de señalar cualquier elemento no disponible y continuar con el resto. Para una plantilla de flujo de trabajo: los marcadores abarcan todo lo que cambia entre ejecuciones, y ningún paso dice «analiza los datos» cuando en la conversación se hizo algo específico. Si el borrador menciona destinatarios o una hora de ejecución, seguirá funcionando, pero es mejor establecer esos detalles en la propia tarea, donde pueden cambiarse sin tocar el prompt. Después, **pruébalo**: abre un chat nuevo, inserta el prompt guardado desde la biblioteca y envíalo. Deberías obtener el mismo informe con los datos actuales. Si difiere, vuelve a la conversación en la que lo creaste, explica al asistente qué ha cambiado y actualiza el prompt guardado.

### Llevar el prompt a una tarea

**Desde la biblioteca, en la página Tareas en segundo plano.** La opción recomendada. En la página Tareas en segundo plano, **Nueva tarea** abre el formulario de tareas; inserta el prompt de la biblioteca y establece el horario, el modelo y los destinatarios. El prompt tiene un único lugar de referencia y la tarea lo utiliza. La guía de Tareas en segundo plano explica el formulario campo por campo.

**Crear tarea recurrente… desde el chat.** La opción directa. Desde el menú de la conversación, el asistente propone una tarea basada en ella y prepara una tarjeta de programación. **Editar** abre el nombre, el horario y el prompt completo; **Aprobar y programar** (o **Aprobar con cambios**, si has editado) crea la tarea; **Cancelar** no crea nada. El nombre que confirmes será el título de la tarea en el tablero. La tarjeta también muestra el modelo que ejecutará la tarea: el modelo para tareas del espacio de trabajo (por defecto, el modelo más potente), en lugar del que se estaba usando en este chat.

La diferencia es clara: el prompt se genera a partir de la conversación en lugar de tomarse de la biblioteca, así que revísalo en **Editar** con la misma lista de comprobación. Plantéate guardar ese prompt revisado también en la biblioteca para tener un lugar donde aplicar futuras correcciones.

En ambos casos, la tarea aparece en tu propio tablero en la página Tareas en segundo plano. Tus compañeros reciben los correos, pero, salvo que sean administradores, no ven la fila de la tarea; por eso, la versión de un informe para el equipo debe crearla quien vaya a mantenerla.

> **Hay una regla que se aplica a todas las opciones.** Una tarea conserva el prompt con el que se creó. Un cambio en la biblioteca solo llega a una tarea cuando se vuelve a seleccionar el prompt en ella. Después de cambiar un prompt de la biblioteca, abre las tareas que lo usan, vuelve a insertar el prompt y pulsa **Ejecutar ahora** una vez para confirmar.

A partir de aquí, continúa con la **Guía de tareas en segundo plano**: estados de ejecución, registros y qué hacer cuando una ejecución necesita atención.

## 11. Cuando un turno falla

La mayoría de los problemas se manifiestan en la transcripción. Busca en la tabla siguiente lo que estás viendo.

| Qué ves | Qué hacer |
| --- | --- |
| **Reintentando** | Una conexión o un servicio ha fallado momentáneamente y el turno vuelve a intentarse por sí solo tras una breve cuenta atrás. Espera. Suele resolverse solo. |
| No aparece nada durante un rato | Un modelo que razona antes de escribir puede permanecer en silencio un minuto o más, y eso no es un fallo. Por defecto, la plataforma da al modelo alrededor de un minuto y cuarto para empezar. Si aún no ha empezado, verás **Reintentando** mientras la plataforma vuelve a intentarlo automáticamente, y después tu instalación puede probar con un modelo de respaldo, que normalmente responde sin que tengas que hacer nada más. Si tampoco empieza el último intento, una tarjeta indica que el modelo no ha empezado a responder. Vuelve a intentarlo desde la tarjeta o elige otro modelo. |
| **Error en el turno** | El turno no se completó. El aviso explica el motivo cuando es posible. En el último turno, **Reintentar** reenvía tu último mensaje. Si falla de la misma manera dos veces, cambia algo: el modelo, la petición o el archivo adjunto. |
| **Sin créditos** | La clave de API de la instalación se ha quedado sin créditos o ha alcanzado su límite de gasto. Recarga la clave de API, o usa **Contactar con licensing@elcanotek.com** en la tarjeta para añadir créditos, y pulsa **Reintentar**. |
| La respuesta parece detenerse | Si el teléfono se bloquea o el portátil entra en reposo, la pantalla puede perder la conexión mientras el asistente sigue trabajando. Espera unos segundos tras recuperar la conexión: la página comprueba el estado automáticamente y reanuda la transmisión en directo o muestra la respuesta terminada. Si el turno ya había fallado durante tu ausencia, la página explica qué ocurrió y ofrece **Reintentar**, o **Elegir otro modelo** si eso era lo que necesitaba el turno. Tras una interrupción prolongada, estas comprobaciones se espacian; volver a la pestaña provoca una inmediatamente. Recarga solo si sigue atascado después de eso. El trabajo no se ha perdido en ningún caso. |
| Un aviso en la parte superior: **… se ha actualizado** | Se ha publicado una versión nueva de la aplicación desde que se cargó esta página. Pulsa **Recargar** cuando te convenga o descarta el aviso con **×**. Nunca recarga la página por sí sola. El mismo aviso aparece en todas las páginas de la aplicación y también cuando se añade a la pantalla de inicio de un iPhone o iPad, donde no hay un botón propio para recargar. |
| Una página que dice **Se ha producido un error** | Se ha producido un error en la página. Pulsa **Recargar** o **Ir a la página de inicio**. Una página que se dejó abierta durante una actualización normalmente se recarga sola una vez para usar la nueva versión. Si esa misma página vuelve a fallar justo después, espera tu intervención. |
| Modelo no disponible | El aviso ofrece **Elegir otro modelo**. Elige uno y vuelve a enviar; la conversación conserva su historial. |
| Archivo rechazado | Si un archivo adjunto supera el límite de tamaño, se rechaza al seleccionarlo y se muestra el límite. Divide el archivo o limítalo a las columnas y fechas que necesitas. |
| Conector no disponible | El selector muestra **No disponible** junto a un conector, o el registro de ejecución muestra una llamada que devolvió un error. Comprueba en **Configuración → Conexiones** si ha caducado el inicio de sesión; en caso contrario, informa al administrador y adjunta una exportación de **Descargar chat** en formato **Datos sin procesar**: siempre incluye el registro completo, así que no ofrece opciones que marcar. |
| Llamada de conector o navegador rechazada (`[REDACTED]` o `$secret:`) | Una llamada intentó reutilizar un marcador oculto anterior del chat, pasar una referencia de credencial exclusiva del chat a una ejecución programada o a un conector personalizado guardado, o ejecutar un conector personalizado cuya definición guardada registró el marcador. Pide al asistente un formulario de credenciales nuevo y vuelve a enviar el secreto, o actualiza o recrea la conexión guardada en **Configuración → Conexiones** con credenciales reales. |
| La conversación está llena | Un aviso indica el porcentaje. **Resumir mensajes anteriores**, o inicia una nueva si has cambiado de tema. |
| La respuesta es incorrecta | Abre las etiquetas del registro de ejecución y lee lo que devolvió realmente cada fuente. Después, pide: «muéstrame las filas de las que sale esa cifra». La mayoría de las respuestas incorrectas se deben a una fuente equivocada o a un identificador mal interpretado; ambos se ven en el registro de ejecución. |

Todo lo que no puedas resolver a partir de la transcripción debe comunicarse al administrador. La forma más rápida de enviárselo es **Descargar chat** en el menú `⋮` de la conversación y elegir **Datos sin procesar**: ese formato siempre incluye el registro completo, incluido lo que devolvió cada herramienta, así que no hay que volver a describir nada ni se puede olvidar ninguna opción. (**Incluir el trabajo del agente** aparece en los dos formatos legibles, que lo excluyen por defecto; Datos sin procesar no muestra la casilla porque nunca omite nada).

## 12. Prácticas de trabajo

Siete hábitos para que una instalación compartida sea comprensible y sus informes fiables.

| Hábito | Motivo |
| --- | --- |
| Pon nombres útiles a las conversaciones | Renombra todo lo que conserves para que el título describa el trabajo realizado. Los títulos sirven para buscar, compartir y pasar el trabajo a un compañero cuando hace falta una segunda opinión. |
| Fija lo importante | Las conversaciones sin fijar caducan. Fija, guarda en un proyecto o archiva todo aquello que no quieras perder. |
| Elige el modelo adecuado para el trabajo | Entre los modelos recomendados, usa el rápido para obtener datos, hacer comprobaciones y dar formato; usa el más potente para emitir juicios y redactar. Cambia de modelo durante la conversación cuando cambie la petición. |
| Especifica fuentes e identificadores | Indica qué informe, qué remitente y qué operación. El registro de ejecución solo puede mostrarte lo que has pedido. |
| Lee la tarjeta antes de aprobar | Una tarjeta es la forma que tiene la plataforma de explicar lo que va a ocurrir. Cancelar nunca tiene coste. |
| Guarda cada prompt en un único lugar | Créalo en el chat, consérvalo en la biblioteca y ejecútalo desde una tarea. Corrígelo en la biblioteca y vuelve a seleccionarlo en la tarea. |
| Anota los aprendizajes en el proyecto | Una regla que el equipo repite continuamente en el chat debe guardarse en los aprendizajes del equipo del proyecto, donde todas las conversaciones la reciben sin que nadie tenga que volver a escribirla. |

## 13. Atajos de teclado

Todo lo que se describe aquí también se puede hacer con el ratón. Pulsa `?` en cualquier lugar fuera de un campo de texto para ver esta misma lista en la aplicación. `⌘` en Mac equivale a `Ctrl` en Windows y Linux.

| Atajo | Acción |
| --- | --- |
| `⌘ K` | Abrir la búsqueda |
| `⌘ ⇧ O` | Iniciar una conversación nueva |
| `⇧ Esc` | Llevar el foco al editor |
| `Enter` / `Shift Enter` | Enviar / añadir una línea (o al revés, si **Enviar con Intro** está desactivado) |
| `J` / `K` | Mover el foco hacia abajo / arriba en la lista de conversaciones |
| `Enter` | Abrir la conversación enfocada |
| `P` | Fijar o desfijar la conversación que tiene el foco |
| `A` | Archivar la conversación enfocada |
| `R` | Cambiar nombre de la conversación enfocada |
| `#` | Eliminar la conversación enfocada (abre la confirmación; nunca se elimina sin avisar) |
| `Y` | Copiar la última respuesta |
| `E` | Editar tu último mensaje |
| `D` | Activar o desactivar [vista de panel](#dashboard-view) (`Esc` permite salir) |
| `?` | Mostrar la ayuda de atajos |
| `Esc` | Cerrar la búsqueda, la ayuda superpuesta o la barra lateral |

Los atajos de una sola letra nunca se activan mientras escribes en un campo de texto, así que no pueden interrumpir un mensaje.

Tres combinaciones que quizá esperarías se dejan libres deliberadamente para que el navegador las conserve: `⌘F` sigue buscando en la página (la forma natural de buscar en la transcripción que estás viendo), `⌘N` sigue abriendo una ventana nueva y `⌘J` sigue abriendo las descargas. Por eso, iniciar una conversación nueva y llevar el foco al editor usan las otras dos combinaciones indicadas arriba.
